# 예정 지지쌍 하중 전환 실험 — 2026-09-12

28조건의 짧은 물리 탐색이며 단독 합격 후보는 없다. 몸체·모터·쿠션 물리값은 변경하지 않았다. 기본 arcturn의 회전 주기/원호 크기를 보존했으며 높이21~23mm, 하중 보상 gain0.3~0.4, 전환 폭40~120ms, 추가선행0~40ms를 비교했다. 14.02초 실행 중5~10초를 평가하고10초 Stop,14초까지 확인했다. 전체60초 검증을 대신하지 않는다.

## 제어 입력과 실험 방식

고정 C CAD 모델에 예정 관절각을 넣어 중력 bias, 발점, 발 Jacobian, 무게중심을 구했다. 각 대각선 쌍의 하중비는 COM을 발점 사이 선분에 투영해0.1~0.9 범위로 배분했다. 쌍 사이 전환은 quintic smoothstep으로 혼합했다. 토크 추정치를 추정 위치 강성35Nm/rad로 나누고 gain을 곱해 ±4°/20ms당0.25° 이내의 위치 보상을 만들었다. 실제 관절각/접촉력/지면높이는 제어 입력으로 사용하지 않았고 평가에만 사용했다. 기존 generic balance는 그대로 적용했다.

실험의 load phase는 기존 virtual_robot의 self.phase, 즉 직전 목표보다20ms 진행된 위상 기준이다. 아래 새 C 헤더는 목표에 이미 적용한 선행위상을 받도록 계약을 명확히 했으므로 root 통합 시 같은 수치를 넣어도20ms 차이를 의도적으로 정리해야 한다.

## 공통 C 이식

`firmware/stm32-learning/Inc/arc_transfer.h`의 `arc_transfer_apply`는 예정 관절각/목표위상/주기/duty/전환폭/추가선행/gain/강성/dt를 받는다. 최저 쿠션 vertex와 같은 지점의 힘 Jacobian을 사용한다. duty>0.5에서는 두 예정 지지 창을 부드럽게 만들어 합1로 정규화한다. 상태·출력은 관절 범위 위반/비유한 입력 시 원자적으로 거부한다. slew는12.5°/초이며 dt에 비례한다. 기본 정책이나 MCU 제어 루프는 이 실험이 변경하지 않았다.

`test_arc_transfer.py`:3검사 통과. 여러 duty·폭·위상에서 C2 경계와 주기성,181개 예정 자세에서 독립 Python 계산과 C 보상 일치,10/20/40ms 시간비례 제한, 잘못된 값과 범위 위반 시 원자적 거부를 검사했다. 실제 로봇 readback·위치 유지·보행 검증은 수행하지 않았다.

조건별 JSON/집계 `results.csv`/실행 로그를 보존했다. `aborted-initial.log`는 최초 실험 스케줄 함수 경계를 수정하기 전 중단한 실행의 기록이며 최종 평가 자료가 아니다. 최종 수치는 `run.log`, `fine.log`, `contact.log`에 해당한다.
