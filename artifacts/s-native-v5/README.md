# S 출발 · FR 첫걸음 V5

2026-09-15 사용자 요청에 따라 첫 FR/RL 동시 스윙, FR만 정상 J1 변화량의 2배로 오므림, 다음 반 주기에 네 다리 정상 오므림으로 전환하는 제어를 추가했다. 앱 목록 맨 위와 지원되는 가상 로봇 연결의 기본은 V5다. V1~V4와 펌웨어 프로필 순서는 유지했다.

## 적용한 동작

- 정지 기준 S는 유지한다. 별도 R 준비 자세 없이 phase=0.5에서 FR/RL이 먼저 움직인다.
- 두 발의 기준 X/Z 궤적을 공유한다. FR의 J1만 별도로 고정하고 J2/J3로 X/Z를 다시 풀기 때문에 안쪽 오므림 자체가 FR의 기준 보폭/발 높이를 바꾸지 않는다.
- 첫 스윙에서 FR의 J1 변화량은 정상 기준의 2배, 나머지 세 J1 명령은 S 그대로다. 다음 FL/RR 스윙 동안 FR 계수는 2→1, 다른 다리는 0→1로 연속 전환한다. 두 번째 걸음에서는 지지 중인 FR/RL도 J1이 바뀐다.
- 정상 기준은 S에서 안쪽으로 9°, 첫 FR은 18°다. S의 J1 약 +0.0076°에 더하는 변화량이다. 정상 보행에서 높이/회전/공통 지지 이동을 위한 보정은 별도로 더해진다.
- 기존 정상 기준 약 12.9°를 두 배로 한 25.8°는 FR J2 부품과 body_3의 실제 CAD 삼각형이 교차했다. 사용자 승인으로 정상 기준을 줄였다. 10°/20°는 최소 여유 약 0.37mm, 선택한 9°/18°는 약 2.09mm였다. 충돌 형상/관절 한계/서보 특성은 완화하지 않았다. 이 수치는 첫 스윙의 51개 목표 자세에서 FR J2/J3와 몸체 네 부품을 검사한 결과이며 모든 동작의 기구 안전 판정은 아니다.
- 첫 스윙 높이를 전후 보폭의 1초 진폭 증가와 분리했다. 이전 방식에서는 첫 스윙 높이도 거의 0으로 억제됐다. 최대 발 높이 25mm, 전후 범위 +20/-60mm, 최대 입력 주기 0.8초, 교대 대기 0초는 유지했다.
- Stop은 현재 J1 오므림에서 시작해 0.8초 동안 S 쪽으로 부드럽게 푼다. 전진 감속과 위상 진행을 함께 유지하고, 이후 기존 S 복귀 처리를 완료한다. 출발 도중 Stop도 현재 각도에서 이어진다. 센서/기울기 보호 정지는 기존 경로를 유지한다.

## 확인 결과와 남은 문제

호스트 검사 54개 통과, 맥 Catalyst 앱 빌드 및 실제 TCP 연결/V5 기본 선택을 확인했다. 실제 로봇은 구동하지 않았다.

`final-video/`는 최종 9°/18° 설정으로 2초 정지 + 전진 100% 10초를 재생한 앞/뒤/위/옆 영상이다. 네 화면은 같은 물리 상태를 보여준다. 기울기 정지를 생략한 실험이며 `safety=ok`는 안정성 통과를 뜻하지 않는다.

- FR/RL은 첫 스윙에서 모두 들렸다. 첫 착지는 **RL 2.46초, FR 2.54초**, 차이 **80ms**였다(20ms 측정, 첫 상승 뒤 바닥 접촉과 하중 확인).
- 2.46초 FR J1 명령 약 -17.99°, 실제 약 -17.69°였다. 나머지 J1 명령은 S를 유지했다. 첫 FR 오므림 목표는 실제로 추종했지만 대각선 착지 동기까지 성립하지는 않았다.
- 2.88초까지 정상 오므림 계수가 모두 1에 도달했다.
- 기울기 5° 지속 관측은 2.66초, 45°는 3.04초, 90° 전도는 **3.20초(보행 +1.20초)**였다.
- 첫 FR J1 완료 시점, 첫 발 들기 모양/높이, 첫 스윙 기간, 한정된 자세 보정 후보도 확인했으나 동시 착지 문제를 해결하지 못했다. 결과 JSON은 비교 기록이며 최종 코드에 전부 적용한 것이 아니다.
- 지지 예측은 완성된 정상 발 배치의 주기 해를 사용한다. 비대칭 첫걸음/두 번째 걸음의 중간 배치, 실제 서보 추종/몸체 운동에 대한 접지 동기 제어는 미완료다.

`stop-validation.json`: 보행 시작 0.3초 뒤 정지한 경우 실제 S 관절 오차 약 0.99°, 최종 기울기 약 0.04°로 복귀했다. 보행 1초 뒤 정지한 경우에는 J1/S 명령은 복귀했지만 이미 진행 중인 넘어짐을 막지 못했다. 관절이 S 각도로 돌아오는 것과 몸체가 서서 정지하는 것을 구분해야 한다.

## 재현

```bash
python -m pytest simulation/mujoco/tests/test_s_native_gait.py simulation/mujoco/tests/test_drive_transition.py simulation/mujoco/tests/test_virtual_robot.py -q
python simulation/mujoco/scripts/analysis/capture_s_native_balance.py --profile s_native_v5 --command 1000 --allow-fall --output artifacts/s-native-v5/final-video
mjpython simulation/mujoco/virtual_robot.py --viewer --allow-fall
```

`first-pass/`, `balance-video/`는 각도 축소 이전 시행이다. 최신 검토에는 `final-video/`를 사용한다. `triangle-clearance.json`은 최종 9°/18° 목표 검사이며 `triangle-clearance-10deg.json`은 10°/20° 비교다.

`checkpoint-validation/`에는 당시 검사 로그, 소스/영상 해시, 새 재현 도구의 정지·간섭 재검사와 후보 시험 출력이 있다. `entry-timing-sweep.json`은 최종적으로 저장된 첫 스윙 기간 배율 비교이며 `end` 값 1/1.25/1.5/2/2.5는 기간 배율이다. 중간 후보의 모호한 필드명을 정상 오므림 각도로 해석하지 않는다. 세부 후보 출력은 `checkpoint-validation/candidate-logs/`에서 확인한다.
