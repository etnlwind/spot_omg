# V6 — 들기 높이와 지지 교대 속도 제한

사용자 요청: FL/RR이 몸체를 크게 기울일 만큼 바닥을 차지 않고 다음 스텝으로 넘어가게 한다.
V5는 보존했고 V6를 별도 모델로 추가했다. 25mm 발 들기를 12mm로 제한하고,
최대 입력의 보행 주기를 0.8초에서 1.2초로 늘렸다. 이는 위치 궤적의 크기/속도를
제한한 조정이다. 힘 센서로 지면 반력을 닫힌 루프로 제어하는 기능을 추가한 것은 아니다.
대각선 쌍의 동일한 기준 X/Z/위상과 첫 FR의 2배 오므림, 9°/18° 각도 제한을 유지한다.
FL/RR만 다른 궤적을 만들지 않고 두 쌍의 공통 교대 궤적에 적용했다.

## 추정 물리 재생

배터리와 쿠션 포함 2.754kg, D37.3×27mm 쿠션, 기존 충돌·서보 지연·속도·토크 한계를 유지했다.
2초 대기 뒤 8초 전진, 넘어짐을 숨기지 않는 `--allow-fall` 조건이다.

| 모델 / 입력 | 최대 roll 또는 pitch | X 변위 | Y 변위 | 전도 |
|---|---:|---:|---:|---|
| V5 / 100% | 약 180° | 전도 후이므로 보행 거리로 해석하지 않음 | — | 3.20초 |
| V6 / 30% | 3.46° | 0.124m | 0.091m | 없음 |
| V6 / 60% | 2.69° | 0.381m | 0.126m | 없음 |
| V6 / 100% | 3.44° | 0.835m | 0.222m | 없음 |

100%에서 발 높이가 2mm를 넘은 누적 시간은 FL/FR/RL/RR 각각 2.30/3.26/0.70/1.46초다.
모든 발이 떨어지는 구간은 있지만 동일한 실제 접촉 타이밍을 달성했다는 뜻은 아니다.
30%에서는 뒷발 두 개가 2mm를 넘지 않았고, 60%에서도 0.10/0.14초에 그친다.
저속의 발 끌림 및 Y 방향 편류는 미해결이다. 완성된 보행 또는 실기 안정성을 주장하지 않는다.

출발 0.3초/1.2초 뒤 Stop 두 조건은 전도 없이 S로 복귀했다. 최종 목표 오차 0°,
실제 관절 최대 오차 약 0.99°다. 주기를 늘렸으므로 오므림을 푸는 Stop 구간도 1.2초다.

FCL 검사: 첫 스윙 51개 목표 자세, FR J2/J3와 몸체 네 부품의 삼각형 간격.
최소 2.106mm, 충돌 없음. 이는 전체 동작/모든 링크/제작 공차를 검증한 결과가 아니다.

## 재현

```powershell
python simulation/mujoco/scripts/validation/validate_s_native_v6.py --output artifacts/s-native-v6/validation-2026-09-15
python simulation/mujoco/scripts/analysis/capture_s_native_balance.py --profile s_native_v6 --command 1000 --allow-fall --walk-seconds 8 --fourth-view side --output artifacts/s-native-v6/video-2s-wait-8s-walk
```

영상 인코더가 PATH에 없으면 `--ffmpeg`에 실행 파일 경로를 지정한다.
`video-2s-wait-8s-walk/four-views.mp4`는 같은 물리 상태를 앞/뒤/위/옆에서 렌더링한 10초 영상이다.
호스트 검사 62개 통과. 실제 로봇의 설정 readback, 위치 유지, 전체 구동은 수행하지 않았다.
Windows 앱에는 V6를 가장 위에 추가하고 지원되는 시뮬레이터에서 기본 선택한다.
iOS 모델 목록/기능 판별도 갱신했으나 이번 Windows 환경에서 Xcode 빌드는 수행하지 않았다.
