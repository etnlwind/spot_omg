# S-native 직진 시 좌회전 원인 — 2026-09-15

현재 앱에서 `SIMULATION / TCP`, `s_native_v6_1`, `직진: on`을 확인했다.
앱 콘솔의 직진 시작 명령은 `drive 473 0 3`으로 회전 입력은0이다.
이는 시작 명령 확인이며, 콘솔에 생략된 이후 모든 heartbeat 입력을 입증하는 것은 아니다.

## 확인된 오류

기존 조종 프로토콜과 `heading_control.h`는 양의 yaw를 우회전으로 정의한다.
하지만 `s_native_gait.py`의 발끝 회전 변위는 양의 yaw에서 실제 몸체를
반시계 방향(좌회전)으로 회전시킨다. `s_native_impl.h`의 C 구현도 같은
발끝 변위 부호를 사용한다. 새 모델과 기존 조종·직진 보정 간 기준이 불일치한다.

왼쪽으로 틀어진 상태를 관측하면 보정기가 양의 값을 출력하지만, 보행 모델은
이를 추가 좌회전으로 실행한다. 직진 보정이 오차를 줄이는 대신 키우는 구조다.
Roll/Pitch 수평 보정 미적용과 별개로 heading 보정은 실행되고 있다.

## 독립 시뮬레이터 재현

실행 중인 사용자 시뮬레이터와 별도로 동일한 기본 물성·모델을 생성했다.
각 시험은 초기 S에서2초 대기 후8초 구동, 회전값을 포함한 heartbeat를
200ms마다 고정 입력했다. 기본 기울기 보호와 충돌을 유지했다.
각도는 센서 보고값이 아니라 MuJoCo 몸체 회전행렬에서 계산한 실제 yaw 변화다.

| 시험 | 8초 후 몸체 yaw 변화 | 최종 보정 출력 |
|---|---:|---:|
| 직진1000, heading ON | 좌31.21° | +0.25(상한) |
| 직진1000, heading OFF | 좌2.98° | 0 |
| 직진473, heading ON | 좌26.80° | +0.25(상한) |
| 수동 yaw +500, heading OFF | 좌46.41° | 0 |
| 수동 yaw −500, heading OFF | 우38.71° | 0 |

모든 시험 최종 safety는 `ok`였다. yaw가 크게 틀어져도 Roll/Pitch가 작으면
기울기 보호를 통과하므로 safety OK는 직진 성능을 뜻하지 않는다.

## 원인 분리 실험

별도 Python 시험 프로세스 안에서만 `SNativeGait.points`에 전달되는 yaw 부호를
반전했다. 이 함수로부터 계산되는 지지 기준도 함께 반영된다. 디스크의 보행 코드,
실행 중인 앱·시뮬레이터, 실제 로봇 펌웨어는 변경하지 않았다.

직진473의 yaw 변화는 좌26.80°에서 좌1.31°로 줄었다. 이 결과는 부호
불일치가 회전 증폭의 원인임을 뒷받침하지만, 잔여 편향·횡이동까지 해결했다는
검증은 아니다. 완성된 수정본이나 실기 검증으로 취급하지 않는다.

수정 시에는 조종 프로토콜의 우회전 양수 기준을 모델 경계까지 일관되게
적용하고 Python 궤적, C 궤적, 생성된 지지 테이블을 함께 검토해야 한다.
목표각 일치·Roll/Pitch·Stop 복귀 검사에 더해, 실제 몸체 yaw로 좌우 회전
방향과 직진 보정의 오차 감소를 독립적으로 검증해야 한다. 서보 영점이나
앞 J1 오므림 부호를 회전 보정 목적으로 다시 바꾸는 것은 해당 오류의 수정이 아니다.

시간별 위치·yaw·보정량 JSON. 실제 로봇에는 구동·변경 명령을 보내지 않았다.
