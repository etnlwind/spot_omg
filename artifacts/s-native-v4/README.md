# S 출발 · J1 아래 착지 V4

Spot 사진에서 관찰한 듯한 안쪽 착지를 직접 적용해 보자는 사용자 요청에 따른 실험이다. 사진만으로 Spot의 실제 보행 정책이나 관절 명령을 복원한 것은 아니다.

정지 S의 발끝 X/R2 정렬은 그대로 유지한다. 보행 발끝의 몸체 기준 Y를 각 J1 축 Y(+/-39.12mm)로 모으도록 목표를 바꾸었다. S의 발끝 Y는 +/-93.28mm이므로 좌우 각각 약 54.16mm 안쪽으로 이동하고, 기준 발끝 폭은 186.56mm에서 78.24mm로 바뀐다. J2 축 Y는 +/-105.75mm로 별개다. 이번 실험에서 '모터 아래'는 **J1 축의 Y**로 해석했다.

기존 V3에는 네 발을 같은 방향으로 옮기는 공통 좌우 지지 이동은 있었지만, 발끝 폭을 줄이는 항목은 없었다. V4는 이 안쪽 착지 항목을 추가한다. 기존 공통 몸체 지지 이동은 별도로 더해지므로 보행 중 발끝 Y가 매 순간 J1 축 Y와 정확히 같도록 고정하는 것은 아니다.

S에서 별도 R 준비 자세 없이 보행을 시작한다. 출발 진폭이 0.5를 넘은 뒤 각 대각선 쌍의 첫 완전한 스윙에서 부드럽게 안쪽으로 옮긴다. 그 차례가 오기 전 지지 중인 발의 착지 폭은 유지한다. RL/FR 및 RR/FL 짝은 반 주기로 교대하며 앞뒤 궤적(+20/-60mm), 주기 0.8초, 대기 0초와 발 들기 25mm는 V3에서 유지했다. 정지 명령에서는 기존 S 복귀 처리를 유지한다.

## 실제 물리 재생

이전과 같은 전진 100%, 2초 정지 + 10초 보행, 넘어짐 허용 조건이다. 네 방향은 같은 물리 상태를 렌더링한다. 아래 시점에서는 바닥만 렌더링에서 숨긴다.

- 2.84초: 첫 대각선(FL/RR)의 안쪽 착지 진행률 약 37%.
- 3.00초: FL/RR 진행률 약 96%, 실제 J1 약 -11.3/-13.4도.
- 3.40초: 나머지 FR/RL 진행률 약 96%, 네 J1 실제 각도 약 -14.0/-11.7/-13.8/-12.5도. 발끝과 J1의 몸체 기준 Y 차이는 -4.4/-11.4/+0.2/-5.8mm로 모였다.
- 3.60초: 두 대각선 모두 안쪽 착지 완료.
- 3.96초: 기울기 45도 초과.
- 4.12초(보행 +2.12초): 기울기 90도 초과, 전도. 같은 조건 V3의 전도는 5.62초였다.

**안쪽 착지는 확인됐으나 단독 적용으로 안정성이 개선되지는 않았다.** 보행 폭을 좁힌 상태에서 기존 지지 이동/서보 응답/몸체 관성의 협응이 충분한지 추가 검증이 필요하다. 현재 지지 예측은 완성된 보행 발끝 배치를 사용하므로, 처음 각 대각선이 발을 옮기는 중간 배치까지 예측하는 것은 아니다. 이 관찰만으로 어느 하나를 전도의 단일 원인으로 단정하지 않는다. safety=ok는 기울기 중단을 생략한 실험 상태이므로 안정성 통과를 의미하지 않는다.

관련 호스트 검사 50개와 맥 앱 빌드 통과. 실제 로봇은 구동하지 않았다. 앱 목록 맨 위 및 지원되는 시뮬레이터 연결의 기본은 V4이며 V1/V2/V3는 비교용으로 남겼다.

최신 영상은 사용자 요청에 따라 아래 시점을 옆모습으로 바꾼 `side-video/four-views.mp4`(앞/뒤/위/옆)다. 원래 아래 시점 영상은 `balance-video/`에 남겼다. 각 폴더의 `summary.json`, `trajectory.json`은 같은 재생을 기록한다. 후자에는 실제 J1 각도, 발끝-J1 Y 차이, 안쪽 착지 진행률이 포함된다.

```bash
python simulation/mujoco/scripts/analysis/capture_s_native_balance.py --profile s_native_v4 --command 1000 --allow-fall --fourth-view side --output artifacts/s-native-v4/side-video
mjpython simulation/mujoco/virtual_robot.py --viewer --allow-fall
```
