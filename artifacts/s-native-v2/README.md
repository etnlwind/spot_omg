# S 출발 · 연속 교대 V2 (2026-09-15)

사용자 요청: 발 교대 때 기다리지 말고 바로 바꾸며, 시뮬레이터에서는 넘어져도 관찰한다.

기존 V1을 비교용으로 유지하고 `s_native_v2`를 앱 목록 맨 위와 지원되는 가상 로봇 연결의 기본 선택으로 추가했다. 주기 1.4초 → 0.8초, 교대 대기 0.3초 → 0초(최대 입력 기준). 한 발을 옮기는 0.4초, 보폭 40mm, 명목 발 들기 25mm와 S 출발은 유지한다. 두 대각선의 목표 궤적은 반 주기 차이다.

`--allow-fall`은 명시적으로 켜는 시뮬레이터 실험 옵션이다. S 보행 중 기울기로 인한 중단만 생략하며 Stop·통신 watchdog·센서 오류·Stow 제약은 유지한다. 일반 실행에서는 기울기 보호가 그대로 켜진다. 화면의 FALL TEST와 상태 응답의 fall_test=on으로 구분한다. 펌웨어는 변경하지 않았다.

## 실제 물리 재생 결과

전진 60%, 32초 자유 몸체·중력·쿠션 접촉·기존 서보 응답 재생. 기울기 보호를 유지한 실행은 약 12.5도에서 중단됐다(`no-hold.json`). 넘어짐 허용 실행에서는 끝까지 발 목표를 교대했으며 6~28초의 네 발 동시 접지 구간 중앙값 40ms, 최대 60ms였다. 전체 최대 몸체 기울기는 약 23.3도였다. 이 접지 지표는 1mm 높이 기준이며 목표 대기 시간과 동일한 값이 아니다.

**대기 제거를 적용한 실험 모델이며 안정 보행이나 실제 대각선 접지 동기가 검증된 모델은 아니다.** 넘어짐 허용 실행의 safety=ok는 기울기 정지를 생략한 결과이므로 안정성 통과로 해석하지 않는다. 목표값은 계속 교대하더라도 몸체 흔들림 때문에 실제 앞뒤 발 높이와 접지 시점은 다를 수 있다.

- `fall-test.csv`, `fall-test.json`: 20ms 간격 실제 물리 기록
- `fall-test.gif`: 같은 실행의 6~10초 측면 영상
- `no-hold.csv`, `no-hold.json`: 기울기 보호 유지 비교
- `live-readback.txt`: 화면 표시용 실행의 모델 및 실험 옵션 응답

재현:

```bash
python simulation/mujoco/scripts/validation/validate_s_native.py --allow-fall --command 600 --gif --output artifacts/s-native-v2/fall-test
mjpython simulation/mujoco/virtual_robot.py --viewer --allow-fall
```

맥 제어 앱 빌드 및 관련 호스트 검사 45개 통과(기존 NumPy 경고 63건). 실제 로봇은 구동하지 않았다. LG 모니터의 실행에서 V2·fall_test=on 상태와 8초 보행을 확인했고, 재실행한 앱도 V2를 기본 선택해 연결했다.
