# V9 같은 쪽 페어 비교 — V95 (69), 실험 후보

사용자 요청: FL+RL / FR+RR을 묶은 옆걸음을 구현하고 기존 V8과 비교.
V8은 보존했다. **현재 V9은 V8보다 나쁘며 실기 적용을 권하지 않는다.**
코드/빌드/시뮬레이션 비교는 완료했지만 정상적인 두 발 동시 이륙은 달성하지 못했다.
실기와 설치 Windows는 V93(67)을 유지했다. 이번 작업에서 실기 명령/OTA는 보내지 않았다.

## 구현

- `attitudepd_v9` 프로필을 끝 인덱스31에 추가, 기존 인덱스 보존.
  앱 지원 목록 맨 위, 지원 연결의 기본 선택 및 시뮬레이터 기본값을 V9으로 갱신했다.
  이름에 실험을 표시한다. V93 펌웨어에는 V9을 자동 선택하지 않는다.
- 옆걸음만 같은 쪽 페어로 변경했다. 전후진·앞 대각선 회전·뒤 대각선 제자리 회전은
  V8과 목표 및 상태 수치가 동일하다는 호스트 검사를 추가했다.
- 왼쪽 FL/RL은 같은 위상, 오른쪽 FR/RR은 반 주기 차이. 요청 방향 쪽 페어가 먼저 움직인다.
- 네 발 지지 구간에 목표 몸체 Y를 좌우60mm 이동한다. 스윙 중에는 해당 지지 쪽 목표를
  유지한다. 모든 발에 같은 반대 방향 Y 변위를 적용하고 X/Z 목표는 보존한다.
  이는 명령 기반 무게 이동이며 실제 COM/접지/하중을 확인해 다음 단계로 넘어가는 제어가 아니다.
- 들림12mm+저장 보정과 스윙 높이 유지 파형은 V8과 동일하다.
  발높이 보정과 자세 보정도 같은 쪽 페어 위상에 맞췄다.
- V9 최종 주기4.8초: 스윙1.2초/네 발 지지1.2초 교대. V8 주기2.4초는 유지.
  같은 주기2.4초에서는 기울기/IK 실패가 발생해 V9만 느리게 했다.
- 펌웨어와 시뮬레이터가 동일한 C 궤적·무게 이동·추가 들림을 사용한다.
  비교 도구 `--transfer-mm`는 시뮬레이션 전용 시험값이며 펌웨어 상수는60mm다.

## 비교 조건과 결과

2초 대기 +20초 조작 +4초 정지, 입력±1000, 질량2.754kg, 동일 물리/접촉 설정.
FL/FR/RL/RR 들림20/20/20/20mm 및 간격-30/-30/+30/+30mm 유지.
V8 우측을 현재 소스에서 다시 실행해 기존 기록과 실제 위치/자세/목표각/실측각/
하중/발높이의 모든 프레임이 동일함을 확인했다. 상태 메타데이터는 V9 필드 추가로 다르다.

| 보행 중 지표 | V8 오른쪽 | V9 오른쪽 | V8 왼쪽 | V9 왼쪽 |
|---|---:|---:|---:|---:|
| 주기 초 |2.4|4.8|2.4|4.8|
| 옆 순이동 절댓값 mm |160.3|74.9|158.4|75.4|
| 앞뒤 위치 범위 mm |22.8|47.5|22.7|47.1|
| roll 최대−최소 ° |18.2|19.8|18.2|19.9|
| yaw 최대−최소 ° |4.5|19.4|5.0|19.3|
| 중앙 스윙 구간 두 발 모두 들림 비율 |87.8%|0%|84.6%|0%|

최종 좌우/우측 반입력588/보정0 시험 모두 보호정지 없이 끝났으나, 모두 두 발 들림
지표는0%였다. 따라서 '안 넘어졌다'는 것과 옆걸음 검증 성공을 구분해야 한다.
V9 오른쪽 저장 보정 시험의 중앙 스윙 구간에서 FL 높이4.6~7.1mm,
FR2.0~8.2mm이고 하중은0.5N 미만이었다. 반면 RL은-2.2~-1.8mm,
RR은-3.0~-1.7mm이며 해당 프레임 모두 하중>0.5N이었다.
음수 높이는 변형 접촉 모델의 눌림이며, **뒷발이 하중을 지닌 채 끌리는 상태**다.

두 발 들림 비율은 보행4.4초 이후 스윙30~70% 구간에서 해당 두 발 모두
발높이>2mm, 하중<0.5N인 프레임 비율이다. 전체 보행 성공률이 아니다.
이번 도구는 fault 이후/동작 종료 후 프레임을 이 비율에서 제외하도록 고쳤다.
`before_fault`와 `normal_stop`도 추가해 넘어진 뒤 정지한 것을 정상 종료로 오해하지 않게 했다.

## 실패 기록

`trial-01/`은 V8과 동일2.4초 주기, 최초 왼발 페어 진입 조건이다.
무게 이동0mm는 영상4.72초 tilt,30mm는5.80초 tilt,
60mm는5.54초 tilt 후 전도,90mm는4.24초 목표 계산 실패로 중단됐다.
보호·충돌을 꺼서 성공으로 만들지 않았다. 고장 후 전체 구간 범위는 전도 영향을
포함하므로 정상 주행 수치와 비교하면 안 된다. 실패 데이터는 보존했다.
`trial-02/`는4.8초 주기 탐색. `final/`은 방향별 선행 페어가 반영된 최종 후보다.

## 해석과 다음 작업

같은 쪽 지지는 대각선 지지와 달리 몸체 한쪽에만 지지선이 생긴다.
현재의 예정된 Y 이동60mm만으로는 실제 하중을 반대편 두 발로 완전히 넘기지 못했다.
특히 앞뒤 간격 보정이 달라 지지선이 몸체 X축과 평행하지 않다. 이 기하와
실제 관절/몸체 추종을 함께 분석해야 하며, 서보 하드웨어 한계라고 단정할 증거는 없다.
다음 개선은 실제/추정 하중 및 자세에 따른 무게 이동과 이륙 조건을 검토해야 한다.
비교 결과는 V9 일반 방식 자체가 불가능하다는 증명이 아니라 **현재 구현 후보의 실패**다.

빌드 최적화 탐색 중 SH2 유틸리티의 기존 `readu32` 식에서 최상위 바이트>=128일 때
signed int 왼쪽 시프트가 정의되지 않는 동작임을 Zig O0 검사가 검출했다.
`artifacts/navigation-v9-verified-tests.log`에 실패 증거를 보존했다. 이 작업에서
해당 외부 드라이버를 수정하거나 최적화하지 않았으며, 시도한 SH2 Os 변경은 철회했다.
따라서 최종 적용 변경의 검사와 이 기존 드라이버 문제를 구분한다.

재현: `python scripts/analysis/verify_v93_side_step.py --profile attitudepd_v9
--input 1000 --seconds 20 --output artifacts/<새 경로> --video`.
실기 설치가 요청되더라도 현재 결과와 한계를 먼저 확인하고, Landing 도착 절차를 지킨다.
