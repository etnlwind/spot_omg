# FL–RR 비동기 원인 분리 — 2026-09-11

## 결론

표시 영상의 `diagonal-preload-1` 조건에서 FL–RR 명령 스윙 위상은 같다. 관측된 큰 지면 여유 차이의 직접 원인은 **몸체 회전**이다. 현재 몸체 좌표계의 발 궤적이 몸체 회전과 함께 돌아가므로, 같은 높이를 명령해도 지면에서의 두 발 높이는 달라진다. 관절 추종 지연의 직접 기여는 작다.

현재 구현의 높이 보정과 정적 하중 보상은 지지 전환의 힘·모멘트 균형을 풀지 않으며, 이 조건에서는 결합했을 때 회전과 발 높이 비대칭을 확대한다. 그렇다고 이 보정들을 전부 제거하면 해결되는 것도 아니다. 무보정은 다른 품질 지표를 악화시킨다.

## 방법

동일한 CAD·쿠션·질량·모터·주기·60mm 보폭으로 20.02초씩 자유 몸체 물리 시뮬레이션을 수행했다. 5초 이후 평가. 실물/앱/라이브 정책 변경 없음. 각 비교에서는 명시된 제어 항목만 바꿨다. 센서 진실값·접촉력은 평가용으로만 사용했다.

각 표본의 FL–RR 최저점 높이 차이를 다음 순서로 분해했다.

1. 명목 관절 목표를 수평 몸체에 적용
2. 센서·하중 보상 후 목표를 적용
3. 실제 명령 필터 출력 적용
4. 실제 관절각 적용
5. 실제 몸체 회전 적용

각 단계의 차이를 더하면 마지막 높이 차이가 된다. 이것은 같은 관절 상태의 순기구학 분해이며 몸체를 실제로 고정한 보행 시험이 아니다.

## 9.98초 분해

| 항목 | FL−RR 높이 차이에 대한 기여 |
|---|---:|
| 명목 궤적 | +0.002mm |
| 센서·하중 보상 목표 | +0.270mm |
| 명령 필터 | −0.073mm |
| 관절 추종 | +0.176mm |
| 몸체 회전 | +25.569mm |
| 합계 | +25.944mm |

실제 기록된 메시 상태 기준 차이는 25.922mm다. 재계산한 순기구학과 저장된 마지막 물리 스텝의 메시 변환 상태 간 차이는 전체 표본에서 최대 0.142mm다. 같은 캐시 상태에서 메시 실제 최저점과 기존 clearance 계산은 1e-14mm 수준으로 일치했다. 따라서 메시 높이 정의의 차이가 결과를 만든 것은 아니다. 표본 간 해상도는 20ms다.

중간 스윙 전체에서도 몸체 회전 성분 RMS 10.50mm에 비해 명목 궤적은 0.01mm 미만, 보상 목표 0.43mm, 필터 0.25mm, 관절 추종 0.33mm다. 성분은 상관되어 있으므로 각각의 RMS를 합산하면 안 된다.

## 시간 순서와 하중

- 9.74초: FL/RR 지면 법선력이 모두 0. FR/RL이 몸체를 지지한다.
- 9.80초: FL/RR 법선력은 여전히 0. roll 0.46°, pitch −0.76°로 이미 기울어져 있다.
- 9.90초: FL/RR 법선력이 모두 0인 상태에서 roll 2.09°, pitch −1.96°. 이미 발 높이 차이에 대한 회전 기여가 20.61mm다.
- 9.98초: RR에 약 6.02N 접촉력이 생긴다. FL은 아직 공중에 있다. roll 3.55°.

따라서 이 대표 구간에서는 **몸체 기울기 → RR 조기 접촉** 순서다. 조기 접촉 뒤에는 다시 몸체 운동을 바꾸는 상호작용이 생긴다. 앞선 단순 접촉 그래프만으로 'RR이 먼저 닿아서 최초 기울기가 발생했다'고 결론내리면 잘못이다.

9.80초 실제 FR/RL 하중은 약 19.13N/23.82N다. 그때 수평면에서 무게중심은 두 발 중심 연결선으로부터 약 9.76mm 벗어나 있다. 총 질량 약 4.398kg의 중력만 계산하면 이 중심선에 대해 약 0.42Nm 모멘트에 해당한다. **발 중심선은 유한한 쿠션 접촉 지지영역의 경계가 아니다.** 이 숫자만으로 넘어짐을 판정하지 않는다. 실제 바닥 힘·모멘트도 저장했으며, 현재 제어는 이를 상쇄할 지지 모멘트를 계산하는 구조가 아니다.

## 코드에서 확인된 구조적 문제

`support_shift.py`:

- `plan()`은 몸체 기준 쿠션 최저점 궤적을 생성한다. FL/RR 위상 오프셋과 명목 높이는 일치한다.
- 기본 `world_swing=False`에서는 스윙 발이 실제 몸체 회전에 대해 지면 기준 목표를 유지하지 않는다. 몸체 회전을 스윙 목표에서 제거하는 작업이 빠진다.
- `height_feedback()`는 실제 접촉 여부 대신 예정 지지 쌍으로 높이를 추정하며, `feedback()`은 높이 수정을 네 발 모두에 더한다. 지지 작업과 스윙 작업이 같은 수정값을 공유한다.
- `load_preload()`는 예정 지지 쌍에 정적 하중을 배분한다. 전환 중 실제 지지와 시점이 다르고, 동적 몸체 모멘트나 마찰 가능한 지지 힘을 풀지 않는다.
- 대표 구간의 높이 수정은 9.56초 +1.16mm에서 9.80초 −6.19mm로 바뀐다. 그 동안 하중 보상도 새 지지 쌍으로 넘어간다. 두 항목을 독립적으로 더하는 구조는 전체 자세 안정성을 보장하지 않는다.
- 지면 기준 스윙 플래그만 켜는 개입도 시험했다. 현재 J1 고정·보정 한도·IK 계산에서 잔여 오차가 최대 13.87mm로 커졌고 실제 지표도 악화했다. 이를 수정 완료로 채택하지 않았다. 모든 가능한 J1 고정 해가 존재하지 않는다는 수학적 증명은 아니다.

## 다음 수정에 필요한 조건

타이밍 상수를 임의로 앞당기는 방식은 원인을 해결하지 않는다. 지지 발에 대해서는 몸체 높이·기울기를 유지할 하중과 관절 작업을, 스윙 발에 대해서는 지면 기준 여유·착지 목표를 별도로 계산하고 조정해야 한다. 예정 위상과 지연 센서로 추정한 실제 지지 전환도 일치시켜야 한다. 현재 고정 J1 조건에서 해가 남는지 잔여 오차와 실제 물리 지표로 확인해야 한다.
