# 기존 80mm 정책 좌·우 턴 확인 — 2026-09-11

앱 V0.5.0 (41)의 `cushion_diagonal_sync_wide80` 정책을 변경하지 않고 별도 headless MuJoCo에서 시험했다. 실물 명령이나 실행 중인 앱의 조작은 수행하지 않았다.

- 전진 입력 0, 회전 입력 좌 −1000 / 우 +1000. 기존 제한을 통과한 실제 입력은 각각 −0.5 / +0.5.

- 몸체 yaw는 unwrap하여 회전량을 계산했다. 제자리 이탈은 몸체 중심의 측정 시작점 대비 종료점 수평 거리다.

## 확인된 제한

`support_shift.py`는 스윙 높이를 `min(1, abs(linear)+abs(yaw))`와 곱한다. 순수 턴은 기존 yaw 제한 0.5 때문에 기본 20mm 스윙이 최대 입력에서도 목표 10mm가 된다. 좌·우 발의 전후 스트로크도 80mm × 0.5 = 40mm이다. 이 목표 축소는 발 여유를 줄이는 요인이다. 실제 발 들림 부족에는 몸체 기울기, 접촉, 서보 추종도 영향을 주므로 이것만을 유일한 원인으로 단정하지 않는다.

좌회전은 FL, 우회전은 FR의 중간 스윙 접촉 비율이 특히 높다. 회전 기능 자체는 동작하지만 부드럽게 발을 들고 도는 보행으로 합격시킬 수 없다. 장시간 턴·대각선 전진 턴·실물 검증은 이 시험에 포함되지 않는다.

## 원호 턴 개선

사용자 요청: 회전 속도를 낮추지 않고 발을 들기. 좌우 회전의 보폭은 80mm일 필요가 없다.

기존 전후 차동 궤적은 몸체 회전 시 필요한 발의 좌우 이동을 표현하지 못했다. 새 경로는 CAD의 기준 발 위치를 몸체 중심 주위로 회전시킨다. 같은 지지 쌍은 동일한 회전 변환을 사용하고, J1/J2/J3는 쿠션을 포함한 발 좌표를 따라 역기구학으로 계산한다. 서보 방향·보정 원점·물성·안전 정지 기준은 유지했다.

선택한 실험 설정:
- `turn_path=arc`, `turn_sweep_rad=0.2` (발 목표의 총 원호 각도 약 11.46°).
- 순수 턴 주기 1.2초, 목표 발 높이 20mm, 최대 회전 입력 ±1.0.
- 직진 80mm 및 기존 직진 주기 1.44초 유지. 조이스틱 대각선 입력은 직진 이동과 원호 이동을 합성한다.
- 발 높이·주기·원호는 속도 입력에 따라 변화하며, Stop은 기존 감속 경로를 사용한다.
- 제어기는 CAD, 보행 단계, 지연된 IMU/엔코더만 사용한다. 진짜 접촉력과 몸체 자세는 평가용이다.

24초 비교에서 1.2초 주기는 좌 18.82°/s, 우 19.16°/s로 회전했고 Stop을 완료했다. 기존 약 3.6~3.9°/s보다 빠르지만 몸체 기울기 품질이 더 좋아졌다는 뜻은 아니다. 중간 스윙의 잔류 접촉이 있으며 전체 정책은 계속 `(검증실패)`로 표시한다.

### 탈락한 후보도 보존

- 전후 차동의 보폭 30/40mm, 높이 20/25mm: 회전은 약 4°/s, 일부 발 끌림이 남았다.
- 원호 0.3rad + 25mm 들림: 양쪽 안전 정지 발생.
- 주기 0.8/1.0초: 한쪽 이상 안전 정지. 더 빠른 주기라고 무조건 유리하지 않았다.
- 몸체/스윙 IMU 보정 이득 증가: 잔류 접촉과 기울기 개선에 실패.
- 스윙의 높이를 일찍 올리고 유지하는 궤적: 대부분 조기 안전 정지. 현재 프로필에는 적용하지 않았다.

관련 `wide80-arc-*-candidates.json`에 실패 시간과 각 발의 접촉·들림을 기록했다. 선택 결과는 시험한 후보 중의 절충안이며, 전역 최적해·완벽한 수평 유지·실물 검증 완료를 의미하지 않는다.

양쪽 모두 안전 정지 없음, 명령한 Stop 완료, 관절 범위 검사 통과. 최대 roll 3°/RMS 1.5° 목표는 실패했다. 발의 스윙 최대 여유는 모두 22.8mm 이상이지만 중간 스윙 접촉은 최악 27.4%로 10% 미만 목표에 실패했다. 최대 여유는 모든 걸음의 최저 보장 높이가 아니다. 접지 발 중심 속도는 쿠션 굴림을 포함하며 순수 미끄러짐과 동일하지 않다.

모터 추정 토크가 토크-속도 한계에 포화되는 비율은 약 3%, 정격 추정치를 넘는 비율은 약 20%이다. 속도와 발 들림의 개선을 실물의 연속 구동 가능성으로 해석하면 안 된다. 추정 마찰도 일부 시점에서 한계에 도달한다.

호스트 회귀 검사: `test_support_shift.py`, `test_virtual_robot.py`, `test_gait_profiles.py` **112개 통과**. 직진 목표 보존, 원호 회전 방향과 지지 발 기하, 전체 회전 입력 전달, 주기 혼합, 기존 Stop/정책 동작을 확인했다.

전진→대각선 우회전→좌회전→우회전→Stop의 28초 시험도 안전 정지 없이 완료했다. 다만 최대 roll 11.59°, pitch 3.74°로 전환 품질 미달이다. 새 설정으로 시뮬레이터를 재시작했으며 TCP syncstate에서 해당 정책과 safety=ok를 확인했다. 앱 바이너리는 V0.5.0 (41)을 그대로 사용하며 같은 정책 항목으로 선택한다. 실물 펌웨어 변경 없음.

비교 영상은 `wide80-arc-turn-comparison.mp4` (20초, 1280×960, 25fps). 위는 기존, 아래는 개선, 카메라 방위는 월드 기준 고정이다. 영상의 stride=80mm 표기는 직진 기본 보폭이며 새 순수 턴은 원호 각도로 별도 계산한다.
