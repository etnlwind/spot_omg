# iOS/macOS 전용 제어 채널 및 진단 로그

V90-R2 앱 빌드 60. STM32/ESP32 기존 controlv1을 사용하므로 이번 변경에 펌웨어 재설치는 필요하지 않다.

## 명령 우선 처리

Windows와 동일하게 BLE 005 쓰기/006 알림으로 `@C sequence command` 및 DATA/DONE 프레임을 주고받는다. 기존 003 알림은 진단 로그 전용으로 취급한다. 초기 상태에서 controlv1과 알림 구독을 확인하고 기존 명령이 완료된 뒤 전환한다. 구 펌웨어 및 시뮬레이터는 기존 통신을 유지한다.

일반 명령은 동시에 하나씩 전송하고 해당 sequence의 DONE만 완료로 인정한다. 조이스틱 @D, 정지 @S, 인터럽트는 진행 중인 일반 명령의 완료를 기다리지 않는다. 오래된 로그의 OK/ERROR/프롬프트는 제어 상태를 바꾸지 않는다. Stand의 물리적 완료 및 새로운 상태 확인은 유지하며, 로그 전송 완료는 기다리지 않는다. STM32가 동작 완료 후 수행하는 내부 기록 자체의 시간까지 제거한 것은 아니다.

## 진단 기록

수신 상세 로그는 RobotConnectionTrace의 백그라운드 직렬 큐에 기록한다. 화면은 명령 결과·오류·상태 변화만 표시한다. 독립적으로 발생하는 support monitoring 오류와 로그 유실 알림은 화면에도 남긴다. 예전 명령의 오류가 새 보행 세션을 중단시키지 않도록 일반 진단 텍스트를 제어 응답 파서에 넣지 않는다.

Library/Caches/RobotConnection의 current.jsonl, previous.jsonl 각 512KiB를 순환 보관한다. 무한 보관이 아니며 캐시이므로 OS가 정리할 수 있다. 콘솔의 '진단 로그 준비'로 현재 두 파일의 스냅샷을 만든 뒤 '로그 저장·공유'로 보존한다. 기록·내보내기 파일 작업은 UI/제어 경로 밖에서 수행한다.

## 전압 경로

전압 표시 및 앱 저전압 경고는 정지 중 `read 1`의 새로운 `ID 1 voltage=... moving=0` 응답으로만 갱신한다. 전용 채널에서는 이 응답도 DATA 프레임에 포함된다. 정지 후 3초 안정화, 1초 이상 간격의 3개 표본, 200mV 이내 편차/중앙값 정책을 유지한다. 진단의 `$BATTERY` 부하값, `Gait diagnostics min_voltage` 과거 최저값, 과거 ID 출력은 앱의 안정 전압 경고에 사용하지 않는다. 보행 중 새 전압을 조회하지 않으므로 표시값은 마지막 안정 전압이다. STM32 자체 구동 보호는 변경하지 않는다.

## 검증

- Mac/iOS 공용 84개 시험 통과: 분할 프레임, 잘못된 프레임, 명령 직렬화, 이전 sequence 무시, 로그 폭주 중 정지/다음 전진, 로그와 독립적인 전압, 기록 내보내기 포함.
- 자발적 support monitoring 경고 표시 추가 후 해당 제어/전압 시험 재검증.
- 기존 STM32/ESP32 실제 통신 코드 호스트 시험 2개 통과: 로그 backlog/overflow 중 완료 및 다음 명령 우선, 실시간 정지 처리.
- 물리적 위치 유지/보행 시험과 위 호스트 통신 검증은 별개다.

## 설치 및 실기 연결 확인

아이폰 UJIN17 및 /Users/etnlwind/Applications/Spot OMG!.app에 빌드 60 설치·버전 확인. 아이폰 실제 로그에서 control-channel enabled 이후 @C 3385163395/3396 read 1과 11700mV 응답을 확인했다. 다음 조회까지 진행했으므로 상관된 DONE 처리도 통과했다. 연결 당시 저장값 FL=20, FR=20, RL=0, RR=0을 읽었다. 연결 시점부터 safety=tilt/fault_code=14였으며, 이 검증에서 전진 명령은 보내지 않았다. 앱 비활성화의 기존 Stand 요청이 뒤이어 기록됐으며, 이를 성공한 자세/보행 시험으로 보고하지 않는다. 증거는 artifacts/foot-lift-v90-r2/control-channel-live-trace 및 control-channel-ios-apps.json.

## 빌드 61: 전/후/좌/우 ±20도 스냅

앞 또는 뒤 축에서 좌우 20도 이내(경계 포함)는 yaw=0으로 보내고, 전후 입력은 원래 스틱 반경에 해당하는 속도를 유지한다. 좌우 양쪽에서 앞축 기준 70~110도(경계 포함)는 linear=0인 제자리 회전으로 보낸다. 나머지 20~70도 및 110~160도 구간은 전진/후진+회전 혼합이다. 중앙 데드존은 유지한다. iOS/macOS 및 Windows 입력 변환을 동일하게 수정했다. 펌웨어/관절 궤적은 변경하지 않는다.

빌드 61 아이폰·맥 설치 및 버전 확인 완료. Windows 프로토콜 시험 136개 통과, Apple 전체 시험 통과 후 최종 ±20도 경계 수정 관련 3개 재검증 통과. Windows 소스 반영만 수행했고 Windows 기기 설치 및 실기 보행 시험은 수행하지 않았다.
