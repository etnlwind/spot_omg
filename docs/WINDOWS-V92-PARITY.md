# Windows V92: Mac 앱 기능·화면 반영

2026-09-22 사용자 요청. 앱 버전 92.0.0, 표시 이름 Spot OMG!. 이 작업은 Windows 앱 소스와 배포 구성을 갱신했다. 로봇 펌웨어·Mac 앱·iPhone 앱을 다시 설치하거나 실기를 움직이지 않았다.

## 반영한 항목

- 기본 다크 테마와 명시적 체크 표시, 높은 대비의 보조 글자. 조종·자세 버튼을 설정 목록보다 위에 배치했다.
- 모델 보행 / 직접 설정 보행 탭. 선택하지 않은 모드의 설정을 숨긴다. 모델은 펼쳐진 목록에서 Mac과 같은 한글 이름으로 표시하고 원래 프로토콜 키를 전송한다. V6가 맨 위이며 지원 capability가 없는 모델은 선택할 수 없다. 기존 V6 기본 선택, ±20도 스틱 스냅, 자동 복귀/입력 유지 기능을 보존했다.
- 주황색 앱 아이콘과 발높이 팝업의 실제 CAD 윗모습은 Apple PNG와 동일한 파일이다. Windows ICO는 같은 아이콘의 형식·크기 변환이다. `build.ps1`에 리소스 포함, ICO, `__version__`에서 생성한 Windows 파일 버전 정보를 추가했다.
- 발높이 저장은 기존 STM32 영구 저장·새 readback 확인을 유지한다. 입력값을 바꿨다는 이유만으로 저장되거나, 팝업 열기로 로봇 값을 덮어쓰지 않는다.
- 상세 진단을 별도 쓰기 스레드의 JSONL 순환 파일 두 개(각 512KiB)에 기록한다. 큐가 가득 차거나 디스크가 느려도 제어 스레드를 기다리게 하지 않는다. 파일 저장은 비동기이며 앱 종료도 파일 쓰기를 기다리지 않는다. 이 제한 때문에 강제 종료·기록 큐 포화 시 일부 진단이 유실될 수 있고 무제한 보관이 아니다.
- BLE의 상관된 제어 응답을 먼저 처리하고, 상세 로그를 Qt 화면에 그대로 쏟지 않는다. 명령 결과·오류·상태·자동 IMU 복구·독립 support 오류·로그 유실 알림은 표시한다. 기존 로그의 배터리 최저값은 충전 경고에 사용하지 않는다.
- 수동 IMU 복구는 지원 펌웨어/실기/정지 상태를 확인하고 정확한 복구 ACK와 새 상태를 조회한다. 그동안 입력을 막고, 완료 후 스틱 해제와 새 입력을 요구한다. 실패·시간 초과·취소를 별도로 표시하며 보호 상태를 임의로 지우지 않는다.

## 검증

- Windows 앱 테스트 **242개 통과**: UI, 명령·입력 상태, 전압, 발높이 저장/readback, 전용 BLE 모형, 로그 폭주·느린 디스크·내보내기, IMU 복구, 기존 MuJoCo 정지 통합 포함.
- Mac의 Qt offscreen 화면으로 기본 화면과 발높이 팝업을 렌더링해 확인했다. 새 모델 이름이 원래 wire key와 분리되어 전송되는지, 다른 모드 입력이 숨겨지는지 검사했다.
- 시뮬레이션 테스트에 기존 NumPy matmul 경고 9개가 남는다. 실제 Windows 그래픽·BLE 드라이버 검증과는 구분한다.
- `git diff --check` 통과. Windows PE 버전 메타데이터 생성 내용과 포함할 리소스를 확인했다.
- **Windows `.exe` 빌드와 Windows PC 설치는 미실행**: 현재 작업 환경은 Mac이고 접속 가능한 Windows 대상이 제공되지 않았다. PowerShell/PyInstaller의 Windows 실행과 실제 배포 앱 시작 검사가 남는다.
- 로봇 설정 readback·위치 유지·실제 보행 시험은 이 Windows 변경에서 수행하지 않았다. 테스트의 모형 응답을 실기 관측으로 해석하지 않는다.
