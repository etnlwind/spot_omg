# 수평 우선 Level 모드 — v19

사용자는 물컵을 실제로 올리겠다는 뜻이 아니라 그 정도로 몸체 수평이 유지되는 보행을 원했다. 물컵/액체/추가 하중 모델은 추가하지 않았다. IMU 교체 가능성도 열어 두었으나 먼저 궤적과 제어, 센서 지연을 분리해서 검증했다.

## J1이 실제로 움직이는가

v18 imu 모드의 60초 최대 직진에서 J1 보정 최대값은 약 0.054도였고, 각 모터 명령은 두 위치 코드 사이에서만 변했다. 명령 범위는 0.08789도였다. 실제 시뮬레이션 관절 각도 범위는 약 4.71~5.36도였다. 이 실제 각도 변화는 능동 보정 명령보다 훨씬 크며 하중과 모델의 서보 추종 오차를 포함한다. 이를 적극적인 수평 보정 성과로 볼 수 없다.

하드웨어와 같은 0.1도 명령 반올림 및 4096 tick 변환을 통과시킨 후 측정했다. 데이터는 `simulation/mujoco/level_gait_validation.json`에 명령 범위, 위치 코드 개수, 실제 관절 범위를 따로 기록한다.

## 선택한 구현

기존 모드는 유지하고 `level`을 추가했다. 크롤/느린 짧은 보폭 후보는 실제 전진 속도가 매우 낮거나 다른 진동이 남아 선택하지 않았다. 최종 발 순서는 기존 대각 트롯을 유지한다.

- 직진 기본 주기 1.0초, duty 0.64, 보폭 파라미터 65mm, 최대 명령 발 높이 7mm.
- 전진 입력을 제한하는 대신 궤적의 주기와 높이를 조정했다. 기존 20mm lift/imu 모드와는 발 높이가 다르다.
- J2/J3 IMU 수평 PI 및 heading hold 유지.
- Level의 J1 roll 보정은 57 deg/rad, 최대 ±1.5도. 필터된 기울기만 사용하고 지연된 Euler 미분 예측, 스윙마다 부호 반전, 적분 증폭은 사용하지 않는다.
- 기존 imu의 작은 J1 보정과 분리된 공통 C 경로를 사용한다. STM32 및 MuJoCo 모두 `balance_control_apply_policy`로 실행한다.
- nominal 조건의 J1 명령 범위는 약 0.44~0.62도, 6~7개 위치 코드였다. 외란/물성 변경에서는 약 0.70도, 8개 코드까지 사용했다.
- 기존 PI만 사용하는 동일 Level 궤적의 결과도 비교했다. 수평 개선의 대부분은 궤적 개선에서 왔으며 J1만의 효과는 작다.

## 60초 최대 직진 비교

`simulation/mujoco/validate_level_gait.py`: 매 200ms에 입력 1000/1000을 재전송. 초기 준비와 최종 정지를 별도로 포함. 실제 물리 질량·모터·마찰을 유리하게 변경하지 않았다.

명목 물성/seed 55 기준:

| 지표 | 이전 imu v18 | Level v19 |
|---|---:|---:|
| roll/pitch 합성 RMS | 2.820° | 0.271° |
| 최대 roll/pitch 절댓값 | 7.881° | 0.644° |
| 자세 변화율 RMS | 30.759°/s | 5.635°/s |
| 상하 가속도 RMS | 1.267m/s² | 0.829m/s² |
| 몸체 높이 표준편차 | 4.016mm | 1.863mm |
| 평균 이동 속도 | 0.0766m/s | 0.0921m/s |

서로 다른 seed 55/77/101에서 Level 최대 기울기는 0.644/0.658/0.655도. 외란, 질량·마찰 변경, COM 변경 포함 직진 검증에서는 최대 0.848도였다. 이 수치는 추정 모델의 선택된 조건에 한정된다. 몸체 높이 변화와 상하 가속도가 남아 있으며 무진동/완전 수평이나 실제 로봇 성능 보장이 아니다.

동일 Level 궤적에서 J1 보정 OFF 시 RMS 0.281도, ON 시 0.271도였다. 센서 교체나 J1 gain 증가만으로 큰 개선이 난 것이 아니다.

## IMU 교체 판단

센서 모델의 fusion delay만 20ms에서 0ms로 줄이고 샘플링/제어 주기 등은 유지한 비교:

- 이전 imu: RMS 2.820 → 3.585도
- Level: RMS 0.271 → 0.295도

이 실험에서는 지연 감소만으로 개선되지 않았다. 비선형 접촉/피드백과 게인 튜닝 영향을 받으므로 '느린 IMU가 더 좋다'는 의미는 아니다. 특정 대체 IMU의 모델이나 실제 성능을 평가한 것도 아니다. 교체 권고에 앞서 실제 BNO055 지연, 설치 축/진동, 서보 하중 추종을 측정해야 한다.

## 검증/실행

- 직진 A/B·센서·물성 11개 실행 완료. `level_gait_validation.json`.
- 좌우 pivot/arc/turn_forward/reverse_arc 8개 실행 통과. 회전 최대 기울기 3.03도이며 직진의 1도 이하 결과를 회전에 일반화하지 않는다. `level_turn_validation.json`.
- 공통 C/서보/프로토콜 테스트 55개 통과. 0.5도 roll 입력에서 Level J1이 서보 4 tick 이상 반응하는 검사 포함.
- 앱 XCTest 45개 통과. 앱 V0.4.1(13), `수평 우선 · Level` 선택 항목. Xcode에서 UJIN17에 설치/실행 완료.
- STM32 `shared-locomotion-v19` 빌드 성공, 152888 bytes. 실물 로봇에 설치하지 않았다.
- MuJoCo 실행 시 `--profile level`. 키 8=Level, 키 7=기존 imu. 앱에서는 `수평 우선 · Level`을 선택한다.

```bash
cd /Users/etnlwind/project/spot_omg
PYTHONPATH=tools/servo_tool:simulation/mujoco /opt/anaconda3/envs/spot_omg/bin/mjpython simulation/mujoco/virtual_robot.py --viewer --profile level
```
