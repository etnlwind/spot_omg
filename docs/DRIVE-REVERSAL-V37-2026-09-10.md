# 전진 → 후진 조종 전환 수정 (V37 / 앱 35)

## 실제 관측

아이폰 연결 로그에서 `drive` 시작 직후 스틱 중앙 입력이 `@S` 정지 요청으로 바뀌었다.
예: 23:06:56 drive seq255 시작, 약94ms 후 중앙 입력으로 @S256 전송.
이후 로봇이 `drive watchdog expired`로 종료했다. 앱은 종료 오류를 “보행 명령 거부”로 표시했다.
전진→후진 중 중앙을 지나면 앱의 세션이 stopping/draining으로 들어가 후진 입력을 무시했다.

펌웨어 shared drive는 정상 Stop 이후 감속/Stand 복귀 중에도 마지막 패킷에서800ms가 지나면
watchdog를 설정했다. 따라서 이 로그만으로 BLE 정지 패킷 유실이라고 단정할 수 없다.
이전 설명의 “정지 신호 처리 불가” 가능성은 확정 원인이 아니었다.

## 변경

- 손가락을 대고 중앙을 지날 때 `@D seq 0 0`으로 감속한다. 세션과200ms heartbeat를 유지한다.
- 반대 방향 입력을 동일 세션의 @D로 전달한다. 펌웨어의 기존 속도 변화 제한을 유지한다.
- 손 떼기, 제스처 취소, 화면 이탈은 기존 @S/안전 정지를 유지한다. 중앙에서 새 보행을 시작하지 않는다.
- 정상 Stop 이후에는 heartbeat가 필요하지 않으므로 감속 중 watchdog 신규 판정을 하지 않는다.
- 실제 패킷 단절에 대한800ms 제한은 그대로다. uint32 시간 wrap도 검사한다.
- 통신 시간 초과는 “조종 신호 지연 · 자동 정지”로 표시한다.
- 시뮬레이터도 정상 정지 이유가 watchdog으로 덮이지 않도록 조건을 명시한다.

## 검증 수준

- Swift 호스트: 전진→중앙→후진이 drive1회+@D 갱신으로 이어짐, 중앙에서 @S 없음,
  손 떼면 @S 전송, watchdog 문구 구분 통과.
- C watchdog 회귀: 경계800/801ms, 정상 정지 장시간 경과, uint32 wrap 통과.
- 공용 보행/펌웨어 호스트38개 및 가상 로봇30개 검사 통과. iOS 기기 빌드 및 STM32 빌드 성공.
- V37 바이너리174404bytes, SHA256 `1616e61e3f77ddc4f0302ba08579731e500b0a8daffb07d42da800544932e56f`.
- 실제 V37 업로드·검증·재부팅 완료. 사전 Landing은 성공했다. 설치 후 `syncstate`: `rev=shared-locomotion-v37 pose=landing torque=off safety=ok profile=cruise`. 아이폰 앱 V0.5.0 (35) 설치 완료. 실기 방향 전환은 아직 검증하지 않았다.
- 자동 연결 해제는 Stop 전송 후 응답 미수신으로 시간 초과했다. 앱 프로세스를 종료하여 BLE를 확보한 후 `--no-app-control`로 업데이트했다. 자동 해제 전체 경로가 통과했다고 보고하지 않는다.
