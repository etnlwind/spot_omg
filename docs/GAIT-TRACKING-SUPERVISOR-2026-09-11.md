# V42 실측 추종 기반 보행 진행 보정 — 실험, 기본 OFF

## 상태

코드/빌드와 추정 물리 비교를 완료한 실험이다. 실제 로봇에는 설치하지 않았다. 실물의 현재 확인 대상은 V41이며 V42 MCU 계산 시간/버스 시간/실기 자세 유지/회전 검증은 미수행이다. 발 들림/착지 접촉/하중 전환까지 해결한 완성형 보행 제어가 아니다.

## 구현

- `gait_tracking.h`: 12축 각각의 실측 오차와 읽은 시각을 보존한다. 실측 오차는 **그 축을 읽을 때 활성화된 목표**와 비교하며, 과거 측정값을 현재 시각의 위치라고 취급하지 않는다. 부호/중심/누적 서보 원점은 변경하지 않았다.
- STM32 기존 `sample_next_joint` 결과를 재사용한다. 추가 모터 조회나 토크 증가 명령은 없다. 기본240ms 순차 읽기와 stall 후보 집중 감시를 유지한다.
- 6° 이하의 추종 오차에서는 진행률1. 6~14°에서 공통 진행률을 낮추고 14° 이상/측정 나이360ms 초과에서는 위상 진행을 멈춘다. 감소 최대0.6/s, 회복0.2/s. 이는 실험용 상위 기준이고 기존 모터 보호 임계값을 완화하지 않는다.
- 공통 위상/진폭 램프/조종 입력 변화 속도를 함께 조절해 다리별 독립 위상 지연을 만들지 않는다. 새 목표각을 오차만큼 증폭하는 방식이 아니다. 목표 보폭은 유지하지만 추종이 부족하면 실제 보행 주기는 길어진다.
- 진행률5% 미만600ms 지속 또는 측정 나이600ms 초과 시 현재 보행을 취소한다. 기존 새 명령 복구 절차는 유지한다.
- Stop은 정상 상태의 진행률 제한을 우회해 감속/정지한다. 이미 피드백 fault가 났으면 보행은 취소 상태다. 센서가 돌아올 때까지 무한 대기하지 않는다.
- `drive_control_step_timed`는 실제 프레임 경과시간을 받아 위상·heading dt·입력 slew를 계산한다. 60ms를 넘긴 프레임은 진행하지 않고 중단한다. 과거 타깃을 몰아서 보내지 않는다. 명령 속도/가속도 진단도 실제 프레임 시간으로 계산한다.
- 기존 `drive_control_step`은20ms/진행률1 래퍼로 남겨 이전 명령과의 회귀 기준을 유지한다.
- 시뮬레이터는 같은 C supervisor를 호출하고, 한 프레임에 한 관절의 틱 양자화 피드백만 공급한다. 실제 접촉력/정답 발 높이는 supervisor 입력으로 쓰지 않는다. 접촉력은 평가에만 사용한다.
- `tracking on`, `tracking off`는 정지 상태에서만 사용한다. `trackingdiag`는 활성 여부, 공통 진행률(1000=1), 최대 현재 샘플 오차(0.1°), 가장 오래된 측정 나이, 정체 시간, fault를 표시한다. `contact=unobserved`를 명시한다. 앱 터미널에서도 같은 명령을 사용할 수 있으며 전용 UI 버튼은 추가하지 않았다.
- **기본 OFF**다. 정상 조건 이외의 접촉/자세 품질이 개선되지 않아 기본 정책으로 채택하지 않았다. 시뮬레이션 A/B는 `tracking_feedback_enabled`로 명시한다.

## 비교 결과

각14.02초,10초에 Stop. 좌/우 원호 턴. 실제 쿠션 CAD와 추정 물성/모터/지연 사용.

| 조건 | 기존 관절 추종 RMS | 보정 RMS | 최소 공통 진행률 |
|---|---:|---:|---:|
| 정상 좌 |1.6356°|1.6356°|1.000|
| 정상 우 |1.6096°|1.6096°|1.000|
| 명령 지연80ms 좌 |2.5173°|2.2533°|0.7502|
| 명령 지연80ms 우 |2.5165°|2.2152°|0.7502|

8개 회전 시험은 안전 정지 없이 Stop 완료. 별도 피드백 누락 조건에서는 tracking fault로 보행 취소했다. 추종 오차 개선 약10.5%/12.0%는 진행 속도를 조절한 결과이며 같은 실속도에서 얻은 성능 향상이라고 주장하지 않는다.

**악화 항목:** 지연80ms에서 최대 roll은 좌0.79→1.84°, 우1.05→1.90°로 커졌다. 일부 다리의 중간 스윙 접촉도 증가했다. 정상 조건은 이번 시험에서 이전 결과와 동일했다. 첫 후보(4°부터 빠르게 개입)는 정상 조건에서도 흔들림/접촉이 악화되어 폐기했고 원시 결과를 `tracking-v42-first-candidate`에 보존했다.

원인 해석: 관절 지연에 맞춰 공통 진행률을 바꾸는 것만으로는 몸체 동역학/지지 전환을 자동으로 맞출 수 없다. 이를 발 들림 보장이나 전체 보행 성공으로 표시하지 않는다.

## 남은 구조적 한계

이 구현은 timestamp가 붙은 **오차 기반 진행 감독기**다. 12축 동시 상태 관측기, 실측 FK 기반 지면 여유 추정, 접촉 추정, 하중 분배/힘 제어는 아직 없다. 각 축의 최근 오차를 보수적으로 사용하며 오래된 측정 사이에 실제 발 위치를 정확히 안다고 가정하지 않는다. 서보 자체 위치 제어와 기존 IMU 보정은 계속 존재한다.

계산량/버스 여유를 실기로 측정하고, 발 위치·접촉 추정과 지지 다리 제어를 결합해 자세/접촉 악화까지 해소하기 전에는 기본 ON 또는 실물 개선 완료로 취급하지 않는다.
