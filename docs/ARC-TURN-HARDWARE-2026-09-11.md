# 원호 턴 실물 이식 — 2026-09-11

## 범위와 구분

사용자가 실물 시험을 요청했다. 기존 `cushion_diagonal_sync_wide80`는 Python 전용 전신 보정 정책이므로 그대로 펌웨어에 설치할 수 없다. 새 `arcturn`은 CAD 원호 발 경로를 C로 옮긴 별도 시험 정책이다. **Python의 전체 SupportShift IMU/엔코더·정적 하중 보정을 이식한 것은 아니다.** 실물과 MuJoCo의 arcturn은 동일한 C drive/IK/balance 코드를 사용한다. 기존 정책 ID와 기본 cruise는 유지했다.

- 원호 각도 0.2rad, 순수 회전 주기 1.2초, 목표 스윙 높이 20mm.
- 회전 입력 ±1000을 절반으로 제한하지 않는다.
- 직진 기본 80mm / 1.44초, 회전과 연속 혼합.
- 실제 쿠션 mesh, CAD 관절축/방향에서 발 위치와 Jacobian을 계산한다.
- J1/J2/J3의 관절각으로 출력하고 기존 서보 보정·signed 원점 변환을 사용한다.
- 지면 높이는 쿠션의 실제 최저 vertex. 매 프레임 접촉력 정답을 사용하지 않는다.
- STM32 20ms 주기 보장을 위해 새 IK 함수에만 GCC O2를 적용. 버스·안전·다른 펌웨어 코드의 최적화 설정은 유지한다.
- 제한을 넘거나 IK가 수렴하지 않으면 전체 목표를 거부한다. 기존 Stop, watchdog, IMU, 추종 오차, 지연 정지 기준을 완화하지 않았다.

## 검증 수준

1. CAD/C 경로 비교: 회전 양방향, 직진, 대각선, 정지 및 시작 진폭에서 Python 목표와 발 위치 차이 0.25mm 이내. (서보 실측 결과가 아니다.)
2. 공용 제어 호스트 검사 16개, 펌웨어 회귀 29개 통과.
3. 동일 C 코드 MuJoCo 24.02초 좌/우 시험, 20초 Stop. 둘 다 safety OK, Stop 완료. 5~19.98초 회전 속도 좌 17.25°/s, 우 17.38°/s; 최대 roll 각각 0.97°/1.15°, pitch 0.34°/0.42°.
4. 발 여유는 최대 약 8~13mm이며 일부 중간 스윙 접촉이 남았다. 발 들림 합격 기준은 미달. 정격 추정치 초과 토크도 존재하므로 전체 정책 표시는 `(검증실패)` 유지.
5. 실물 설치 전 상태: V37, stand, safety=ok, read 1 전압 12100mV, 온도30°C, moving=0, hw=0x00. 업데이트 전 Landing 정상 완료.

원시 시뮬레이션 기록: `artifacts/upright/2026-09-11/cushion/arcturn-shared-c-{left,right}.json`.
기하 생성: `simulation/mujoco/scripts/analysis/export_arc_geometry.py`.
물리 검사: `simulation/mujoco/scripts/validation/validate_arc_hardware.py`.
실물 검사는 `tools/test_arc_turn_hardware.py --execute --output <JSON>`로만 명시 실행한다. 방향별 최대 4초의 명령 구간과 Stop을 사용한다. 초기 정상 전압/상태, 설치 버전 확인, 시험 후 오류/지연 확인을 통과해야 다음 방향으로 진행한다.

## 앱과 벤치마크

iPhone V0.5.0 (42)에 `원호 턴 · 실물 시험 (검증실패)`를 추가한다. 새 앱 메뉴는 실제·가상 로봇 모두에서 같은 `arcturn` ID를 보낸다. V37에서는 지원하지 않으므로 V38 설치 후 사용한다.
기존 속도 측정값의 원본 manifest hash를 바꾸지 않았다. 원본 manifest를 별도 보존하고 생성기가 기존 정책 설정의 동일성을 확인한 경우에만 예전 값을 유지한다. 새 실험 정책은 측정 속도로 합격 처리하지 않는다.


## 실물 시험 결과

V38 설치·검증·재부팅은 완료했다. 그러나 `stand` 준비 단계에서 FL-J2(ID2)가 `SAFETY stall`로 중단됐다. **arcturn 선택과 좌·우 회전은 실행되지 않았다.** 목표1565 / 실측2867 / 오차1302틱, load−632, current39, 30°C, 하드웨어 오류0, 지속254ms, `TORQUE_OFF_ALL`을 기록했다. current는 프로토콜 원시값이며 단위 변환 없이 기록한다.

정지 후 조회: pose=custom, torque=off, safety=fault. ID2 위치2934, 12300mV; ID5 위치1062, 12200mV; 두 모터 speed=0/moving=0/hw=0. 배터리 저전압으로 단정할 증거는 없다. 걸림·좌표·토크 부족 중 무엇인지 아직 판별되지 않았으므로 자동 재시도하지 않았다. 사용자에게 현재 자세와 걸림 여부를 확인 요청했다.

`stowcheck`의 문구는 정적 구성 설명이며 실제 레지스터 readback 검증으로 세지 않는다. `imuprobe`는 BNO086 SPI용이므로 그 실패 출력도 현재 BNO055의 고장 증거로 해석하지 않는다.

후속 V39는 arcturn 궤적/보정 코드를 바꾸지 않고 `gaitprofiles` 목록을 생성된 프로필 목록과 일치시키며 reverse_limit 상태 표시를 실제 제한 계산과 일치시킨다. 보호 정지 후 불필요한 Landing 재시도를 피하도록 `firmware stm32 --skip-landing`을 추가했다. 이 옵션은 syncstate로 torque=off를 확인하지 못하면 업데이트를 거부한다. 기본 업데이트는 기존처럼 Landing을 시도한다. 관련 검사9개와3개 하위 검사 통과.

원시 기록: `arcturn-hardware-v38.json`, `arcturn-hardware-v38.log`, `arcturn-readonly-after-stall.log`.

## V39 약 2초 후 정지 → V40 계산량 개선

후속 사용자의 실제 원호 턴 로그에서 `reason=motion aborted elapsed=2990ms`, `late_frames=43`, `fault_code=12`를 확인했다. 이 구간에도 @D 명령은 지속 도착했다. min_voltage=11900mV, lag=0, fall=no, bus retries3회 모두 회복. 반복 제어 지연과 40ms 초과 지연 시 중단하는 공용 루프 경로가 일치한다. 최초 Stand의 stall과 다른 정지다. CPU/버스 기여 시간 자체는 V39가 기록하지 않아 분리 측정 전이다.

V40 변경:
- 매 IK 반복의 쿠션 2000개 정점 전체 검색을 균형 공간 트리의 branch-and-bound 검색으로 바꿨다. 형상 축소나 스윙 높이 축소가 아니다. 5006 방향에서 전체 검색과 최저 투영값 차이 1e−8m 미만을 검사했다. 동점은 정점 인덱스로 결정한다.
- 초기에 시도한 convex 인접 정점 하강은 평평한 면의 float 동점에서 실패해 폐기했다. 실패를 허용 오차로 통과시키지 않고 공간 트리로 교체했다.
- 관절 회전/이동 변환을 한 번 계산해 발 중심·쿠션·Jacobian에 재사용한다. 반복 삼각함수 호출을 줄였다.
- 20ms 주기, 40ms 초과 정지, 관절/토크/IMU/추종 보호는 유지한다.
- `locomotiondiag`에 compute_max_ms/io_max_ms 추가. `arctiming`은 모터 명령 없이 좌우 128개 원호 목표를 계산해 최대/평균 시간을 출력한다. 실기 시간 예산 확인 후 움직임을 시험한다.
- 검증 중 시뮬레이터 C 라이브러리 캐시가 새 `arc_turn.h`/`arc_geometry.h` 변경을 반영하지 않던 문제를 발견했다. 이 의존성을 캐시 키에 추가했다. 초기 O0/O2 차이는 오래된 코드와의 비교였으며, 캐시 수정 후 전송 틱의 **완전 일치** 검사에 통과했다. 1틱 허용으로 기준을 완화하지 않았다. 수정 전 생성된 V40 시뮬레이션 결과는 새 캐시로 다시 실행한다.

호스트/펌웨어 회귀 48개 통과 (캐시 의존성 회귀 포함). 데스크톱의 최저점 검색 부분은 전체 검색보다 약3.8배 빠르지만 이 수치를 STM32의 전체 루프 속도로 해석하지 않는다. 최종 V40 빌드는 223308바이트, SHA256 `731cf4cc1a0538ed70e448f8a7e23e92ca8baf2e519474d30e37ec3915a11d4d`.

V40 설치·이미지 검증·재부팅 완료. `arctiming`: samples=128, max_ms=23, mean_us=18976, failures=0, motor_commands=0. 계산만으로 20ms 예산을 넘으므로 실물 회전을 실행하지 않았다. V40만으로 해결되지 않았음을 기록한다.


## V41 Cartesian 초기값 표

V40의 실제 계산 시간이 부족하여 중립각부터 반복하는 IK의 초기값을 개선했다. CAD/쿠션을 사용해 각 다리의 Cartesian 작업 영역을 9×5×3 위치에서 오프라인으로 풀고, 실행 시 삼선형 보간한 관절각을 **계산 초기값**으로 사용한다. 표의 목표점 잔차 최대0.0996mm. 실제 명령은 여전히 원래 목표에 대한 full-mesh IK 수렴·관절 제한 검사를 통과해야 한다. 표 밖에서는 초기값 조회만 경계로 제한하며 목표점이나 보폭은 제한하지 않는다. 중립부터 시작하는 방식과 같은 목표/허용오차이며, 정수 틱까지 이전 버전과 동일하다는 뜻은 아니다. O0/O2 간에는 여전히 전송 틱 완전 일치 검사를 유지한다.

V41 호스트/펌웨어 검사48개 통과. 공용 C 코드 MuJoCo 좌우 각각24.02초/20초 Stop: 안전정지 없이 Stop 완료. 좌 max roll0.9384°, pitch0.3022°; 우1.1357°,0.4049°. 관절범위/추정 토크-속도 envelope 내. 정격 추정치 초과 비율과 발 접촉 미달이 있으므로 정책의 전체 검증실패 표시는 유지한다.

V41 이미지230240바이트, SHA256 `a50afcced41da3252e8f7b2c1cd80bd5c4184acc951e4eebb6da185a767a5b45`. 실기 계산 시간과 회전 결과는 설치 후 별도로 기록한다.


### V40 사용자 좌회전 시험에서 옆걸음 관측

사용자는 좌회전 시 오른쪽으로 옆걸음한다고 보고했다. 앱 기록에서는 `drive ... yaw=-776`, 이어서 대부분 linear=0 / yaw≈−995가 전송되어 좌회전 입력 자체는 확인됐다. 18.501초 후 reason=ok, Stop으로 종료됐으나 late_frames=618/744samples였다. 사후 `locomotiondiag` compute_max_ms=24, io_max_ms=34, fault=0. 두 최대값이 같은 프레임에서 발생했다는 의미는 아니다. min_voltage=11600mV, 버스 retry10회 회복/실패0회. 최대 J3 추종 오차 FR6.9°/RL5.7°/RR7.6°, lag 기준 초과0회. 추종 오차 기준 통과를 발 들림 성공이나 정확한 회전의 증거로 사용하지 않는다.

실제 접촉/세계좌표 이동 기록이 없으므로 방향 부호, 발 끌림, 하중 비대칭 중 원인을 확정하지 않았다. V41은 계산 지연 개선이며 옆걸음 해결판으로 표시하지 않는다. 설치 전 Landing은 정상 완료됐다.


### V41 설치 결과와 남은 검증

Landing 정상 완료 후 V41의 ESP32 전송, STM32 flash100%, 이미지 검증, 재부팅까지 성공 응답을 받았다 (`arcturn-v41-upload.log`). 재부팅 뒤 직접 BLE 검색은 기체를 찾지 못했고, 앱 원격 연결 해제도 응답 시간 초과됐다. 따라서 V41의 실행 버전 readback, MCU arctiming, 실제 회전/IMU 변화 검사는 아직 미수행이다. 설치 성공을 실행 시간/옆걸음 문제 해결로 표현하지 않는다. 사용자에게 앱 완전 종료 후 링크 해제를 요청한다.
