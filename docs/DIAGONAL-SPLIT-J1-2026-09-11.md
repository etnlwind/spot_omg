# J1 허용 후 지지·스윙 분리 구현 — 2026-09-11

## 현재 상태

사용자가 J1 고정 해제를 허용했다. `cushion_diagonal_sync`를 `upright_profiles.json`에 **검증실패 실험 정책**으로 저장했다. 기존 기본 정책·앱·라이브 서버·실물 펌웨어를 교체하지 않았다. 60초 안전정지 없는 동작은 확인했지만 전체 안정성·동기 기준은 미달이다.

## 저장한 정책의 동작

- 60mm 명목 보폭, 1.44초 주기, 지지율 0.5. 대각선 두 발 교대. 의도적 네 발 대기 없음.
- `split_residual_tasks`: 지지 다리의 자세/높이 보정과 스윙 다리의 지면 기준 높이 오차 보정을 분리한다. 보정은 제한된 잔여 오차 보정이며 완벽한 지면 궤적 추종으로 표현하지 않는다.
- 스윙 구간에는 지지용 높이 보정을 더하지 않고 정적 하중 보상도 부드럽게 줄인다.
- J1/J2/J3를 모두 CAD Jacobian IK에서 사용할 수 있다. 임의 J1 각도를 더하는 대신 발 위치 목표로 계산한다.
- 지연 IMU·엔코더로 지지 발과 무게중심을 중력 좌표계에 옮겨, 무게중심을 지지 발 중심선 쪽으로 이동시키는 최대 10mm 좌우 보정을 계산한다. 접촉력 정답은 입력으로 쓰지 않는다. 두 발 중심선은 유한한 쿠션 접촉 지지영역 전체를 나타내지 않으며, 이것은 완전한 동역학 제어가 아니다.
- 높이 추정과 높이 피드백 이득을 분리한 구현도 추가했다. 특히 실험용 전체 작업 풀이에서 높이 보정을 껐다고 추정까지 꺼지지 않도록 했다.
- 기존 관절 범위·모터 토크/속도·안전정지는 유지했다. 실험용 전체 작업 풀이의 별도 보정 한도 확대 시험은 현재 저장 정책에 사용하지 않는다.

`support_task_experiments.py`에는 전체 X/Y/Z 작업 풀이, J1 고정 X/Z 풀이 등을 보관했다. 해당 경로의 시험은 실패했으며 저장 정책은 완만한 residual 분리 경로를 사용한다. 이 경로들을 동일한 검증 수준으로 취급하지 않는다.

## 비교 결과

같은 60초 평가(65.02초 실행, 5초 이후 평가):

| 항목 | 기존 J1 고정 | J1 허용·분리 정책 |
|---|---:|---:|
| 안전정지 | 없음 | 없음 |
| 몸체 높이 최대−최소 | 8.43mm | 6.92mm |
| 몸체 높이 표준편차 | 1.52mm | 1.43mm |
| 최대 roll | 5.36° | 5.62° |
| RMS roll | 1.34° | 1.77° |
| 최대 pitch | 2.74° | 2.37° |
| RMS pitch | 0.63° | 0.78° |

별도의 같은 20초 동기 진단:

| 항목 | 기존 | 수정 |
|---|---:|---:|
| FL–RR 중간 스윙 접촉 불일치 | 25.0% | 16.81% |
| FL–RR 높이 차이 RMS | 10.55mm | 10.48mm |
| FR–RL 접촉 불일치 | 22.22% | 26.22% |
| FR–RL 높이 차이 RMS | 6.67mm | 14.70mm |

**한쪽 접촉과 높이 변동은 개선했지만 반대 대각선과 roll은 악화했다. 전체 동기 문제를 해결했다고 판정하지 않는다.** 60초에서 J1 명령 보정 최대값은 다리별 약 2.95~3.58도였다. 측정된 물리 모델의 rated torque 초과 비율도 약 21%로 품질 기준 미달이다.

14초 Stop 명령 후 18초에 motion/transition 모두 없음, safety OK를 확인했다. 호스트 회귀 25개 통과. 실기 설정 readback·위치 유지·전체 동작 검증은 수행하지 않았다.

## 제외한 접근

고정 J1 전체 지면 작업, J1 허용 후 큰 자세 이득, 빠른 보정, 짧은 보행 주기, 빠른 지지 이동 등을 시험했다. 일부는 기울기 안전정지, 일부는 높이/각도 악화로 제외했다. `artifacts/upright/2026-09-11/cushion/diagonal-separated-*.json`과 `diagonal-split-*.json`에 실패 결과도 보관했다. 과거 실험 중 추정기/XY 작업 구현 변경 전에 생성한 결과는 해당 시점의 구현 결과이며, 현재 코드로 모든 과거 수치가 그대로 재현된다는 보장은 하지 않는다. 현재 저장한 residual 정책의 60초/20초 결과는 아래 파일로 구분한다.
