# V90-R2: 로봇 소유 발 높이 설정

Windows / Mac Catalyst / iOS는 같은 로봇의 FL, FR, RL, RR 값을 읽고 쓴다. 앱 로컬의 `footLiftMm`는 더 이상 읽거나 자동 전송하지 않는다. 마지막으로 정상 저장한 값이 해당 로봇의 공통 설정이다. 앱의 미저장 편집은 다른 앱에 공유되지 않는다.

## 프로토콜

- `footlift show` 또는 `syncstate`: 로봇의 현재 저장·적용값 조회.
- `footlift save FL FR RL RR`: 정지 상태에서 네 값을 STM32 플래시에 기록하고 읽어 확인한 후 RAM에 반영. 응답은 `OK footlift saved` 및 상태.
- 앱은 `footliftpersist` capability가 있을 때만 저장을 허용한다. 저장 ACK 뒤 별도 조회 응답의 네 값까지 일치해야 완료로 표시한다.
- V90-R2는 구 `footlift set`을 거부한다. 업데이트되지 않은 앱의 연결 시 자동 업로드가 새 공통 설정을 덮어쓰지 않도록 하기 위함이다.
- 범위는 기존과 동일한 0..2147483647 정수 mm. 도달 불가능한 보행 목표는 기존 IK 보호를 따른다.
- 연결/팝업 열기/로봇 값 불러오기에서 최신 값을 읽는다. 다른 앱이 수정한 새 상태는 미편집 필드에 반영하며 작성 중인 초안은 유지한다.

## 저장 구조

기존 Sector 7(0x08060000..0x0807ffff), 128바이트 체크섬 저널에 전용 magic의 설정 레코드를 추가했다. 같은 값의 재저장은 쓰기를 생략한다. 부팅 후 최신 유효 레코드를 복원하며, 중단된 레코드는 건너뛴다. 로그 회전/삭제 또는 IMU 보정 저장 시 최신 설정을 prefix의 0x08060100 위치로 보존한다. IMU 보정은 첫 256바이트, 로그 시작은 기존 0x08060400을 유지한다. OTA 부트로더는 Sector 7을 지우지 않는다.

제약: 기존 단일 Sector 7 구조상 **섹터 전체 삭제 후 prefix 복원 중의 전원 차단은 이중 뱅크처럼 원자적으로 보호되지 않는다**. 정상 저장 완료 후 재부팅 및 개별 레코드 쓰기 중단과 구분해야 한다. 이 변경은 플래시 배치를 늘리거나 모터 구동 로직을 바꾸지 않는다.

시뮬레이터는 같은 save/show 의미를 사용하고, 실제 실행에서는 `simulation/mujoco/config/foot_lift.local.json`에 저장한다(버전 관리 제외). 파일 교체 실패 시 적용값을 바꾸지 않는다. 테스트는 임시 저장 경로를 사용한다.

## 검증 수준

- 호스트 C: 모든 32개 워드 경계에서 기록 실패 후 이전 값 복원, 재부팅, 동일값 쓰기 생략, 로그 삭제/회전, IMU 보정 저장 후 보존.
- 시뮬레이터: 컨트롤러 재생성 후 복원, 저장 오류 시 기존 값 유지, 구 앱 set 거부.
- 앱: 로컬 값 자동 업로드 금지, 새 저장 ACK + 새 readback 필요, 구 펌웨어 저장 금지, 다른 클라이언트가 바꾼 값 표시.
- Mac/iOS 공용 테스트 79개 통과. Windows 전체 117개 중 기존 116개 통과 후, 발견한 새 ACK/조회 판정 오류 수정. 수정된 설정·프로토콜 60개 및 레이아웃/설정 12개 통과. 펌웨어/센서/시뮬레이터 45개 통과. 기존 MuJoCo 수치 경고가 존재하며 해당 시험은 통과했다.
- STM32 빌드 327156바이트, 320KiB OTA 영역 내. Mac/iPhone V90-R2 빌드58 설치.
- 실기: STM32 V90-R1 제어 채널 응답 확인. 첫 조회에서 서보 12개 timeout, pose/torque unknown. Landing 이동·OTA 미실행, 서보 전원 확인 대기.

실제 위치 유지 시험·전체 보행 시험은 이 설정 변경 검증에서 수행하지 않는다. 실기 저장 readback과 재부팅 시험은 별도로 기록한다.

## 실기 진행 추가 기록

서보 전원이 켜져 있다는 사용자 확인 후 개별 ping 및 raw busprobe에서도 수신 0바이트였다. 이후 서보 통신이 복구되어 12개 응답, 11.8~12.1V, hw=0을 확인했다. Landing 시도는 첫 번째 기울기 보호, 두 번째 servo=1 bus=ok 오류로 완료되지 않았다. 이후 사용자 명시 지시 “펌웨어부터 설치해라”에 따라 Landing 재시도를 생략하고 기존 자세에서 Relax 후 `torque=off safety=ok`를 읽어 확인했다. 이 절차는 Landing 완료로 기록하지 않는다. 증거: artifacts/foot-lift-v90-r2/hardware-user-firmware-first/.

OTA는 100% 전송·STM32 검증·재부팅까지 성공했다. 재연결 조회에서 `rev=attitudepd-v4-v90-r2`, `footliftpersist`, `torque=off safety=ok fault_code=0`을 확인했다. 업데이트 직전의 FL/FR/RL/RR 값 `[0, 0, 0, 0]`을 `footlift save`로 저장해 `OK footlift saved`를 받았고, 별도 `syncstate` 조회에서도 네 값이 일치했다. `ota.json`과 `verify.json` 모두 success=true이다. 설치 후 자세는 여전히 `custom`이며 Landing 도착을 확인한 것은 아니다. 저장 후 실기 전원 재인가에 따른 보존 시험 및 위치 유지·보행 시험은 수행하지 않았다.

## 설치 후 iPhone 전진·설정 잠금 수정 (앱 빌드 59)

사용자가 Stand/Stand11은 되지만 전진이 안 된다고 보고했다. 재조회는 Stand, torque=on, safety=ok, fault_code=0, 보행 진단 no samples였다. iPhone `iphone-forward-trace`의 실제 기록에서 Stand 전송 1789990588371, 동작 중 syncstate 전송 1789990592570, Stand OK 수신 1789990596423을 확인했다. 동작 중 보낸 조회에는 응답이 없고 완료 후 새 조회에만 응답이 왔다. 앱은 응답 없는 조회를 대기 개수에 남겨 전진 및 발 높이 설정을 막았다. 이 세션에는 drive 및 footlift save 전송 자체가 없었다.

자동/수동 상태 동기화는 이전 명령의 최종 프롬프트를 받은 뒤 실행하도록 변경했다. 단순 OK 이후에도 기구 진단이 이어질 수 있어 최종 프롬프트까지 기다린다. 긴 Stand, OK 이후 지연 진단, 새 상태 수신을 재현해 전진 전송 및 발 높이 설정 가능 상태 복귀를 검증했다. Mac/iOS 공용 80개 테스트 통과. 물리적 전진 시험은 아직 수행하지 않았다. 네 값 0은 설치 직전 로봇값을 보존한 것이고, 기본 보행에 더하는 높이가 0이라는 의미다. 이전 앱 로컬 설정의 자동 이관은 하지 않았다.
