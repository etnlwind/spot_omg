# V48 전진 FR 끌림 진단

사용자 관찰은 **전진 중 FR**이다. 좌우 회전 시 앞발 8mm 들림 수치를 전진의 실측값처럼 적용하면 안 된다.

## 확인한 사실

- 직접 BLE 조회: V48, `profile=centerpivot`, Stand, torque on, safety ok.
- FR ID4/5/6 정지 조회: 각각 전압 10.8/10.7/10.8V, 온도 36/32/38°C, hw=0x00, moving=0. 이는 동작 중 토크/추종이 정상이라는 증거가 아니다.
- `jointtrace status`에는 이번 동작 기록이 없었다. 이후 `jointtrace arm` 성공. 준비 명령만 보냈으며 새 보행 명령을 보내지는 않았다.

## 추정 물리 모델의 전진 재실행

V48 공용 C `centerpivot`, full forward, 17초 실행, 15초 Stop:

| 다리 | 전체 시험 최대 여유 | 중간 스윙 접촉 비율 |
|---|---:|---:|
| FL | 26.9mm | 9.0% |
| FR | 21.7mm | 12.1% |
| RL | 29.4mm | 7.9% |
| RR | 28.0mm | 7.7% |

FR은 다른 발보다 낮지만 최대값만으로 매 스텝 들린다고 판단할 수 없다. 몸체 기울기 최대 4.73°, 속도 약 0.092m/s, 안전 정지는 없었다.

관절 추종과 몸체 자세를 분리하기 위해 평가용 MjData에 현재 몸체 자세를 유지한 채 명령 관절각만 대입했다. 제어기에는 이 정보를 공급하지 않는다. 중간 스윙에서 실제 여유가 1mm 미만인 FR 표본의 '완전 추종 시 같은 몸체 자세에서의 여유' 중앙값은 -3.53mm였다. 따라서 **이 모델에서는 단순히 모터를 더 빨리 따라오게 하는 것만으로 해당 접촉을 없앨 수 없다.** 발끝 목표와 몸체 자세 관계도 점검해야 한다. 이는 실물 원인 확정이 아니다. FL에도 유사한 문제가 나타났다.

원본: `artifacts/audits/fr-forward-2026-09-12/`의 `simulation.json`, `feet.json`, `tracking-counterfactual.json`. 재현 스크립트 `simulation/mujoco/scripts/analysis/audit_fr_forward.py`.

## 다음 실측

같은 정책에서 사용자가 전진을 약 5초 조작하고 Stop한 뒤 기록을 내려받아 FR-J2/J3의 목표와 실제 위치를 비교한다. 관절별 약 240ms 간격이므로 정밀 지연 확정에는 부족하다. 자료 확보 전에는 모터 속도·토크 제한·서보 부호 또는 FR만의 임의 각도 오프셋을 바꾸지 않는다.

후속 데스크톱 연결 화면에서 `pose=custom error=418 torque=off safety=fault fault_code=15`를 확인했다. 코드 15는 ROBOT_SAFETY_FAULT(스톨 감지에 따른 토크 차단)이다. 발생한 축·동작·시각은 아직 사건 로그로 확정하지 못했다. 이후 보호를 해제하거나 새 보행을 실행하지 않았다. 기록기는 준비했으나 새로운 실제 보행 기록 다운로드는 아직 미완료다.
