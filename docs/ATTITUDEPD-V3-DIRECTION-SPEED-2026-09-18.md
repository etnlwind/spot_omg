# V3 전진·후진 속도 차이 분석 — 2026-09-18

기준: `2450d3268ffe313cf4b80213eaeef234a40bd9fb`, `attitudepd_v3` / V79.
사용자는 실기 보행이 잘 되었고 후진이 전진보다 빠르게 보인다고 알렸다.
현재 실기 준비 전이므로 코드·이력·호스트·추정 물리 시뮬레이션만 조사했다.
배포 보행 파라미터, 펌웨어, 서보 설정은 변경하지 않았다.

## 확인된 원인과 아직 확정하지 못한 부분

**후진 발 교대가 더 빠르도록 설정되어 있다.** 전진은 기본 주기 1.35초,
후진은 회전과 공유하는 1.05초를 사용한다. 같은 최대 입력에서 후진의
주기당 빈도는 전진보다 28.57% 높다. 이 비대칭은 V3에서 새로 생기지 않았다.

그러나 **실물 몸체 이동 속도 차이까지 이 설정만으로 설명됐다고 확정하지 않는다.**
동일 입력을 준 이번 MuJoCo에서는 후진 발 교대는 빨랐지만 몸체 이동은 전진이
빨랐다. 실물 관찰을 부정하는 결과가 아니라, 현재 추정 물리 모델이 그 관찰을
재현하지 못한 것이다. 하드웨어 한계나 실제 전진 발 끌림을 원인으로 판정할
증거도 이번 조사에는 없다.

## 코드 경로

- `config/locomotion_profiles.json`의 V3 `params`와 `turn_reverse_params`가 다르다.
- `firmware/stm32-learning/Inc/locomotion.h::locomotion_params`는
  `smootherstep(clamp(linear / 0.5, 0, 1))`로 두 집합을 섞는다.
  **signed linear**이므로 모든 음수 입력은 `turn_reverse_params`를 선택한다.
  전진 입력이 0.5 이상이면 `params`를 사용하며, 0~0.5에서는 보간한다.
- `locomotion_period`는 선택된 기본 주기에
  `1.35 - 0.35 * min(1, abs(linear) + abs(yaw))`를 곱한다.
  이 배율 자체는 전후 대칭이지만, 선택한 기본 주기가 다르다.
- `drive_control.h`의 입력 상승 제한은 양쪽 모두 2000‰/s이며 위 주기로
  실제 위상을 진행한다. V3에는 예전 native 일부 모델의 후진 -600 제한이 없다.
- iOS `RobotDriveVector.make`와 Windows `drive_vector`의 직진 축은 ±입력이
  대칭이다. 앱에서 후진 입력만 증폭하는 경로는 확인되지 않았다.

최대 입력 ±1000, yaw=0, 정상 진폭 기준:

| 항목 | 전진 | 후진 |
|---|---:|---:|
| 같은 다리의 한 주기 | 1.35초 | 1.05초 |
| 대각선 쌍 교대 간격 | 0.675초 | 0.525초 |
| 지지 비율 | 0.52 | 0.52 |
| 평면 IK 보폭 파라미터 | 80mm | 70mm |
| 기본 들림 파라미터 | 24mm | 22mm |
| 평면 IK 다리 깊이 파라미터 | 220mm | 201.75mm |
| 전진 전용 앞발 추가 들림 | +4mm | 없음 |
| 기본 스윙 들림 형태 | 올림 40%·유지 30%·내림 30% | 둥근 아치 |

보폭/주기 비율로 계산한 후진/전진은 1.125이다. 지지 시간으로 나눈 평면
발 X 평균 속도도 113.96→128.21mm/s로 같은 비율이다. 이는 **명령 기하의
지표이며 실제 몸체 속도가 12.5% 빠르다는 측정값이 아니다.**
공유 C 목표를 CAD FK로 변환한 FL/RR 지지 구간 X 이동도 각각 약
83.69mm / 73.85mm다. 평면 IK 보폭을 실제 쿠션 이동과 동일시하지 않는다.
높이 파라미터도 실측 지상고와 구분한다.

## 비대칭이 생긴 경위

[9월12일 실측 비교 기반 실험](MEASURED-GAIT-EXPERIMENT-2026-09-12.md)은
전진 발 들림 개선에 1.35초·80mm·24mm를 사용하고, 회전에는
1.05초·70mm·22mm와 기존 아치를 사용했다고 기록한다.
`scripts/tuning/search_measured_turn.py`는 실제로 더 짧고 빠른 회전 후보를
`turn_reverse_params`에 넣어 탐색했다. 그 스크립트의 평가 방향은 좌회전,
상위 후보 검증은 전진·우회전이었다. 후진 속도 일치 검증은 그 경로에 없다.

이 설정은 `measured_lift` → `centerpivot` → `attitudepd`로 이어졌고,
`3cb33c0`의 centerpivot/attitudepd에도 이미 동일한 두 배열이 있다.
`bb53f72`의 V2, `2450d32`의 V3도 그대로 복사한다.
[V3 변경](ATTITUDEPD-V3-GAIT-STAND-2026-09-18.md)은 Stand(B) 통일이며,
정상 진폭의 V2/V3 목표와 주기는 보존했다. 따라서 이번 비대칭은
V3의 Stand 변경에 따른 신규 오류가 아니라 **회전·후진 설정 공유와 이전
방향별 튜닝의 상속**이다. 후진을 빠르게 하려는 별도 요구가 있었다고
추정하지 않는다.

## 이번 Windows 시뮬레이션

각 조건을 독립 초기화하고 Stand 준비 7초 → 보행 12초 → Stop 및 B 복귀로
실행했다. PD OFF, heading OFF는 문서화된 V2 실기 시험과 동일하다.
추정 질량·접촉·모터 모델은 기존 값, 물리 적분 0.5ms, 제어 20ms다.
출발 후 처음 2초를 제외한 +2.00~+11.98초의 root world X를 시간에 선형
회귀했다. 초기 전방은 world +X다. 여기서 50%는 조이스틱 물리 위치가
아니라 펌웨어에 전달한 입력 ±500이다.

| 입력 크기 | 전진 몸체 속도 | 후진 몸체 속도 | 전진 주기 | 후진 주기 |
|---|---:|---:|---:|---:|
| 100% | 0.1430m/s | 0.0892m/s | 1.3500초 | 1.0500초 |
| 50% | 0.0497m/s | 0.0366m/s | 1.5863초 | 1.2338초 |

네 경우 모두 보호 정지 없이 Stand(B)로 종료, 최종 B 목표 오차 0°였다.
위상 진행으로 측정한 주기는 공유 C 주기와 일치했다. tracking 감속은 OFF.
정상 구간의 최대 절대 yaw는 3.24° 미만, 횡속도는 2.43mm/s 미만으로
단순한 회전 때문에 전후 측정이 뒤집힌 것은 아니다.

접촉 진단도 추가했다. 최대 입력에서 계획한 스윙 중간 60% 동안 앞발이
0.5N보다 큰 하중을 받는 비율은 전진 약 52%, 후진 약 98~99%였다.
발-바닥 접촉점의 수평 속도를 접촉 하중으로 가중한 평균은
전진 약 0.0498m/s, 후진 약 0.0725m/s다. 이는 **추정 모델 안의**
접지/미끄러짐 증거이며, 실물이 같은 비율로 발을 끈다는 증거가 아니다.
각 원인의 몸체 속도 기여율을 분리한 실험도 아니므로 이 값만으로
속도 차이 전체를 인과적으로 설명하지 않는다.

실물 비교를 마무리할 때는 같은 바닥·같은 입력·같은 측정 시간의 전후진
영상에서 고정된 지면 기준 이동거리를 측정하고, 실제 송신 입력·위상·목표와
실측 관절값을 함께 기록해야 한다. 발 교대 속도와 몸체 이동 속도를 따로
비교한다. 지금 확인한 소프트웨어 비대칭을 개선할 경우에도 정상 보행 V3를
보존하고, 후진/회전 설정 분리와 방향별 속도 기준 통일을 별도 후보로 검증한다.
