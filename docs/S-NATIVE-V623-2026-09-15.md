# V6.2.3: 빠른 움직임과 더 큰 뒤쪽 범위

## 요청과 구현

사용자 기준은 0.5초 왕복 주기 자체가 아니라 **빠르게 움직이면서 이전보다 실제 다리를 더 뒤로 뻗는 것**이다. 이번 구현은 그 목적의 독립 실험 모델이며, 실제 도달각과 실제 속도가 확인되기 전에는 달성했다고 하지 않는다.

- `s_native_v6_2_3`을 새 인덱스19로 추가. V6.2.2 인덱스18과 과거 모델은 보존.
- 앞 +20mm 유지, 뒤 −125 → −135mm. 전체 전후 목표 폭 145 → 155mm.
- 회수 높이 12mm를 유지하면서 swing의 처음/끝 35%에 quintic smootherstep을 적용. 경계의 높이·속도·가속도가 연속이므로 기존 sin^0.25 높이 곡선의 급격한 끝점 요구를 제거한다.
- 기본 주기 1초. 시험한 0.56/0.6/0.8/1.0/1.2초 중 몸체 고정 추정 모델에서 J2의 과도한 왕복이 줄어드는 1초를 채택했다. 실제 기체 속도를 측정해 맞췄다는 뜻은 아니다. 서보 속도3400/가속254 설정 및 기존 보호 기준은 변경하지 않았다.
- S 출발, FR/RL 동기·반대 대각선 반주기, FR 첫 걸음 J1 2배, Stop 두 걸음 1.6초 보존.
- 새 궤적의 지지 표를 별도 생성. 기존 지지 표 보존, 기준 역학 주기2초 유지. 고속 바닥 균형을 최적화한 표로 해석하지 않는다.
- 앱 목록 맨 위·지원 연결 기본, 시뮬레이터 기본을 갱신. 이전 capability 장치는 해당 모델로 전환하지 않는다.
- 펌웨어 `s-native-v6-2-3-v65`. 영점, 서보 방향, J2 누적 목표 좌표 유지.

## 검증 수준

### 호스트·빌드

- V6.2.3/기존 V6.2.2·V6.2.1/Windows 프로토콜 회귀79개. 전진·후진·회전·복합 입력, 출발 중 Stop, 정상 Stop, 과거 인덱스, 5ms 밀집 목표 속도·서보 인코딩 검사 포함.
- J3가 목표보다 14° 덜 접힌 실제 관측 범위를 모델에 주입하여 발 높이 여유가 줄어드는 현상을 재현한다. 정확한 지연/토크 모델을 식별한 시험은 아니다.
- C/Python 변환 오차 기준0.15° 이내. 기존 모델 기준은 유지. Python의 1보다 조금 작은 위상이 float32에서 1로 반올림되는 검증 경계 문제를 펌웨어와 동일하게 wrap하여 수정했다.
- 안전·Stow 좌표·Stow 경로·자세 감독·명령 복구 C 검사5개 통과.
- iOS 시뮬레이터 대상 앱 빌드 성공. 실기 앱 설치는 하지 않았다.
- STM32 빌드 결과는 `artifacts/s-native-v6-2-3/firmware-build.log`에 보존. 320KiB 슬롯 안에 들어가는지 빌드가 검사한다.
- 기존 NumPy/MuJoCo matmul 경고는 로그에 보존. 실패를 숨기기 위해 경고나 물리 충돌을 끄지 않았다.

### 물리 시뮬레이션

몸체를 0.3m 높여 고정한 모델: 내부 충돌0, 보호 중단 없음, Stop 이후 S 최종 오차 약0.22°. 정상 구간 J2 관측 폭은 약27.6~29.2°였지만 전체 관절 순간 추종 오차 최대43.6°가 남는다. **정확한 추종 통과가 아니다.**

바닥 모델: 보행 출발 후2.08초에 기울기 보호 중단. **바닥 전체 보행 실패.** 보호 중단 이후 값을 정상 속도/보폭으로 평가하지 않는다. 기구 간섭을 숨기려고 충돌을 끄지 않았다.

### 실제 기체

V6.2.3 설치, 설정 readback, 독립 위치 유지, 전체 동작 시험은 아직 하지 않았다. 마지막 확인된 기체는 V6.2.2/v64, 토크OFF다. 실제 움직임 속도 유지와 뒤쪽 도달각 향상은 미검증이다.
