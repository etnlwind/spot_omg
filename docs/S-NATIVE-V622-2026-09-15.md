# V6.2.2 고속 동작 실험

사용자 요청: V6.2.1과 같은 동작을 더 빠르게 하고 V6.2.2로 보존하여, 몸체 고정 상태에서 1분간 시험.

## 변경

- 모델 `s_native_v6_2_2`, 기본 주기 0.5초(전진100%). V6.2.1의 2초 대비 명목4배.
- 기존 모든 모델/프로필 인덱스 보존, 새 인덱스18. V6.1=16, V6.2.1=17 유지.
- 각 위상의 X/Y/Z 형상, 앞+20mm/뒤−125mm, 12mm 회수 높이, 첫 FR 추가 오므림, J1/J2/J3 변환 보존.
- V6.2.1 지지 표를 그대로 공유한다. Python의 `support_reference_period_s=2`는 기존 위상별 목표와 일치시키기 위한 값이며, 고속 바닥 보행의 지지 역학을 최적화했다는 뜻이 아니다.
- 두 걸음 Stop은 기존1.6초 유지. 정지의 안정성을 명목 보행 속도에 맞춰 무조건 가속하지 않는다.
- 앱 목록 맨 위/지원 연결 기본, 시뮬레이터 기본 갱신. 구형 실기 capability에서는 기존 지원 모델 선택.
- 펌웨어 `s-native-v6-2-2-v64`. 모터 영점/방향/한계 및 센서·기울기·워치독·서보 보호 유지.

## 선택과 검증

0.4–2초 후보의 전진100% 초기8초, 20ms 간격 C 목표를 비교했다. 0.4초는 최고3518.8틱/초, 0.5초는2950.6틱/초의 목표 변화율이었다. 저장소 motor_capability.h의 명목 무부하 한계(STS3215 270°/s, STS3250 451°/s)와 비교했다. 0.4초의 J3 최대309.27°/s는 넘고, 0.5초의 최대259.33°/s는 한도 안이므로 비교 후보 중0.5초를 선택했다. 속도 레지스터3400 자체를 실제 각속도로 동일시하지 않는다. 전원/부하/가속도에 따른 실제 최고 속도를 측정한 값은 아니다.

V6.2.2의 C/Python 목표 비교는 직진·후진·회전·복합 입력과 출발 중/일반 Stop을 포함한다. 복합 입력에서 압축 지지 표·IK 차이의 최대 관절 오차 약0.0913°를 관측했다. 신규 기준0.12°는 서보2틱 미만이다. 기존 V6.2.1의0.06° 기준은 유지했다.

신규/Windows 검사45개 통과 후, 실기에서 관측한 J3 14° 덜 접힘을 기하학 모델에 주입하는 회귀도 추가·통과했다. 이 민감도 시험에서는 명목12mm 회수 여유가 소진되며, 실제 지연 모델을 식별했다는 뜻은 아니다. 이전 묶음의 기존 V6.2.1 관련19개도 통과했다. 안전/Stow좌표/Stow경로/자세감독/명령복구 C 검사5개 통과. 기존 NumPy/MuJoCo 경고는 결과 로그에 남겼다.

## 바닥 보행 한계

보호를 유지한 4초 바닥 시뮬레이션에서 출발+0.76초에 tilt fault가 발생했다. 이후 수치는 이미 실패한 동작의 기록이며 정상 보행 성능으로 해석하지 않는다. **이 버전은 바닥 안정 보행 통과 모델이 아니다.** 현재 요청된 실제 시험은 몸체 고정·발 비접지 조건이다.

실기 설치/짧은 구동/1분 결과는 `artifacts/s-native-v6-2-2/`에 별도 보존한다. 설정 조회, 관절 추종, 몸체 지지 시험, 바닥 전체 보행을 구분한다.

## 몸체 고정 시뮬레이션

몸체를0.3m 높인 위치에 weld로 고정하고 충돌과 서보 모델을 유지했다. 전진100% 4초 후 Stop에서 내부 충돌0, 보호 중단 없음, 최종S 오차0.22°였다. 그러나 순간 목표/실측 오차는 최대52.4°로 컸다. 이것을 고속 추종 통과로 보지 않는다. 정해진 명령 주기와 실제 동작 속도/진폭은 구분한다. 실기 지지 시험의 전압·온도·오차 결과도 별도로 확인한다.
