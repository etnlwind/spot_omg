# V7 조종 정책 / V93 (67)

2026-09-22. 소스 구현, STM32·Windows 빌드 및 호스트·MuJoCo 검증 기록.
**실기 V93 및 Windows V93(67) 설치 완료. 실제 하중 보행은 아직 하지 않았다.** Apple 소스와
시험은 갱신했지만 이 Windows 컴퓨터에서 Xcode 빌드·설치는 하지 않았다.

## 동작과 호환성

기존 V6와 이전 모델을 보존하고 `attitudepd_v7`을 프로필 마지막 인덱스에
추가했다. 펌웨어·시뮬레이터 기본값 및 지원하는 앱의 목록 첫 번째이다.
V7 capability가 없는 기체에서는 기존 최신 지원 모델로 선택한다.
통신은 기존 전용 제어 채널의 `drive` / `@D` / `@S`를 사용한다.

| 조이스틱 입력 | V7 동작 |
| --- | --- |
| 정전진 | 전진, IMU 방향 보정 |
| 정후진 | V6의 같은 입력 궤적을 유지하고 주기 2배(보행 주파수 50%) |
| 정좌 / 정우 | 바라보는 방향을 유지하는 4박자 옆걸음 |
| 앞 대각선 | 전진하며 해당 방향 회전 |
| 뒤 대각선 | 후진 성분 없이 몸체 중심 기준 제자리 회전 |

앱의 기존 ±20° 축 입력 영역은 유지한다. 속도 표시와 별도로 옆걸음,
제자리 회전, 후진 50%를 표시한다. V7의 좌우 입력은 회전 제한을 적용하기
전에 해석한다. 시뮬레이터의 기존 `limited_yaw`가 옆걸음 입력까지 0.5로
잘라내던 경로도 V7에 한해 제거해 펌웨어와 일치시켰다.

## 직진 보정

IMU yaw는 반시계 양수, 회전 명령은 시계 양수이다. 직진 진입에서 0.2초간
관측을 평균내 방향을 잡고, 기존 저역 필터·PI·출력 변화율 제한을 사용한다.
V7에서는 전진과 후진 모두 활성화하며 사용자의 회전 입력·정지·관측 무효
시 보정을 해제한다. 전후 방향 전환 시에도 기준을 다시 잡는다.

기존 yaw 경로에 보정값을 합산하지 않는다. 보정 전 궤적을 생성한 뒤
CAD 쿠션 좌표에서 좌우 X 보폭만 최대 ±20% 조정한다. Y/Z와 접지 예정
위상, 주기는 유지한다. 후진에서 부호가 자동으로 반대가 되도록 **부호 있는
전후 입력**에 대한 보폭 비율을 계산한다. 명령 각도와 실제 모터 위치가
같다고 가정하지 않으며, 목표 궤적 검증과 실제 추종은 구분한다.

## 옆걸음·회전·정지

옆걸음과 제자리 회전은 네 발을 순서대로 옮기는 4박자, 접지율 0.8이다.
옆걸음 주기 4.4초, 전체 좌우 보폭 최대24mm, 회전 주기3.4초로 검증했다.
접지 중인 발은 같은 직선 속도를 갖는다. 왼쪽 옆걸음은 발 순서를 좌우
반전하고, 추가 들림과 자세 보정의 접지 가중치도 같은 순서를 사용한다.

동작 종류를 바꿀 때 기존 움직임을 감속해 Stand 기준에 맞춘 후 새 종류를
시작한다. 일반 정지는 최대 입력부터 2초 감속 후 기존1초 Stand 복귀를
사용한다. 통신·IMU 업데이트는 계속50Hz이며 외부 중단 경로는 이 감속을
기다리지 않는다. 기울기·통신 watchdog 등의 보호를 제거하지 않았다.

V7 내부 좌표는 CAD이며 앞 J1 부호는 서보 인코딩 경계에서 한 번만 바꾼다.
Stand·보행·idle과 시뮬레이터 모두 이 경계를 사용한다. 기존 모델 좌표를
일괄 변경하지 않았다. 발 간격도 V7에서는 CAD에서 적용한다.

## 검증과 발견 후 수정

- 실제 펌웨어 C 커널을 호출하는8방향·전환·정지·후진 주기·IMU 무효 시험.
- MuJoCo CAD FK로 보정 전후 발 Y/Z 유지, 좌우 보폭 방향을 독립 확인.
- O0 실행 파일과 호스트 라이브러리의 서보 틱 비교에 V7 상태와 전용
  인코더 포함. 이전 모델 프로필 인덱스와 V6 회귀를 유지했다.
- 정지2초 → 명령8초 → 정지4초의 동역학 시험. 로봇에 저장돼 있던
  들림20/20/20/20mm, 간격−30/−30/+30/+30mm도 별도로 시험했다.
- 외부 yaw 토크0.02Nm 비교(명령2초 이후6초): 방향 오차 RMS 전진
  1.057°→0.750°, 후진0.913°→0.667°. IMU 추정과 제한된 물리 모델 결과이다.
- 초기 V6 회전 재사용은 앞으로 약0.4m 흐르므로 폐기했다. CAD 중심
  회전으로 변경했다. 빠른 옆걸음은 큰 발 보정에서 전방 흐름/보호가 있어
  접지 속도·순서·주기·보폭을 수정했다.
- 최대 전진 후 정지 보호는0.5초 및1초 감속으로 해결되지 않았으나2초
  감속에서는 완료했다. 전도 한계나 보호 임계값을 높이지 않았다.
- 호스트 시험 일부는 Windows Zig에서 assert가 비활성화돼 계산 호출이
  사라지는 문제가 있었다. V6 시험에 `-UNDEBUG`를 명시하고 독립 PD 시험은
  기존 공용 Windows 컴파일러 경로를 사용하도록 수정했다.

최종 증거는 `artifacts/navigation-v7/`에 있다. `simulation.json`은8방향,
`heading-disturbance.json`은방향 보정 비교, `full-input-final.json`은 최종
최대 입력 및 저장 발 설정 시험이다. `planar-*`, 초기 `stored-foot-settings.json`,
`side-final.json`, `forward-stop-final.json` 등은 중간 후보 기록이므로 최종
성공 증거와 혼동하지 않는다. 최종 요약은 `verification-summary.json` 참조.

## 빌드와 남은 검증

- 최종 선택 회귀 402개 통과, 기존 진단 내보내기 시험1개 실패.
- 펌웨어: `artifacts/navigation-v7/firmware/attitudepd-v7-v93.bin`.
  327284바이트, 슬롯 잔여396바이트. SHA256
  `7439d991a835e21e000fa116ec61c34d598e31a3730a65224e40e28288e031f7`.
  기존320KiB 슬롯 크기는 유지했다. 새 제어 코드, 발 보정 및 PD 어댑터에
  크기 최적화와 부동소수점 연산 결합 금지를 적용해 슬롯 안에 넣었다.
- Windows: `apps/windows/dist/v93-build67/SpotOMGController/SpotOMGController.exe`.
  `%LOCALAPPDATA%/Programs/SpotOMG/V93-67/`에 설치·실행했고 바탕화면 바로가기를
  갱신했다. 설치본229개 파일의 SHA256이 빌드 결과와 일치한다.
- Apple: 93.0.0/build67 소스. 실제 Xcode 시험·설치 대기.
- 실기 설정 readback과 Landing 도착은 아래 설치 기록에서 확인했다.
  외력에 대한 위치 유지, 전체 보행, MCU의 실제50Hz 처리 시간은 아직 미검증이다.
  실제 후진 이동속도가 정확히50%인지는 별도 실측 대상이다.
- 옆걸음/제자리 회전의 동역학 위치 흐름이 완전히0은 아니다. 특히 큰
  발 간격 보정에서 회전 중심이 수cm 움직이는 한계가 남는다.
- 전체 Windows 회귀 중 기존 `test_stop_ready_without_waiting_for_logs_and_old_reply_cannot_complete_new_command`의
  진단 내보내기 `control-tx @D` 검증 실패가 남는다. 실제 테스트 내부의
  heartbeat 전송 수·로그 폭주 중 제어·정지 완료 검사는 통과하며,
  이 실패는 이번 변경 전에도 재현된 기록이다. 전체 통과라고 보고하지 않는다.

## 실기 설치 기록

사용자의 로봇·앱 설치 요청 후 `artifacts/navigation-v7/install-01/`에 증거를
남겼다. 기존 V92-R2 Landing을 새로 확인하고 Landing 명령 완료24틱 →
12축 토크OFF → OTA 검증·재부팅 → `attitudepd-v7-v93` / `attitudepd_v7` →
Landing 완료23틱을 확인했다. 모든 서보의 영구 레지스터0..39는 설치 전후
같았고 저장된 들림20/20/20/20mm, 간격-30/-30/+30/+30mm도 그대로다.

`verify_attitudepd_v6_install.py --revision attitudepd-v7-v93`의 마지막 상태
조회에서 ID12 온도가150°C로 한 번 읽혀 자동 검증은 실패했다. 직전45°C였고,
이후 동작 없이 별도 연결로 세 번 조회한 값은45/46/45°C였다. 나머지 모터는
34~52°C, 전체12축 정지·hw오류0·전압11.2~11.4V를 확인했다. 기존V92-R2의
설치 준비 Landing에서도 ID6 온도105°C 단발값이 기록됐다. 순간 이상값의
원인은 확정하지 않았으며 실제 지속 과열로도, 단순 소프트웨어 오류로도 단정하지 않는다.

원래 실패 기록 `post-verify.json`을 덮어쓰지 않았다. `recheck-01..03/inspect.json`
및 `completion.json`이 후속 확인 증거다. 최종 readback은 Landing/오차22틱/
토크ON/safetyOK, V7, IMU 직진보정ON이었다. 이는 설치·설정·정지 상태 조회의
검증이며 실제 보행, 외력 위치 유지, 센서 정확도 검증과 구분한다.

Windows 앱에서도 BLE 연결과 전용 제어 채널을 확인했다. 화면에
V93(67), 펌웨어V93, 적용모델V7, Landing, safetyOK를 표시한다.
`install-01/windows-ui-readback.txt` 및 `windows-install.json`에 기록했다.
설치 검증 중 보행·Stand 명령은 보내지 않았다.
