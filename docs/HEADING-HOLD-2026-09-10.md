# IMU 직진 방향 유지와 앱 토글

가상 로봇 `heading-v6-sim`, 앱 V0.3.5 (11).

앱의 **직진 보정 → IMU 직진 방향 유지**를 켜면 전진 조이스틱의 회전 입력이 0인 동안 상대 방향을 유지한다. 기본 ON이다. OFF이면 사용자 입력만 전달하던 기존 방식으로 동작한다. 연결 대상이 `headinghold` capability를 제공할 때만 토글을 표시한다. 실제 제어기의 상태 응답을 화면에 반영하며, 보행 중 설정을 변경하면 정지 완료 후 전송한다. 설정은 가상 제어기 실행 중 유지하고 재시작하면 ON으로 초기화한다.

- 전진 입력 > 0.15, 회전 입력 0, 기존 회전 출력이 가라앉은 상태가 200ms 유지되면 현재 IMU yaw를 기준으로 저장한다.
- ±180° 최단 방향 오차에 저역 필터와 제한된 PI 보정을 적용한다. 시계 반대 방향 yaw 오차는 오른쪽 회전 명령으로 보정한다.
- 보정 한도 ±0.25, 출력 변화율 초당 0.5, 0.3° 오차 허용 구간을 사용한다. 적분 포화를 제한한다.
- 사용자가 회전하면 자동 보정 기준을 즉시 해제한다. 정지·후진·센서 누락/오래된 측정·안전 정지·OFF도 기준과 적분을 초기화한다. 다시 직진하면 새 방향을 잡는다.
- BNO055의 지연·양자화·노이즈가 포함된 `yaw_tenths`만 제어기에 입력한다. MuJoCo 실제 방향은 검증 지표에만 사용한다.

공유 C 계산은 `firmware/stm32-learning/Inc/heading_control.h`, 호스트 연결은 `gait_policy_host.c`, 가상 제어기 연결은 `heading_controller.py`에 있다. 이번 배포는 가상 로봇과 앱에 적용한다. 실제 STM32의 BNO055 콜백은 아직 yaw를 방향 유지 루프에 전달하지 않으므로, 실제 로봇에서 이 기능이 작동한다고 표시하지 않는다. 실제 로봇 설치/구동은 하지 않았다.

## 동역학 A/B 검증

같은 CAD 물성·중력·모터·배터리·BNO055 설정에서 30초간 전진하며 ±0.1Nm의 일정한 yaw 외력을 가했다. 명령은 `drive`/`@D`/`@S` 경로로 전달했다. 관측된 방향 변화의 크기는 다음과 같다.

| 정책 | OFF | ON |
|---|---:|---:|
| 크루즈 | 약 7.9° | 약 0.4–0.8° |
| 트롯 | 약 12° | 약 0.9–2.0° |

8개 A/B 사례에서 안전 상태 정상, 발 이외의 접촉 없음, 정지 완료를 확인했다. 상세 결과는 `simulation/mujoco/heading_hold_validation.json`, 재현은 `validate_heading_hold.py`이다. 더 작은 ±0.02Nm 외력 결과도 `diagnostics/heading-small-disturbance.json`에 보존했다. 작은 외력에서는 보행 주기 진동이 오차에서 차지하는 비중이 커서 RMS 개선은 약 25–47%였다.

방향 유지는 위치 경로 추종과 다르다. 옆으로 미끄러진 위치까지 원래 선으로 복귀시키지는 않는다. IMUPLUS의 상대 yaw 드리프트도 남으므로 장시간 절대 방향 유지나 실제 기구 편차 보상을 보장하는 결과는 아니다.

자동 검증: 전체 Python 테스트 265개와 subtest 26개, 앱 XCTest 44개 모두 통과했다. 추가 8개 회전→직진 전환 동역학 시나리오도 통과했다(`heading_transition_validation.json`). Mac 대상 Debug 빌드 성공.

Mac 앱 V0.3.5 (11) 실행 및 가상 TCP 연결 완료. 실제 UI의 스위치 OFF → 상태 응답 `heading=off`, ON → `heading=on` 왕복을 확인하고 ON으로 남겼다.
