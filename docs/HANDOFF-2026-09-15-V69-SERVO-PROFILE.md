# V69: 실측 관절별 속도·가속도 적용

V67 handoff를 대체한다. 사용자는 최신 메시지에서 “30초간 해봐”라고 요청했다.
몸체 고정 시험 맥락이며 실제 바닥 보행 성공을 주장하지 않는다.

## 핵심 원인과 수정

1. Stand가 실제 레지스터를 300/30으로 낮췄는데 보행은 위치만 갱신했다.
   `profile`의 3400/254는 소프트웨어 요청값이어서 이 문제를 숨겼다.
2. V67과 V68은 속도 복구 후 모두 가속도 254를 검증해 보행 전에 중단됐다.
   V68 후 실측은 **속도 전부 3400, J1/J3 가속도 50, J2 가속도 254**였다.
   분리 쓰기만의 문제라는 가설은 V68 전체 블록 쓰기에서도 실패했으므로
   입증되지 않았다. EEPROM의 최대 가속도 레지스터를 확인한 것은 아니다.
3. V69는 설치된 기체에서 확인한 값을 `robot_servo_profile_acceleration()`에
   반영한다. 요청 가속도가 50보다 클 때 J1/J3에 50을 명시적으로 기록하며,
   J2에는 요청값을 기록한다. 읽힌 값이 이 적용값과 일치해야 출발한다.
   다른 STS3215 제품 전체의 보편적 최대값이라고 일반화하지 않는다.
4. 목표/시간의 원시 바이트를 보존한 41..47 블록 쓰기를 사용한다.
   누적 위치를 PRESENT_POSITION에서 재구성하지 않는다. 위치 원점·방향·토크
   제한과 추종/기울기 보호 조건은 이 수정으로 변경하지 않았다.
5. Simulator도 기본 적용 가속도를 `[50,254,50] × 4`로 제한한다.
   이전 가정과 비교하는 재생 도구는 명시적으로 cap=254를 사용한다.

## 출발 준비의 의미

보행 궤적에는 별도 준비 단계가 없지만 `drive` 내부의 감독된 S 진입은 남아 있다.
시험 스크립트가 그 전에 보냈던 중복 `stand`는 제거했다.
`$SPOTDRIVE started`는 내부 S 진입 전에 출력되므로 호스트의 30초 입력 시간은
실제 보행만의 30초가 아니다. 실기 기록을 읽을 때 구분한다.

## 마지막 급하게 내려가는 동작에 대한 사용자 질문

사용자: “마지막에 다리 내릴떄 엄청 빨랐는데? 그건 왜이렇게 빨라?”
정지 복귀와 토크 해제 중 어느 시점인지 질문했다. 로그:

- host 33.002s: 첫 `@S`.
- host 35.706s: 정상 정지 응답.
- host 37.117s: `relax` 전송(정지 응답 약 1.411초 뒤).
- host 37.595s: torque=off, pose=stand error=6.
- host 68.585s: torque=off, pose=custom error=381.

`relax` 직후 툭 내려간 경우는 모터 구동 속도가 아니라 토크 해제로 인한
중력 낙하와 일치한다. 정지 복귀 중이라면 `gait_tracking_step(stopping)`이
rate=1을 반환하고 S-native stop은 실시간 1.6초 궤적을 쓰는 것도 원인 후보다.
어느 구간을 사용자가 지칭했는지 확정하기 전 단일 원인으로 단정하지 않는다.
현재 토크는 꺼진 상태다. 추가 실기 동작은 이 조회 후 실행하지 않았다.

### 사용자 후속 확인: 빠르게 보인 것은 S 복귀

사용자는 “S자로 복귀활때 속도가 너무 인상적인데?”라고 구간을 특정했다.
따라서 이 관찰을 토크 해제 후 중력 낙하로 설명하지 않는다.
S 복귀와 보행은 동일한 서보 속도/가속도 설정을 사용한다. 차이는 상위
목표 궤적과 시간 진행이다. 보행은 추종 오차에 따라 위상 진행을 늦추지만,
정지 복귀는 1.6초의 고정 궤적을 사용한다. 대각선 한 쌍당 0.8초 중
수평 복귀 명령은 0.16초, 하강 명령은 0.20초에 집중된다.
이 수치는 코드의 목표 시간이며 실제 관절 최고 속도 측정값이 아니다.
최초 5초 joint trace에는 마지막 S 복귀가 없어 두 구간의 실측 속도 비율은
현재 자료만으로 구할 수 없다. 해당 복귀 동작에서 빠른 움직임이 관찰됐으므로
보행의 느림을 모터 능력만으로 설명하면 안 된다. 연속 보행의 궤적·하중·
접지 조건에서 같은 속도가 가능한지는 별도 검증 사항이다.
