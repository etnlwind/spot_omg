# 새 명령으로 보행 오류 재시도 (V25)

## 확인된 문제

실제 로봇 V24에서 어댑터 전원 케이블 재연결 후 Landing/Stand는 동작했지만 전진이 차단됐다. 조회 결과 `pose=stand error=17 torque=on safety=fault`, `locomotiondiag fault=1`, 서보 안전 모니터는 `Safety: ok`였다. 최초 보행 오류의 원인은 V24 상태만으로 확정할 수 없다.

## 변경

- 보행/대기 제어 오류 발생 시 이전 속도 목표와 대기 자세 제어를 취소한다. 연속 보행 오류 후 Stand 목표를 추가 전송하지 않는다.
- 새 자세/보행 명령은 과거 보행 오류와 서보 안전 오류가 있으면 12개 서보 상태를 읽어 재확인한다. 통신 실패, 하드웨어 오류, 과열, 잘못된 위치값이면 명령을 거부하고 정지 상태를 유지한다.
- 검사 통과 시 이전 오류와 제어기 상태만 초기화한다. 검사 자체는 토크나 위치를 쓰지 않는다. 이후 새 명령의 기존 검증과 동작을 수행한다.
- 기울어진 상태에서도 새 자세 명령을 시도할 수 있다. 보행에는 기존 IMU/기울기/부하 감시가 유지되므로 조건이 나쁘면 다시 중단될 수 있다. 물리적 장애물 제거 여부는 정지 상태의 센서값만으로 보장할 수 없다.
- 자동 복귀는 없다. 기존 `@D` heartbeat는 오류를 해제하지 못하며, 오류 중에는 속도 갱신도 받지 않는다. 새 foreground 명령만 재시도한다.
- 앱은 `commandretry` capability가 있는 펌웨어에서 Recover 강제 잠금을 사용하지 않는다. 중단된 조이스틱은 놓았다가 다시 조작해야 한다. V24에는 기존 잠금 유지.
- `syncstate`에 `recovery=new-command`, `fault_code`를 제공하며 `safety` 조회에 보행 오류 이유를 추가한다.

## 검증 및 배포

호스트 C 테스트: 26개 통과. 재시도 성공, 통신 장애 지속/복구, 과열/하드웨어 오류/잘못된 위치 거부, 실행 중 재시도 거부, 이전 목표 초기화를 검증했다. 검사 코드는 모터 쓰기 함수 없이 링크해 실행했다.

ARM 펌웨어와 iOS Debug 앱 빌드가 모두 성공했다. 실제 로봇 설치는 몸체 지지 및 BLE 해제 준비 확인 후 진행한다. 이 문서 작성 시 실제 설치/실기 보행 시험은 미수행이다.

### 실제 설치 완료

사용자 요청에 따라 먼저 Landing으로 전환했다(`error=5`). BLE OTA로 V25 159864바이트 이미지(SHA256 `fb052b38623159c154f0896b0220ea71a272ee65851b09a38440ae82914d32d7`)를 설치했고 검증 및 재부팅이 완료됐다. 재조회에서 `pose=landing error=57 torque=off safety=ok rev=shared-locomotion-v25 caps=...,commandretry,... recovery=new-command fault_code=0`를 확인했다. 실제 아이폰 UJIN17에도 Debug 앱 설치 완료. 재부팅으로 초기화된 보행 정책은 `jointsport`로 복원했다. 실기 전진이나 의도적인 오류 유발 시험은 하지 않았다.
