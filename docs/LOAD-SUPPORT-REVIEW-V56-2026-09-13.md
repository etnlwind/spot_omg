## 발견하고 수정한 문제

1. 전진 진입이 drive_active를 설정한 뒤 내부 Stand를 호출하나 자세 감독기가 이를 외부 중복 명령으로 거절했다. 내부 준비 구간 플래그만 허용하고 외부 중복 자세는 계속 거절한다. 준비 중 Stop도 중단시킨다.
2. 정상 하중에서 목표 근처 잔여 오차를 정체로 취급했다. 진행 방향의 실측 진전은 계속 인정한다. 마지막 단계에서 120틱 이내이고 1.2초 동안 위치 범위8틱 이내, IMU roll/pitch 변동 각각1도 이내, 전압/온도/전류 정상일 때 load-supported로 구분한다. 24틱 정밀 완료 및 기존40틱 잔여 완료와 별도 상태다.
3. Stand 후 수평 유지 루프는 기존 safety_update 경로를 통해 전체 토크를 해제할 수 있었다. 해당 idle 경로를 지지 감시로 교체했다. 이상 시 보정 명령 갱신을 멈추고 마지막 지지 목표/토크 상태를 보존한다. 통신 손실 시 실제 정지를 보장하는 것은 아니다.
4. 고정 목표에서 오차와 위치가 1.2초 창 동안12틱 이상 악화하면 처짐, 120틱 초과 오차도 범위 이탈로 구분한다. 고부하만으로 스톨이라 판단하지 않는다. 전류>=700raw, 전압<10.5V, 온도>=70C/하드웨어 오류는 별도 감시한다. 이상 전압/온도/상태는 다시 읽고 확인한다.
5. 데이터 누락500ms 이후에는 관찰 창을 재시작한다. IMU는 창 전체 최대/최소로 변동을 검사한다. 목표 근처라는 이유로 중간 이동 정체가 무한 대기하지 않도록 했고, 최종 단계에서3개 창 연속 불안정하면 진단 중단한다.
6. 유지 감시 오류를 두 콘솔에 ERROR 줄로 알리고 support 상태를 syncstate에 포함한다. 이미 설치된 앱의 빨간 오류 표시로 확인할 수 있다.

실제 펌웨어 함수를 호스트에서 구동: 느린 진전, 정체/고부하, 통신 손실/재시도, 쓰기 실패, 저전압, 과열/단발 이상값, IMU 손실/기울기, Stop, 잘못된 위치, 느린 버스, 잔여 오차, 조기 도착 축, 출발 출력 필요,67틱 안정 지지, 전진 준비 진입/Stop, 외부 중복 거절, 목표 근처 고부하 정체.
순수 지지 창: 고부하 안정 지지, 점진적 처짐, 과전류, 저전압, 과열, 목표 변경, 오래된 샘플.

## 남은 한계 / 리뷰 사항

- 2.754kg은 사용자가 잰 배터리 포함 전체 질량으로 기록했다. 이 무게만으로 관절 토크나 접촉을 추정하지 않는다. 위 임계값은 제한된 경험 기반 기준이며 모든 하중에서 보장되지 않는다.
- load-supported는 안정 지지와 일치하는 관측이라는 뜻이다. 물체에 걸린 상태와 정상 지지를 센서만으로 완전히 구분하지 못한다. 120틱은 약10.55도이며 정밀 위치 도달 성공으로 표현하지 않는다.
- 지속 감시는 Stand의 수평 유지 루프 범위다. 다른 모든 보행/수납/개별 서보 원점 탐색 경로를 이번에 통일한 것은 아니다. 해당 기존 경로의 토크 해제 정책은 별도 리뷰 대상이다.
- 전진 준비의 invalid argument 코드는 수정했으나 실제 전진 성능·안정성 검증은 아직 하지 않았다.
- 센서 실패 시 마지막 지지 목표 유지가 실제 안전을 항상 보장하지 않는다. 독립 브레이크/접촉센서/전류 단위 실측과 하중별 데이터가 필요하다.
