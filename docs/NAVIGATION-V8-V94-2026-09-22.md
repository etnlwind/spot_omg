# V8 대각선 두 발 옆걸음 — V94 (68), 실험 단계

2026-09-22. 사용자 요청: 기존 네 박자 옆걸음을 두 발씩 움직이는 방식으로 구현.
코드와 빌드는 완료했지만 **접지 품질 검증은 미완료**다. 실기에 설치하지 않았다.
현재 설치된 로봇/Windows는 V93 (67)이며 이번 작업에서 실기 명령을 보내지 않았다.

## 구현

- V7을 보존하고 `attitudepd_v8`을 프로필 끝 인덱스30에 추가했다.
  지원하는 연결에서 앱 목록 첫 항목/기본값이며 시뮬레이터 기본값도 V8이다.
- FL+RR과 FR+RL을 교대로 옮긴다. 주기2.4초, duty0.75로
  한 쌍의 스윙0.6초와 네 발 지지0.6초를 번갈아 계획한다.
- 시작1.5초 동안 네 발을 지지하며 기존 저장 간격을 적용한다.
- 스윙 초반25%에서 들고, 중앙50% 동안 높이를 유지하고, 마지막25%에서 내린다.
  횡방향 복귀는 스윙20~80%에 집중한다. 기본 들림12mm에 사용자 들림을 더한다.
- 저장 들림에도 동일한 높이 파형을 적용한다. 펌웨어/시뮬레이터가 C 함수를 공유한다.
  자세 보정의 지지 위상도 대각선 쌍과 일치시켰다.
- 전후진/대각선 회전/후진50% 정책은 V7과 동일하다. 간격·들림 저장값을 바꾸지 않았다.
- 네 발 지지는 **계획된 구간**이다. 실제 접지가 항상 일치한다고 주장하지 않는다.

## 최종 시뮬레이션

`artifacts/navigation-v8/v94/`가 최종 저장 보정 시험이다.
2초 대기 +20초 옆걸음 +4초 정지. 고정된 앞/뒤/위/옆 카메라,
명령/실제 관절각, 하중, 발끝 높이, 자세와 위치를 기록했다.
보정은 FL/FR/RL/RR 들림20/20/20/20mm, 간격-30/-30/+30/+30mm다.

| 항목 | V7 오른쪽 | V8 오른쪽 | V7 왼쪽 | V8 왼쪽 |
|---|---:|---:|---:|---:|
| 보행 중 앞뒤 위치 범위 mm |28.18|22.76|31.09|22.75|
| roll 최대−최소 ° |21.11|18.22|21.09|18.17|
| yaw 최대−최소 ° |11.09|4.47|10.73|4.97|

V8 좌우 모두 보호정지 없이 종료하고 정지 복귀했다.
옆 이동량은 오른쪽160mm/왼쪽158mm였다. 흔들림 절반이라는 초기 목표는 미달이다.
오른쪽 반입력588 시험도 완료했으나 앞뒤 범위50.74mm로 오히려 더 나빴다.

접지 품질은 별도로 측정했다. 보행4.4초 이후 스윙 중앙30~70% 구간에서
해당 두 발 모두 높이>2mm이고 하중<0.5N인 프레임 비율은 오른쪽87.8%, 왼쪽84.6%,
오른쪽 반입력88.5%다. 이는 전체 보행 성공률이나 정확한 동시 이륙률이 아니다.
여전히 한 발이 늦게 떨어지는 구간이 있다.

**보정0의 기본 시험에서는 같은 기준이0%였다.**
`verified/default/trajectory.json`은 최종과 같은12mm/평탄한 들림 파형이며
넘어지지 않아도 일부 발을 끌고 이동한다. 이 설정을 검증 완료라고 취급하면 안 된다.
모터/접촉/질량 분포는 추정 물리 모델이며 실제 하드웨어 한계로 단정할 수 없다.

## 실패한 후보와 다음 작업

- `trial-01`~`trial-13`과 `final/`, `verified/`는 중간 실험 기록이다.
  `final/`이라는 이름도 최종 채택을 의미하지 않는다. 최종 영상은 `v94/`만 사용한다.
- 몸체를 대각선 지지선/교점 쪽으로 이동한 시도는 보호정지 또는 큰 앞뒤 이동을
  일으켜 제거했다. 최종 코드에는 몸체 이동 기능이 없다.
- 기본 들림을8mm로 낮추면 roll은 감소했지만 보정0에서 발을 끌었다.
- 기본24mm+저장20mm 후보(`trial-13/right`)는4.76초에 tilt로 중단됐다.
  실패 기록을 보존했다. 최종 기본12mm를 성공 최적값으로 해석하지 않는다.
- 다음에는 앞뒤 두 다리의 실제 이륙 지연을 각도 추종/하중/몸체 기울기로 나누어
  확인하고, 사용자 보정0/20과 좌우/반입력을 함께 통과하는 궤적을 찾아야 한다.
  단순히 들림을 낮춰 흔들림 지표만 좋게 만들지 않는다.

## 빌드와 검증 수준

- 관련 호스트·기구학·Windows UI 테스트273개 통과.
  기존 C 테스트 별도14개 통과/13개 건너뜀. 최적화한 packet/config 코드는
  Zig 호스트에서 `-Os`로 packet/actuator C 시험을 별도 실행해 통과했다.
- STM32 `firmware-final/attitudepd-v8-v94.bin`:327500바이트,
  고정320KiB 슬롯 여유180바이트. manifest에 해시/벡터 검증 기록.
  OTA 영역을 늘리지 않았다. drive_control은 엄격한 부동소수점 옵션을 유지한 Os,
  빌드 스크립트의 순수 packet/config 소스도 Os로 줄였다.
- Windows `windows-dist/SpotOMGController/SpotOMGController.exe` V94(68) 빌드 완료.
  설치/실행/바로가기 교체는 하지 않았다. Apple 소스/테스트 갱신, Xcode 빌드 미수행.
- 실기 설정 readback, 실제 위치 유지, 실제 전체 보행 검증은 **이번 V8에서 미수행**.

재현 도구: `scripts/analysis/verify_v93_side_step.py --profile attitudepd_v8
--input 1000 --seconds 20 --output artifacts/<새 경로> --video`.
경로가 이미 존재하면 덮어쓰지 않는다. `--lift 0 0 0 0 --width 0 0 0 0`으로 기본값 시험.
`summary.paired_clearance`와 `first_fault`를 반드시 함께 확인한다.
