# iPhone: 정상 Stop 뒤 진단 로그 수신 시간 제한 수정

2026-09-18. 사용자가 Windows와 같은 문제가 iPhone에도 있는지 확인하고
수정하도록 요청했다. **동일한 고정 5초 제한을 코드에서 확인하고 소스를 수정했다.**
현재 Windows에는 Swift/Xcode가 없어 iOS 컴파일, XCTest 실행, 기기 설치 및
실제 BLE 재시험은 하지 못했다. 소스 빌드 번호는 **0.5.0 (51)**이며,
이전에 설치가 확인된 UJIN17 앱은 **0.5.0 (49)**다.

## 원인

`RobotBluetoothManager.armDriveCompletionTimeout()`은 `.stopping`과 `.draining`
모두 5초 뒤 Ctrl+C와 연결 해제를 실행했다. `$SPOTDRIVE stopped`로 정상 정지가
확인된 뒤에도 진단 패킷 수신은 타이머를 갱신하지 않았다. STM32는 모든 관절의
진단 출력 뒤에 `# `를 보내므로 BLE로 긴 로그를 받으면 같은 연결 해제가 가능하다.
이는 코드 경로 확인이며 iPhone에서 해당 오류를 새로 실측했다는 뜻은 아니다.

## 수정

- Stop 응답을 기다리는 5초 제한은 유지한다. 배터리 알림은 이 제한을 연장하지 않는다.
- 종료 응답 이후에는 부분 줄을 포함한 수신 패킷마다 5초 무수신 제한을 갱신한다.
- 최초 종료 응답부터 전체 30초 상한을 유지한다. 중복 Stop/오류 응답도 상한을 재설정하지 않는다.
- 프롬프트나 연결 종료 시 두 기한을 초기화한다. 오래된 타이머 콜백은 현재 기한과
  상태를 다시 검사하여 갱신된 세션이나 후속 자세 명령을 끊지 않는다.
- 시간 비교는 시스템의 단조 증가 시간으로 한다. 테스트에서는 같은 만료 처리
  경로에 가상 시간을 주입한다. 기존 생성자와 호출 방식은 유지했다.
- 정상 정지 전과 종료 로그 수신 중의 시간 초과 메시지를 구분했다.

BLE·시뮬레이터 콘솔 모두 공통 수신 처리를 사용한다. 기존 heartbeat 중단,
프롬프트 전 명령 보류, 정지 후 새 조작, 안전 정지 처리 규칙을 유지한다.

## 추가한 XCTest (미실행)

`RobotCommandTests.swift`에 다음 6개 테스트를 추가했다.

1. 실제 V80 진단 4,278바이트를 20바이트/30ms 및 180바이트/300ms로 수신하고,
   5초를 넘겨도 연결 유지 → 분할 프롬프트 → 새 조작을 확인.
2. 줄 끝이 없는 조각 수신은 진행으로 인정하지만 빈 입력은 인정하지 않고,
   이후 5초 무수신 시 연결 해제.
3. Stop 미확인 상태에서 배터리 알림만 와도 5초 뒤 연결 해제.
4. 출력/중복 Stop이 계속 와도 프롬프트가 없으면 전체 30초 뒤 연결 해제.
5. 종료 프롬프트 뒤 보류한 Stand가 시작되면 이전 타이머가 그 명령을 중단하지 않음.
6. 실제 Dispatch 타이머와 RunLoop에서 6초간 진단 수신을 유지하는 검사.

`V80StopDiagnostics.txt`는 Windows에서 사용한 실제 첨부 로그 발췌와 동일하다.
원문은 마지막 진단 줄 도중에 끊겼으므로 테스트의 마지막 줄 끝/프롬프트는 합성
입력이다. 전송 간격도 시험 조건이며 iPhone 실측 처리량이 아니다. XCTest 번들에
리소스로 등록하여 Mac 원본 경로에 의존하지 않는다.

Windows에서 확인한 범위는 diff 검토, fixture 원문 일치·프로젝트 리소스 연결,
빌드 번호 일치, 설치 스크립트 문법 및 dry-run, 소스 ZIP 내용 검사다.
이 검사를 Swift 빌드/XCTest 통과로 보고하지 않는다.

## Mac에서 이어서 할 일

Xcode에서 `apps/ios/SpotOMGController/SpotOMGController.xcodeproj`를 열어
`RobotCommandTests` 전체를 실행하고 iOS 빌드를 확인한다. 이 테스트의 로봇 명령은
주입된 메모리 송신기로 전달하며 실제 로봇에 연결하지 않는다.

서명·페어링이 준비된 Mac에서 설치 및 빌드 51 조회:

```bash
python3 scripts/hardware/install_ios_v4.py
```

설치 스크립트는 앱을 자동 실행하거나 로봇에 연결하지 않는다. 설치 후 실제
조이스틱 보행 → 손 놓기 → 긴 로그 → 연결 유지 및 재조작을 확인해야 한다.
`artifacts/attitudepd-v4/ios-v4-build51-source.zip`에 최신 프로젝트·fixture·설치
스크립트·문서를 묶었다. 소스 ZIP이며 서명된 IPA가 아니다. 빌드 50 ZIP은 이전
준비 상태로 보존하고 새 설치에는 사용하지 않는다.
# 추가 한계: 출력 누락

Windows 0.1.2에서 ID11 진단 끝부분/프롬프트 누락으로 시간 초과가 재발했다.
Windows 0.1.3의 상태 재조회 복구는 현재 iOS 빌드 51에 이식되지 않았다.
빌드 51의 진행률 기반 타이머만으로 모든 연결 해제 문제가 해결됐다고 보고하지 않는다.
