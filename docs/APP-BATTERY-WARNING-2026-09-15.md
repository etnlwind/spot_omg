# 충전 경고: Windows · Mac · iPhone

사용자 요청: 충전해야 하는 전압이면 세 앱 모두 강력하게 경고한다.
앱 경고와 펌웨어의 기존 보호 정지 정책은 별개다. 이 변경으로 모터 제어,
서보 위치·원점, 보행 궤적, 자동 토크 해제 조건을 변경하지 않는다.

## 경고 정책

3S LiPo와 현재 서보 전원선 측정에 대한 운용 기준이다. 팩 단자의 직접 측정,
셀별 전압, 배터리 잔량 백분율이나 완충 판정으로 취급하지 않는다.
기준은 현재 펌웨어의 11.0V droop 기준 및 10.5V 자세 보호 기준과 맞췄다.

| 전압 | 앱 동작 |
|---|---|
| 11.0V 이하 | 상단 빨간 경고: **배터리 부족 · 지금 충전하세요** |
| 10.5V 이하 | 상단 빨간 경고 강화: **즉시 사용 중단 · 배터리 충전** |
| 11.4V 이상 지속 | 1초 이상 떨어진 새 측정 3회 이상, 첫~마지막 측정 5초 이상이면 해제 |

- 낮은 전압은 한 번 감지해도 경고한다. 상향 회복에만 지연을 둔다.
- 회복 측정 사이 15초를 넘긴 공백이 생기면 회복 확인을 다시 시작한다.
- 처음 감지하거나 위험 단계로 올라갈 때 소리로 알린다. 아이폰은 오류
  진동을 요청하고 접근성 알림도 제공한다. 소리·진동은 기기/OS 설정에 따른다.
- **확인**은 상세 설명만 접는다. 빨간 경고는 회복 조건까지 유지한다.
- **보행 정지** 버튼은 기존 정상 Stop 경로를 사용한다. 경고 자체로 토크를
  끄거나 자동 자세 전환을 보내지 않는다. 기존 정지·긴급 중단 조작을 유지한다.
- 안내: “보행을 멈추고 몸체를 지지한 뒤 전원 스위치를 끄고 충전하세요.”
- Mac Catalyst와 iPhone은 같은 Swift 코드다. Windows는 같은 경계값과
  상태 전이로 구현했다. 시뮬레이터 연결의 경고에는 가상임을 표시한다.
- 연결 해제 시 전압과 경고를 초기화하고, 재연결 후 새 측정으로 다시 판정한다.

## 전압 수신

### 기존 펌웨어에서도 적용

연결/상태 동기화/동작 후 `read 1` 응답을 판정한다. Idle에서는 약5초마다
짧은 전압 조회를 보내며 다른 명령의 응답 대기나 보행 세션 중에는 끼워 넣지
않는다. 15초 이상 된 전압은 기존처럼 “이전”으로 표시한다. 경고가 새 상태
조회 대기 중 사라지지 않도록 마지막 값을 유지한다.

정지 후 `Gait diagnostics: ... min_voltage=...mV`도 경고에 반영한다. 이 값은
이미 끝난 보행의 최소값이므로 경고를 올릴 수만 있고, 최근 전압 표시나 회복
판정을 덮어쓰지 않는다. 실제 기록 10.9V → 동작 최소10.3V를 회귀 시험했다.

### V71부터 보행 중 수신

기존 성공한 서보 피드백에서 전압만 재사용한다. 직전 전송 이후 최소값을
초당 최대1회 `$BATTERY mv=10300` 형태로 전송한다. 새 서보 조회가 없고,
50Hz 보행 시간이나 추종 보호 곡선을 변경하지 않는다.
USB/BLE 콘솔은 각자 이벤트 번호로 같은 측정을 받는다. 한 콘솔이 읽어서
다른 콘솔의 알림이 사라지는 것을 회귀 시험했다. 실시간 ACK가 있으면 전압
전송을 다음 서비스 기회로 미룬다. UART 송신 대기는 최대5ms다.
실제 추가 지연·보행 중 수신은 충전 후 실기로 확인해야 한다.

V71 capability는 `batterytelemetry`, revision은 `s-native-v6-2-5-v71`이다.
기존 설치 V70은 보행 중 전압 스트림을 보내지 않는다. 앱만 업데이트한
경우 보행 도중 새로 생긴 저전압은 동작 종료 후 진단/조회에서 경고할 수 있다.

## 검증

- Windows 정책·화면·연결 회귀 **53개 통과**. macOS 호스트의 Qt offscreen에서
  Windows 앱 코드를 검사했다. Windows 실행 파일의 설치/동작 검증은 아니다.
- 실제 Qt 경고 화면을 렌더링해 확인. 확인 후에도 빨간 배너 유지 및 단계 상승
  때 상세 설명·소리가 다시 활성화되는 것을 검사했다.
- Swift CLI로 iPhone/Mac 공통 정책과 실제 manager 수신 경로를 검사했다.
  경계 전압, 일시 회복, 오래된 값, 잘못된 값, 모든 문자열 분할 위치,
  보행 중 조회 금지, 명령 응답 대기, 연결 해제 초기화를 통과했다.
- Mac Catalyst 빌드, 서명된 iPhone 기기용 빌드 통과. iOS Simulator는 실행하지 않았다.
- C 전압 집계/간격/타이머 wrap/USB·BLE 양쪽 전달 회귀 통과.
- V71 펌웨어 빌드 **326668 bytes**, 320KiB 슬롯 안에 들어간다.
  SHA256 `9a7d005b4e9feb0dd1e86ec29688ff89d9c85e872db6d7e3e49af5165e0b6b73`.
- 이번 변경 검증은 호스트/빌드/화면 수준이다. 충전 필요 상태인 실제 로봇에서
  추가 구동 시험이나 V71 OTA를 하지 않았다. 실제 설치 펌웨어는 V70이다.

## 앱 배포 상태

- Mac: 서명 검증 가능한 로컬 앱을 `/Users/etnlwind/Applications/SpotOMGController.app`에
  배치했다. 실행 중이던 다른 경로의 앱은 그대로이며 새 앱을 실행해야 적용된다.
- iPhone UJIN17: 서명 빌드 완료. 설치는 기기 잠금으로 CoreDevice가 거부했다
  (`10003 device locked`). 사용자에게 잠금 해제를 요청했으며
  `iphone-install.json`에 첫 시도 오류를 보존했다.
- Windows: `SpotOMG-Windows-0.1.1-source.zip`에 업데이트 소스를 묶었다.
  Windows에서 `setup.ps1`/`run.ps1` 또는 `build.ps1`로 사용한다.
  macOS에서 `.exe` 빌드·Windows 설치를 했다고 보고하지 않는다.
- 펌웨어: V71 빌드만 완료. 실제 보드 V70은 유지한다. 충전 후 OTA와
  실시간 전압 수신을 별도 검증해야 한다.
