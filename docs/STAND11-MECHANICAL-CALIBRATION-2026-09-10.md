# Stand11 조립 영점 검증과 STM32 기록

Stand11은 **현재 저장된 중심 tick을 12개 모터에 명령하는 자세**다. 모터가 중심 tick에 정확히 도착해도 혼 조립 각도, 링크 휨, 베어링 유격, 몸체 기울기가 있으면 실제 다리는 일직선이 아닐 수 있다. 피드백만으로 이를 자동 판정하거나 중심값을 자동 수정하지 않는다.

현재는 배터리가 준비되지 않았으므로 펌웨어 코드와 호스트 테스트만 진행했다. 아래 실물 절차는 정상 전원이 준비된 뒤 사용한다.

## 무엇을 확인할 수 있나

| 관찰 | 가능한 해석 | 추가 확인 |
|---|---|---|
| 목표 tick과 실제 tick의 차이가 큼 | 모터 추종 오차, 부하, 마찰, 전압 영향 | 전압·전류 원시값·부하·동작 구간을 함께 비교 |
| 목표와 실제 tick은 같지만 링크가 비뚤어짐 | 조립 영점, 혼 위치, 링크/몸체 변형 가능성 | 외부 지그나 각도계로 실제 축 정렬 측정 |
| 동일 지그인데 접근 방향에 따라 tick이 달라짐 | 유격, 마찰, 지그 정렬 반복성 문제 | 양쪽 방향에서 여러 번 접근해 범위 비교 |
| 무부하에서는 정렬되지만 하중에서 달라짐 | PLA/PETG 링크·프레임 탄성, 체결부 변형 가능성 | 몸체 지지 상태와 하중 상태를 구분하여 측정 |

전류·부하는 모터가 보고한 원시값이다. 서로 다른 J2(STS3250)와 J1/J3(STS3215)의 값을 곧바로 동일한 토크로 비교하지 않는다. 지지/스윙 표시는 명령상의 구간이며 실제 접지 측정이 아니다.

## Stand11 외부 기준 설정

1. 몸체를 지지대에 고정하고 기준 프레임을 수평으로 맞춘다. 발이 몸체 무게를 받지 않게 한다. 다리를 끝까지 당긴 상태나 기계적 스토퍼를 영점 기준으로 사용하지 않는다.
2. 정상 전원에서 `stand11`을 실행해 현재 상태를 기록한다. 성공하면 `stand11` 라벨의 12모터 로그가 자동 저장된다. 아직 이것은 **기존 중심값에 대한 확인**이다.
3. 지지대를 유지하고 `relax`로 토크를 끈다. 모터 위치 피드백을 읽기 위해 모터 전원은 유지한다.
4. 실제 0° 기준을 외부에서 맞춘다. J3는 측면에서 관절축 중심과 링크 기준선의 일직선을, J2는 그 기준선과 몸체 기준축의 관계를, J1은 정면에서 CAD 기준에 맞는 좌우 기울기를 확인한다. 출력물 외벽보다 STEP의 축 중심/기준면을 이용하며, 설계상 오프셋을 없애려고 억지로 정렬하지 않는다.
5. 각 관절을 기준의 한쪽에서 천천히 접근하여 맞춘 뒤 `mechdiag capture jig_plus`를 실행한다. 반대쪽에서 접근해 `mechdiag capture jig_minus`로 기록한다. 각 방향에서 3회 이상 반복하면 중심 오차와 반복 오차를 구분하기 쉽다.
6. 양방향 차이가 크면 체결, 유격, 마찰, 링크 변형과 지그 정렬을 먼저 확인한다. 실제 영점이 일관되게 달라진 경우에만 중심 tick 변경을 검토한다. 변경 후에는 지그 검증과 하중 상태 검증을 다시 한다.

초기 지그는 몸체 고정대와 정면/측면의 기준선을 가진 판으로 구성할 수 있다. 정확한 지그 치수는 새 STEP의 관절축 위치와 실물 체결 치수를 대조해 정해야 한다. 이 문서가 치수가 검증된 지그 설계도는 아니다.

## 저장되는 내용

- `stand`, `stand11`, `landing` 완료 시: 12개 모터의 위치 tick, 중심값·방향·범위, 환산각, 목표 위치와 오차, 토크 상태, 속도, 부하, 전류 원시값, 전압, 온도, 하드웨어 오류.
- `mechdiag capture LABEL`: 동작을 명령하지 않고 동일한 정지 진단을 수동 기록한다. 라벨은 영문/숫자/`_`/`-`로 1~16자다. 캡처는 12모터를 순차로 읽으며 동시 측정이 아니다.
- 보행 종료 시: 상위 3개만 기록하던 방식 대신 12개 전체의 부호 있는 평균 오차, 지지/스윙별 평균과 샘플 수, 최대 오차 시점의 목표/측정값·전류·부하·지연 관련 정보를 자동 저장한다. 측정이 없으면 `MECH_UNSAMPLED`로 표시한다.
- 보행 중에는 기존 안전 검사에서 읽은 모터 상태를 RAM 통계에 재사용한다. 추가 모터 통신과 플래시 쓰기는 없다. 공통 보행 경로에서 낡은 명령 이력과 지지 구간이 로그에 섞이던 부분도 수정했다.

정지 진단은 최대 50개 로그 레코드를 사용한다. STM32 내부 플래시 sector 7의 기존 비행 로그에 기록하며, IMU 보정 영역을 보존한다. 기록 묶음이 중간에 순환 삭제되지 않도록 공간을 먼저 확보한다. 용량이 차면 오래된 로그가 순환 삭제되므로 실험 후 내보낸다. 기록 중 전원이 끊기면 미완성 레코드를 건너뛰며 이전의 정상 레코드를 보존한다. 실패한 캡처와 불완전한 기록은 분석에서 중심값 제안에 사용하지 않는다.

## 조회와 분석

```text
mechdiag capture stand11_check
log status
log show 64
```

앱 콘솔에서 내보낸 로그 텍스트를 파일로 저장한 뒤 다음처럼 분석한다. `--fixture-label`은 **그 라벨을 찍을 때 실제 0° 정렬을 외부에서 확인했다는 선언**이다.

```sh
python3 tools/analyze_mechanical_logs.py motor-log.txt \
  --fixture-label jig_plus --fixture-label jig_minus \
  --output mechanical-report.md
```

분석 도구는 로봇에 연결하거나 설정을 쓰지 않는다. 완전한 기록 중 토크 OFF, 정지, 하드웨어 오류 없음, 10.8V 이상, 유효한 위치 범위의 반복 측정만 중심값 검토에 사용한다. 기존 중심과 방향이 다른 기록은 합치지 않는다. 최소 두 번의 유효 측정이 있어야 평균 중심 tick과 반복 범위를 제시한다. Stand11 라벨만으로 실제 영점을 검증했다고 간주하지 않는다.

## 검증

가짜 모터/플래시를 사용한 C 실행 테스트로 움직이는 상태의 진단 거부, 좌우 반전 부호, 12모터 저장, 읽기 누락, 저장 실패, 지지/스윙 통계, 레코드 길이, 쓰기 중 전원 차단 복구, 묶음 단위 순환, IMU 보정 영역 보존을 확인했다. 분석 도구는 지그 선언 없는 Stand11, 토크 ON/불완전 기록 제외, 반복 측정 중심 제안, 중복 로그 제거를 테스트한다.

실제 모터의 정렬 오차와 전류 특성은 아직 측정하지 않았다.

## 현재 Stand11 중심값과 2048 비교

괄호 안은 `중심값 - 2048` tick이다. 원점 2048과의 차이는 조립 오차의 실측값이 아니다.

| 다리 | J1 | J2 | J3 |
|---|---:|---:|---:|
| 왼쪽 앞 FL | 1929 (-119) | 2077 (+29) | 1965 (-83) |
| 오른쪽 앞 FR | 2089 (+41) | 1922 (-126) | 2081 (+33) |
| 왼쪽 뒤 RL | 2104 (+56) | 1942 (-106) | 1964 (-84) |
| 오른쪽 뒤 RR | 1951 (-97) | 2255 (+207) | 2046 (-2) |

가장 큰 차이는 RR J2, ID 11의 +207 tick으로 모터각 약 +18.19°다. 다음은 FR J2, ID 5의 -126 tick(약 -11.07°)이다. `360° / 4096 tick`으로 계산한 엔코더 중간값 대비 차이며, 관절의 기구 오차나 자세각으로 단정하지 않는다. 일괄적으로 2048로 변경하지 않는다.

최종 펌웨어 빌드: `shared-locomotion-v24.bin`, 158824 bytes, SHA-256 `506617f34ed886472bd99cca68a494f7a3b53dd74a6bb9455391bf6bbf89174a`. 실제 로봇에는 전송하지 않았다. 기구 진단 및 기록/분석 검증 23개 통과.
