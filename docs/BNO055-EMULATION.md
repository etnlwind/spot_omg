# BNO055 가상 센서 적용 — 2026-09-09

실물 STM32의 BNO055 경로를 확인하여 MuJoCo에 **IMUPLUS Euler 출력 에뮬레이터**를 연결했다. 실제 센서나 로봇 펌웨어를 플래시하지 않았다. Bosch의 비공개 센서 융합 알고리즘 자체를 재현한 것은 아니다.

## 데이터 경로

MuJoCo 물리 서브스텝의 몸체 자세 → 100Hz 센서 샘플 → 추정 융합 필터·지연 → Euler 레지스터 6바이트 → I²C 전달 지연 → 50Hz 읽기 → 실물과 같은 축 변환·0.1도 정수 변환 → 자세 필터 및 기울기 정지 판정.

물리 자세를 바로 안전 판정에 넣던 이전 경로는 제거했다. 화면의 물리 자세는 비교용이다. 현재 보행은 **센서 모니터링 모드**이며, 이 변경으로 능동 균형 보정이 활성화되지는 않는다. 실물 robot.c에는 능동 보정도 있지만, 가상 보행에 대한 안정성 검증이 별도로 필요하다.

## 확정값과 추정값

| 항목 | 적용 | 근거 |
|---|---|---|
| 모드 | IMUPLUS, 자기계 미사용 | `bno055.c`의 0x08 |
| 센서 갱신 | 100Hz, 샘플 유지 | Bosch 데이터시트 표 3-14 |
| Euler | signed little-endian, 16LSB/도 | 데이터시트 표 3-28/29 |
| 보드 축 | 로봇 roll = 센서 pitch, 로봇 pitch = 센서 roll | 현재 `bno055_read_euler` |
| 정수 변환 | raw × 10 / 16, 0 방향 절삭 | 실물 코드 |
| I²C | 100kHz, 6바이트 읽기 81클럭 = 0.81ms | main.c 및 주소/ACK 포함 전송량; 추가 clock stretching 제외 |
| 제어 읽기 | 20ms | robot.c |
| 자세·미분 필터 | (이전 × 3 + 새 값) / 4, 정수 절삭 | robot.c |
| 미분 제한 | ±120도/초 | robot.c |
| 기울기 정지 | 12도 초과 2프레임 | robot.c, 영점 기준 full 모드 |
| 읽기 오류 | 3회 연속 오류 시 정지 | robot.c; HAL 100ms 블로킹 시간 자체는 미재현 |
| 융합 전달 지연 | 기본 20ms | **추정**, 설정 가능 |
| 융합 1차 필터 시정수 | 10ms | **추정**, 설정 가능 |
| 각도 노이즈 | 표준편차 0.08도, seed 55 | **추정**, 재현 가능한 난수 |
| yaw 드리프트 | 0.02도/초 | **추정**, 자기계 없는 모드의 오차 실험용 |
| 모드 진입 대기 | 30ms | 드라이버의 IMUPLUS 설정 후 대기; 전원 부팅 전체 아님 |
| 데이터 정체 감지 | 샘플 나이 100ms 초과 시 읽기 실패 | 시뮬레이터 추가 진단; 실물에는 타임스탬프 없음 |

내부 융합 지연은 데이터시트의 보장값으로 취급하지 않는다. 실제 보드의 장착 오차, 진동·가속도에 따른 융합 오차, 온도, 자기장, 자동 캘리브레이션, I²C clock stretching, HAL 블로킹 및 전체 부팅 시퀀스는 아직 실측하지 않았다. 센서 모델은 로봇의 정상 보행 자세 범위를 대상으로 하며, 뒤집힌 자세의 Bosch Euler 분기까지 재현하지 않는다. 칩 ID·전체 레지스터 뱅크 또는 MCU 에뮬레이터가 아니다.

## 설정과 확인

`virtual_robot.py --parameters PATH`가 읽는 물리 JSON에 `bno055` 객체를 추가하면 센서 파라미터를 덮어쓸 수 있다. 예: `"bno055": {"fusion_delay_s": 0.04, "noise_std_deg": 0.15}`. 단위는 이름에 명시했다. 기본값은 `simulation/mujoco/bno055_emulator.py`의 `BNO055Config`에 있다.

BLE/TCP 콘솔에서 `imudiag`를 보내면 모드, 측정값, 실제 샘플 나이, Euler 원시 바이트, 필터 결과, 오류 횟수, 설정값이 나온다. `baldiag`에도 같은 진단을 포함했다. `syncstate`는 `imu=bno055-emulated` 및 `bno055emu` capability를 제공하고, `balance=monitor`를 유지한다. MuJoCo 화면에는 센서 샘플 나이가 표시된다.

`check_bno055_response.py`는 10도 계단 입력에 대한 최초 응답·필터 50%·90% 도달 시간을 측정하고, 20/60ms 융합 지연에서 5개 보행의 좌회전→전진→정지를 검증한다. 결과는 `simulation/mujoco/bno055_validation.json`에 저장한다. 이는 추정 센서의 응답이며 실측 BNO055 응답이 아니다.

공식 출처: [Bosch BNO055 데이터시트 Rev 1.8](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bno055-ds000.pdf), 표 3-14, 3-28, 3-29.

## 이번 검증 결과

- Python 전체 243개 테스트 및 26개 subtest 통과.
- 20/60ms 지연 × 5개 보행의 회전→전진→정지 10건 모두 안전 상태 정상, 정지 완료, 발 이외 지면 접촉 없음.
- 기본 설정의 10도 계단 응답: 측정값 최초 변화 40ms, 필터 50% 80ms, 90% 200ms. 50Hz 읽기 위상과 정수 필터를 포함한 결과이다.
- 실행 중인 MuJoCo를 재시작하고 실제 TCP `imudiag`에서 BNO055/IMUPLUS, 샘플 나이 30ms, 오류 0을 확인했다. 기존 BLE 앱은 같은 가상 연결을 사용할 수 있다.
