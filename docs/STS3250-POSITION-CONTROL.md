# STS3250 위치 제어: 실기 확인 사항과 구현 기준

## Landing / J3 기구적 끝점 (2026-09-16 사용자 확인)

사용자는 Landing이 **J3가 더 이상 접히지 않는 기구적 접힘 끝에 도달하여,
토크를 풀어도 자세가 유지되는 상태**라고 설명했다. Landing 먼저 전환 후
토크를 해제하는 절차는 이 기구적 안정성을 전제로 한다. 실제 도착 확인 없이
명령을 전송했다는 이유만으로 안정된 Landing이라고 간주하지 않는다.

이 설명은 사용자의 기구 확인이며, 이번 에이전트가 네 축의 물리적 끝점 각도를
독립 측정한 것은 아니다. 코드의 Landing J3 목표130°를 네 축의 검증된 물리
한계나 링크 내각으로 곧바로 확정하지 않는다. 서보 EEPROM 제한도 임의로 바꾸지 않는다.
기구적 끝점에서 추가 접힘을 요구하는 것은 가속도 식별 시험이 될 수 없다.
동작 방향과 여유 구간을 먼저 확인하고 시험한다.

v74/v75의 작은 RR J3 시험은 **Stand에서 시행한 뒤 Landing으로 종료**했다.
현재 Landing의 끝점 설명만으로 당시 Stand 시험이 끝점에 막혔다고 확정하지 않는다.
다만 실제 방향/기구 여유를 사전 확인하지 못했으므로, 당시 원시 목표·피드백
기록과 ‘접힘 성능’이라는 해석은 분리해서 다룬다.

## 후속 J1 좌표 주의 (2026-09-15)

S-native의 CAD J1 음수 오므림을 모터 각도로 그대로 보내면 실제 앞 두 J1은
바깥으로 벌어진다. FR ID4 증가=안쪽은 2026-09-10 단독 이동에서 확인되었고,
2026-09-15 사용자가 v59 보행의 앞 두 다리 벌어짐/뒤 두 다리 오므림을 확인했다.
`s_native_servo.h`는 앞 J1만 CAD→실기 경계에서 변환한다. 저장된 모터 영점/방향,
J2 누적 위치 기준을 이 문제 때문에 바꾸지 않는다. [v60 진단 기록](S-NATIVE-V61-FRONT-J1.md).
v60은 호스트/시뮬레이터 검사, 빌드, 실기 설치/상태 readback까지 완료했다.
후속 실기 로그에서 앞 J1 엔코더의 수정된 오므림 방향을 확인했다. 두 보행은
기울기 보호로 중단됐으며, 독립 위치 유지 시험과 정상 Stop→S 복귀는 미검증이다.
[v60 실기 보행 분석](../artifacts/s-native-v6-1/log-analysis-2026-09-15/REPORT.md)을 참고한다.

## STS3250 실기 확인

확인 날짜: 2026-09-10. 대상은 Spot OMG의 앞 J2(ID 2, 5). 모든 STS 제품/펌웨어에 동일하다고 일반화하지 않는다.

## 먼저 알아야 할 사항

**다회전 목표값과 위치 피드백을 같은 좌표라고 가정하지 않는다.** 현재 실기 STS3250은 누적 회전 목표를 수행하면서도 위치 조회에서는 0~4095 안의 값을 반환하는 동작이 확인되었다. 읽힌 값이 단회전 범위라고 해서 내부 회전 수도 0이라고 판단하면 안 된다.

- J1/J3: STS3215 8개. J2: STS3250 4개(ID 2, 5, 8, 11).
- 앞 J2 두 축만 현재 Stow 경로에서 단회전 경계를 넘는다.
- 한 바퀴4096틱, 1틱=360/4096도. 로봇 관절각0도와 서보 원시값0은 다르다.
- 목표 위치의 음수는 BIT15 부호 + 나머지 비트 크기의 sign-magnitude다. 2의 보수로 인코딩하지 않는다.
- 현재 설정: mode33=0, resolution30=1, offset31/32=0. 다회전 시 min9/max11=0. 설정 읽기 검증은 실제 동작 검증을 대체하지 않는다.

## 실제 실패와 원인 확인

V29에서 수동으로 접힌 상태의 Landing 실행:

```
STOW_TRACK id=2 elapsed=760 target=850 actual=328
```

시작 위치858에서 목표는850(8틱=약0.7도 변화)이었지만 피드백은328로 변했다. 약46.6도 움직인 값이며 추종 오차522틱이 보호 기준512틱(45도)을 넘어서 토크가 해제됐다. 사용자가 본 되돌아옴은 역방향 복귀 명령이 아니라 토크 해제 후의 내려앉음과 일치했다.

최종 회전각이45도/60도로 제한된 것이 아니다. 각 시점의 목표와 실측의 불일치로 중단된 것이다. 중단 기준을 늘려 우회하면 안 된다.

작은 이동으로 한계를 둔 위치 유지 비교 결과:

| 검사 | 시작 피드백 | 보낸 목표 기준 | 최대 관측 피드백 | 결과 |
|---|---:|---|---:|---|
| ID2 normal |860|읽힌 값860|847|13틱 편차로 중단|
| ID2 extended |861|읽힌 값861|848|13틱 편차로 중단|
| ID2 canonical |861|Stow 누적 관절각에서 계산(약4957)|861|400ms 유지, 편차0|
| ID5 canonical |3159|Stow 누적 관절각에서 계산(약−937)|3159|400ms 유지, 편차0|

**같은 접힌 물리적 자세에서도 목표 좌표는 앞 좌우 각각 한 바퀴 위/아래일 수 있다.** `raw - normalized`만으로 목표의 회전 기준을 복원한 이전 구현이 잘못됐다. 현재 기체에서는 읽힌 값만으로 목표를 만들면 유지 대신 큰 회전을 요구할 수 있다.

## 구현 시 지켜야 할 기준

1. 관절각(기구), 누적 목표 틱(명령), 원시 피드백(센서)을 구분한다. 서보 방향을 임의 반전하거나 목표를 무조건 `%4096`으로 만들지 않는다.
2. Stow 경로는 공용 `stow_control.h`에서 생성한다. 앞 J2 목표 약−254.63도는 정상 단회전 범위를 넘으므로 signed 누적 목표가 필요하다.
3. 누적 목표 기준은 실제 위치 유지 검사로 검증한다. 단회전 피드백이 들어왔다는 이유로 검증한 회전 기준을 덮어쓰지 않는다.
4. 검증한 목표 기준에서 회전 경계를 지나는 피드백 오차는 순환 좌표로 계산한다. 예: 목표4097과 피드백1은 같은 물리 위치다. 이 계산만으로 명령의 누적 원점까지 알 수 있는 것은 아니다.
5. STM32 재부팅과 서보 전원 재인가는 다르다. 제조사 문서상 서보 회전 수는 전원 차단 시 보존되지 않는다. 이전 원점을 무조건 재사용하거나 무조건0으로 초기화하지 않는다.
6. Stop/중단 위치 유지, Landing 완료 후 일반 보행 좌표도 같은 명령 기준을 유지해야 한다.
7. 수동으로 접거나 중력으로 안착한 자세는 원래 보간선에서 벗어날 수 있다. 모든 관절이 보간선에 가깝다는 조건만으로 Stow 여부를 판단하지 않는다.
8. 서보 모델 시험은 내부 누적 위치와 단회전 피드백을 별개로 모델링한다. 목표를 쓰면 피드백이 그대로 같은 숫자가 된다는 mock만으로 실기 호환성을 판단하지 않는다.

## 검증 순서

### 보행 속도 설정의 실제 적용 확인 (2026-09-15)

`profile` 조회의 요청값만으로 서보 속도 설정이 적용됐다고 판단하지 않는다.
v66에서는 Stand가 기록한 300/30이 위치만 갱신하는 보행에도 남았으며,
요청값 3400/254와 실제 12개 서보 readback이 달랐다. S→Drive 전환 후
주소 41(가속도), 46/47(속도)을 실제로 확인한다. V67은 위치·토크·영점을
건드리지 않는 프로필 쓰기와 12개 readback을 보행 시작 전에 수행한다.
mock/simulator도 이 레지스터의 지속성과 제한을 재현해야 한다.
V67의 분리 쓰기는 실기 일부 서보에서 가속도 50이 읽혀 검증에 실패했다.
V68은 기존 목표/시간의 원시 바이트를 보존한 41..47 전체 블록 쓰기로
수정했다. 요청값과 다르면 보행을 시작하지 않는다. 분리 쓰기의 내부 원인은
확정 전이며 readback 통과 없이 성공으로 보고하지 않는다.
V68의 전체 블록 쓰기에서도 J1/J3 8개는 가속도 50, J2 4개는 254로 읽혔다.
V69는 이 기체의 관측값에 맞춰 J1/J3에 최대 50, J2에 최대 254를 명시적으로
쓰고 정확한 값 일치를 검증한다. 시뮬레이터의 기본 적용값도 동일하다.
이는 설치된 기체의 관측 기준이며 제조사 전체 제품의 최대값을 뜻하지 않는다.
[원인과 검증](SERVO-PROFILE-RESTORE-2026-09-15.md).

### ACC 기본 정책 변경 (2026-09-23)

사용자 요청으로 J1/J3의 소프트웨어 ACC50 상한을 제거했다. 기본 보행 요청
3400/254를 12축 모두에 그대로 전송하고 기존 readback 일치 검사를 유지한다.
명시적인 낮은 ACC 요청(예: 느린 자세 전환의30)은 그대로 적용한다.
위 V69 문단은 과거 정책이며, 당시50 readback은 실측 가속도 한계의 증명이 아니다.
이번 변경의 실기 설치·설정 readback·하중 동작은 아직 수행하지 않았다.
서보가254 요청에50을 반환하면 기존 검사에서 실패해야 하며 이를 우회하지 않는다.

시뮬레이터 기본값도 전 축254로 변경했으나 실제 성능을 식별한 값은 아니다.
과거 실기를 재현할 때는 `servo_acceleration_cap_register=[50,254,50]*4`를
명시하며 해당 회귀 검증을 보존한다. [변경·빌드·검증 기록](ACC254-2026-09-23.md).

### 위치 제어 검증

- 빌드 및 호스트 회귀: signed 인코딩, 양쪽 경계, 잘못된 원점, 전원 재인가, 수동 자세, Stop/재개, 일반 보행 좌표 보존.
- 설정과 원시 피드백 조회.
- 정지 자세 유지: 낮은 속도 설정, 짧은 시간, 작은 편차에서 해제. `stowholdcheck`는 모터에 토크를 켜는 **구동 검사**다.
- 앞 J2 양쪽 유지 통과 후 전체 Landing/Stow 경로를 검사.
- 전체 경로를 통과하기 전에는 “실기 수정 완료”라고 기록하지 않는다.

## FR J1 영점 변경 (2026-09-17)

사용자가 토크 OFF 상태에서 확인한 ID4 위치2073틱을 새 영점으로 저장하도록 요청했다.
FR J1 center2089→2073, direction+1 유지, 호스트 offset41→25(2048기준), neutral ID4도2073으로 동기화했다.
서보 EEPROM offset은 변경하지 않았다. 로봇 보정값을 포함한 펌웨어
`s-native-v6-2-7-v77-t1-param-j1`을 설치했고 재부팅 후 `targets`의 ID4 target2073을 확인했다.
서보 영구 레지스터 보존 확인, 새 보정값의 Landing 완료, 최종 torqueOFF/safetyOK.
별도 Stand11 위치 유지와 전체 보행은 아직 검증하지 않았다. J1 추가 오므림 로직은 그대로다.
근거: `artifacts/v77-t1/fr-j1-install/verify.json`.
