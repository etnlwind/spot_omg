# 보행 제어 주기 조사 (2026-09-23)

후속 [V96](ASYNC-FEEDBACK-V96-2026-09-23.md)에서 공유 보행의 서보 조회를
비동기로 변경했다. 아래는 조사 당시 분석이며 제어 주기는 여전히50Hz다.

## 판단

현재 운용값50Hz를 유지하고, 비블로킹 통신과 연산시간 정리 후100Hz를 첫 비교
후보로 삼는다. **100Hz가 실기 최적값이라는 판정은 아니다.** 새 펌웨어 주기 변경,
실기 명령, 주파수별 바닥 보행 시험은 이번 조사에서 수행하지 않았다.
현재 코드에는 50Hz를 전제로 한 필터·미분·보호·자세 전환이 있어 상수 하나만
바꾸는 비교는 같은 보행 조건을 유지하지 못한다.

## 제조사 자료에서 확인한 범위

- [Waveshare ST3215 사양](https://www.waveshare.com/product/st3215-servo.htm):
  1Mbps, 4096단계 위치, 속도/가속도 설정을 확인했다. 확인한 자료에는 설치된
  기체의 권장 보행 명령 주기나 내부 PID 갱신 주기가 제시되지 않았다.
- [Feetech STS3215 제어 사양](https://files.seeedstudio.com/products/Feetech/108090023_STS3215-C001_Datasheet.pdf):
  제조사 작성 PDF의 4쪽에 디지털 패킷, 반이중8N1, 최대1Mbps, PID가 나온다.
  이 PDF는7.4V 모델이므로 전기/속도 수치를 현재12V 모터에 대입하지 않았다.
- [Feetech STS3250 제품 페이지](https://www.feetechrc.com/en/562636.html)를 확인했다.
  별도 사양 PDF 본문은 서버 시간 초과로 확보하지 못했으며, 설치 서보의
  최대 명령 처리 빈도·최적 빈도를 검증했다고 보고하지 않는다.
- [Bosch BNO055 데이터시트](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bno055-ds000.pdf),
  3.6.3/Table3-14: IMU 모드 자세 융합 출력100Hz. 현재 BNO055 경로는 IMUPLUS,
  캐시10ms다. 200Hz로 연산해도 이 센서의 새로운 자세값이200개/s 생기지는 않는다.
  다만 더 촘촘한 궤적 출력의 이득까지 없다는 뜻은 아니다.

## 같은 궤적과 한 걸음 시간을 유지하는 주기 비교

12축 위치만 전송:8+12×(ID1+위치2)=44B. 1Mbps/8N1에서는0.44ms.

|주기|프레임 시간|위치 쓰기만의 선로 점유율|200ms 스윙의 분할 수|균등 목표 유지의 평균 시간|
|---|---:|---:|---:|---:|
|50Hz|20ms|2.2%|10|10ms|
|75Hz|13.33ms|3.3%|15|6.67ms|
|100Hz|10ms|4.4%|20|5ms|
|200Hz|5ms|8.8%|40|2.5ms|

마지막 열은 갱신된 목표를 다음 갱신까지 유지하는 단순 표본화 계산이다.
서보 실제 응답 지연이나 보행 오차 측정값이 아니다. 선로 점유율은 상태 읽기,
전환/응답 대기, 재시도, IMU, 연산, 로그를 제외한다. 전체 프로필104B를 매번
쓰면 각각5.2/7.8/10.4/20.8%이며 현재 보행은44B 경로를 사용한다.

100Hz의 예상 이점은 동일 시간 궤적을 두 배로 촘촘히 전달하고 새 IMU 관측을
더 자주 활용하는 것이다. 목표를 자주 보내는 것만으로 모터 토크·가속 응답이나
접지 타이밍이 개선된다고 확정하지 않는다. 200Hz는100Hz 대비 계산 횟수는
두 배지만 위 단순 평균 시간 개선은2.5ms여서 우선순위가 낮다.

## 저장된 실기 데이터 재계산

도구:`scripts/analysis/assess_control_rate.py`
결과:`artifacts/control-rate-review-2026-09-23/analysis.json`
각 캡처는 약4.6~5.1초이며 전체 시험 시간을 대표하지 않는다.
이전 펌웨어/보행/ACC 설정의 관측이므로 최신 빌드 성능으로 일반화하지 않는다.

|기록|명령 수|송신 간격 중앙값 / P99 / 최대|상태 조회 중앙값 / 최대|
|---|---:|---|---|
|V69 hardware-30s|256|20 /22 /22ms|2 /3ms|
|V70 hardware-pilot-15s|256|20 /23 /46ms|2 /31ms|
|V70 hardware-30s|256|20 /23 /46ms|2 /31ms|
|V6.2.7 resume-hardware-first-step-06|231|20 /22 /22ms|2 /3ms|
|V78 attitude-v2 trial-02|256|20 /21 /21ms|2 /3ms|

기록의 타임스탬프는1ms 분해능이다. 송신 기록0~1ms는 즉시 전송이라는 뜻이 아니다.
송신 시작 간격은 연산 시작 주기와 다르며 프레임별 계산 시간 변동도 포함한다.
조회 시간은 전체 트랜잭션이므로 수신 타임아웃 값과 동일하지 않다.
V70 전체 시험의 별도 진단은 compute_max14ms/io_max36ms/late8회,
재시도10회 회복으로 기록됐다. 서로 다른 프레임의 최대값을 합산하지 않는다.
I/O 최대에는 서보 쓰기/읽기와 IMU가 포함되며 실패 후 break 경로는
최대값 갱신 전에 종료할 수 있어 모든 실패 대기를 포괄하는 측정도 아니다.

현재 서보 응답 타임아웃25ms, 추가 재시도1회다. 송신은 정상이고 응답만
없는 경우 한 번의 조회가2×(1ms간격+25ms응답대기)+1ms재시도간격 및
요청 패킷 시간으로 명목상 대략53ms를 소비할 수 있다. HAL_Delay의 tick 추가까지
고려하면 정상 tick 조건에서도 약53~56ms 수준이며 엄밀한 상한은 아니다. UART 오류/송신 실패의
엄밀한 모든 경로 최대시간 계산은 아니다. 정상 평균 처리시간만 보고100Hz
가능 여부를 판단하면 안 된다.

현재 일반 공유 보행은 매 프레임1축 조회이므로50Hz에서 관절별 기본 주기는
240ms다. V6.2.5~6.2.7 일부 경로는2축/프레임이므로120ms다. 명령 주기와
각 모터의 피드백 주기를 같은 값으로 부르면 안 된다. 기록에서도 이 차이가 보인다.

추가 [46ms 사건 분석](CONTROL-GAP-46MS-2026-09-23.md)에서 원시 기록과 CSV를
대조했다. 두 사건 모두 위치 쓰기1ms, 조회 합33ms, 나머지12ms로 분해된다.
조회 내부31ms의 최초 오류 원인은 아직 시도별 계측이 필요하다.

## 주기를 바꾸기 전에 함께 수정·검증할 코드

1. `robot.c`: `ROBOT_TROT_FRAME_MS=20`, 첫 프레임`.02`, 자세 전환
   `transition+=.02f`, 실시간 콘솔 서비스의10ms 여유 조건.
2. `attitude_control.h`: 각속도 차분×50, 프레임 기반 연속 실패/기울기 판정,
   고정 필터 계수. 실제 경과시간과 관측의 신선도를 기준으로 유지해야 한다.
3. `heading_control.h`: 고정 필터 계수0.1. 같은 계수로100Hz 실행 시
   시정수가 약190→95ms로 달라진다. 같은190ms를 유지하려면100Hz 계수는
   약0.0513이다. 이는 수식 계산이며 현장 최적 필터를 찾은 결과가 아니다.
4. simulator/runtime: `.02` 적분/제어 호출, 명령 지연 큐 계산 등.
   비교 시 물리 적분 간격과 실제 초 단위 명령 지연을 동일하게 유지해야 한다.
5. TX DMA만 바꾸지 말고 RX 응답/재시도와 버스 예약까지 비블로킹 처리한다.
   대기 중 최신 명령 보관, 오래된 명령 누적 방지, 정지 우선 처리,
   오류 복구와 피드백 신선도 정책을 함께 설계한다.

## 최적값을 확정할 실험 기준

50/75/100Hz를 먼저 비교하고100Hz의 이득이 확인된 경우200Hz를 추가한다.
한 걸음 시간·보폭·발높이·J1·ACC·배터리/바닥 조건과 필터 시정수를 고정한다.
최신 빌드에서 MCU 연산/송신/RX/IMU 시간을 각각 고해상도로 측정한다.

- 주기 초과·명령 유실·통신 오류, 송신 간격의 P99 및 최대.
- 관절 추종 오차, 발끝 최소 여유, 접지/이륙 타이밍.
- 몸체 roll/pitch/yaw, 이동거리, 정지 동작, 전류/온도.
- 정상 통신뿐 아니라 응답 누락/재시도에서도 제어·정지 처리가 유지되는지.

평가 기준은 가장 큰Hz가 아니라 같은 보행에서 시간 제약을 지키면서 관절·몸체
오차를 줄이는 값이다.100Hz는 이 실험의 우선 후보이고50Hz는 현재 운용 기준이다.
