# V13 전체 업데이트 — 2026-09-08

## 설치 완료

- STM32: `cad-trot5-v13`, BLE OTA 검증 및 재부팅 완료.
- iPhone UJIN17: `Spot OMG V0.2.0 (3) - Debug` 설치 완료.
- 앱 bundle ID: `com.etnlwind.spotomg.controller`.
- 실제 로봇의 보행 명령은 실행하지 않았다.

업로드 후 로봇에서 읽은 응답:

```text
$SPOTSTATE pose=custom error=1261 torque=off safety=ok balance=full rev=cad-trot5-v13 caps=trot5
```

업로드 전 서보 ID 1 전원은 12.2V, 이동/전류 0, 오류 0x00이었다. 이는 명목 11.1V
3S 배터리의 실제 조회값이며, 시뮬레이터 기준 전압 11.1V와 구분한다.

## 사용하는 방법

iPhone 앱의 **보행 → 개선 전진 · 3회 · 844ms**를 누르면 새 보행을 실행한다.
로봇이 `caps=trot5`를 알려준 뒤 버튼이 활성화된다. 조이스틱의 연속 `drive`는 기존
전후진·회전 정책이며 새 궤적은 별도 개선 전진 명령에 반영했다.

펌웨어/호스트 콘솔에서는 `trot5 [CYCLES [PERIOD_MS]]`를 사용한다. 기본은 3회/844ms,
허용 범위는 1..10회/844..2400ms이다. Stand 후 현재 서보 위치에서 1초 준비 전환,
진폭 완화 보행, 1초 Stand 복귀를 수행한다. 혼합 모터 속도·가속도 제한과 IMU/기울기/
모터 안전 감시는 유지하고, 새 보행에서 IMU 자세 피드백만 사용하지 않는다.

시뮬레이터 비교 UI:

```bash
conda activate spot_omg
mjpython simulation/mujoco/gait_lab.py
```

R 재시작 / 1 기존 / 2 개선 / P 또는 Space 일시정지.
개선 보행은 STM32와 동일한 C 함수를 호출하며, Python 구현은 탐색·대조에 사용한다.

## 검증

- 호스트/펌웨어/시뮬레이터 테스트: 194개 및 26개 subtest 통과.
  localhost 소켓 2개는 샌드박스 바인드 제한으로 실패해 외부 환경에서 재검증했다.
- iOS XCTest: 26개 통과. 실제 기기 Debug 빌드 성공 및 설치 성공.
- STM32 ARM 빌드: `-Wall -Werror`, 링크 주소/이미지 크기/리비전/벡터 검사 통과.
- 선택한 Python 궤적과 C 궤적을 전 주기·4개 진폭에서 비교: 각도 오차 0.0002도 이내.
- 공용 C 정책 동역학 20초: 자세 유지, 약 0.189m/s, 최대 기울기 약 3.51도.
- 실제 로봇에서는 업로드·재부팅·리비전/기능/토크 확인만 수행했다.

시뮬레이터의 질량·마찰·관성·모터 모델 및 CAD 영점은 추정이다. 실제 보행 성능과
장시간 모터 발열은 미검증이며, 새 정책은 전체 회전/후진으로 확장하지 않았다.
