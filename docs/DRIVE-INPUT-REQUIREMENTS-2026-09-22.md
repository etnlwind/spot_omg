# 다음 조종 정책: 사용자 확정 요구사항

2026-09-22 사용자 요청. 후속 V7 구현·빌드·시뮬레이션은
[V93 검증 기록](NAVIGATION-V7-V93-2026-09-22.md)을 참고한다. 실기 설치는 미수행이다.

| 입력 | 요구 동작 |
| --- | --- |
| 정전진 | 전진. IMU 방향 오차에 따라 좌우 보폭을 조정하여 직진 유지 |
| 정후진 | 후진. 같은 조이스틱 세기의 기존 후진 속도 대비 50% |
| 정좌 / 정우 | 몸체가 바라보는 방향을 유지하며 왼쪽 / 오른쪽으로 이동(게걸음) |
| 앞 대각선 좌 / 우 | 전진하며 왼쪽 / 오른쪽으로 회전 |
| 뒤 대각선 좌 / 우 | 후진 없이 제자리에서 왼쪽 / 오른쪽으로 회전 |

좌우 수평이동은 사용자가 방향을 유지하는 게걸음이라고 확인했다.
정후진 50% 제한은 뒤 대각선의 제자리 회전에는 적용하지 않는다.
기존 중간/최대 입력에 따른 보행 형태와 발 들림을 단순히 입력값 절반으로
축소하지 않고, 보행 진행 속도를 분리하여 낮추는 방향으로 구현한다.
보행 주파수를 절반으로 설정하는 것과 실제 이동 속도가 정확히 절반인 것은
다르므로 실측 결과를 구분해서 보고한다.

## 구현 전 확인한 기존 코드

- Windows `drive_vector`와 Apple `RobotDriveVector.make`는 현재 정좌/정우를
  회전으로, 뒤 대각선을 후진 회전으로 처리한다. 양쪽 앱 변경이 필요하다.
- `heading_control.h`의 기존 직진 보정은 전진 입력에서만 작동한다.
- 기존 `gait_policy_crab_targets`는 네 박자 옆걸음 궤적이다. 유한 횟수
  `crab` 명령과 연속 조이스틱 제어는 다르므로 watchdog·정지·재개 경로를
  연결하고 검증해야 한다.
- STM32 공용 보행과 native 보행, MuJoCo 경로에 동일한 속도 정책을 적용해야 한다.
- V92-R2 펌웨어 이미지가 326260바이트로 320KiB 슬롯의 여유가 작다.
  새 기능 추가 후 반드시 실제 링크 결과와 OTA 슬롯 적합성을 확인한다.

## 남은 검증

입력 영역·경계 전환·중립·정지·통신 시간 초과의 호스트 회귀, 좌표 변환과
보행 궤적 확인, MuJoCo 접지·회전 방향·속도 비교, 실제 하중 보행 시험을
구분한다. 현재 이 새 정책에 대한 실기 설치나 보행 검증은 하지 않았다.
