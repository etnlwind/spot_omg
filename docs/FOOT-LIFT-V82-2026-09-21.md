# V82: 다리별 추가 들림 설정

사용자 요청: 고속 후진에서 앞발이 덜 들려 보이는 원인을 확인하고, 모든 보행
모델에 적용하는 개별 발 들림 옵션을 로봇 위에서 본 그림에 배치한다.
상단 J2/하단 J3 각도를 개별 수정하는 UI가 아니라 발끝의 추가 높이를 입력한다.

## 코드 분석

V4 최대 입력은 전후 모두 22mm 들림의 아치 스윙이다. 반 입력의 앞발 +4mm는
최대 입력에서 0이 된다. 이는 기존 고속 정책 선택 규칙이며 앞발만 더 낮게
명령하는 별도 분기는 발견하지 못했다. 고속 직선·진폭 1의 생산 C 목표를
CAD 쿠션 최하점으로 변환하면 전후 방향 모두 네 발의 몸체 기준 Z 변화폭은
약 21.694mm로 같다. 이는 지면 기준 실제 여유 높이/실제 서보 추종 측정이 아니다.
따라서 실기 차이를 하드웨어 한계로 확정하지 않는다.

분석: `scripts/hardware/analyze_v4_front_clearance.py`,
`artifacts/v4-front-clearance-2026-09-21/summary.json`.

## UI와 저장 의미

후속 V90-R1에서 사용자 요청으로10mm 상한을 제거했다. 아래는 초기 설계 기록이며
현재 빌드/설치 상태는 [V90-R1 인수인계](V90-R1-HANDOFF-2026-09-21.md)를 따른다.

- Windows 0.1.5 / iOS 빌드 52 소스에 위에서 본 로봇과 FL/FR/RL/RR 입력칸 추가.
- Windows 정책 선택 옆 `발 들림 보정` 버튼으로 전용 설정 창을 연다.
  조종 스틱/정지 버튼이 설정 화면 때문에 아래로 밀리지 않게 했다.
- 로봇 기준 앞쪽이 위, 왼쪽이 화면 왼쪽이다. 각각 0~10mm, 1mm 단위.
- 기본 0. 앞발만 +10mm는 `10,10,0,0`이다. 기본값을 자동으로 10으로 바꾸지 않는다.
- 저장·반영은 정지 상태에서만 가능하다. 설정 readback이 요청값과 일치해야
  앱 로컬 저장을 완료한다. 저장값 불러오기는 편집칸만 변경한다.
- 설정은 로봇 RAM에 있으며 모델/방향/속도 전환에도 유지된다. 로봇 재부팅 후
  다시 반영해야 한다. PC/iPhone의 로컬 저장은 서로 자동 동기화하지 않는다.
- 실제 적용값을 편집값과 별도로 표시하며, `footlift` 미지원 장치는 반영 불가.

## 제어 경로

`footlift set FL FR RL RR`, `footlift show`. 네 값은 전부 검증한 뒤 한 번에 갱신한다.
`syncstate`에 `lift_fl/fr/rl/rr`을 포함한다. V81 전용 제어 채널을 그대로 사용하며
ESP32 브리지 재설치는 필요 없다. 원래 콘솔 연결의 iOS에서도 같은 명령을 사용한다.

일반 모델은 모델별 duty/위상(크롤, 대각선, arc 선행 위상 포함)에 맞춰 쿠션의
Z만 `64u³(1-u)³`로 추가한다. 시작/착지의 추가 높이와 1·2차 미분은 0이다.
X/Y 보존을 위한 CAD IK를 사용하며, 관절/서보 한계와 기존 보호를 늘리지 않는다.
0mm는 기존 목표를 그대로 반환한다. 진폭/정지 감속과 함께 추가량도 줄어든다.

S-native는 고유의 고정 sole-material X와 J1 잠금 경로 안에서 추가 Z를 적용한다.
보정된 마지막 자세를 기존 정지 배치 동작의 출발점으로 사용한다. Landing/Stand/
Stow와 점프는 이 **보행 스윙** 옵션의 대상이 아니다. 새로운 보행 모델을
덮어쓰지 않고 공통 선택 옵션으로 추가했다.

입력 범위 내라도 기구적으로 불가능한 목표는 기존 계획 실패 경로로 중단한다.
10mm가 모든 하중/속도에서 실기로 달성된다는 의미는 아니다.

## 검증 및 설치 상태

- Windows 및 C 관련 호스트 검사 100개 통과: `artifacts/foot-lift-v82/host-tests.txt`.
- 새 시뮬레이터/C 비교·설정·V4 후진 제어 루프 검사 9개 통과:
  `simulator-lift-tests.txt`. C/Python 비교는 V6.1, V6.2.1, V6.2.3~V6.2.7의
  출발·보행·정지와 비대칭 `10,3,0,7` 설정을 포함한다.
- 기존 attitude PD TCP 제어 검사 4개 통과 (`simulator-tests.txt` 안에 포함).
  위 검사와 중복되는 항목은 합산하지 않는다.
- 일반 배포 모델의 전후 위상 검사에서 비대상 발/지지 발 유지, 선택 발의
  X/Y 보존, 서보 인코딩 범위 및 0mm 원본 일치를 검사했다.
- 이 검사는 제어/기구학 검증이다. 실제 하중 추종·발 끌림·전도 개선 검증은 미실시.
- V82 펌웨어와 Windows 패키지 준비. **V82 실기 설치는 하지 않았다.** 현재 실기에
  마지막으로 설치한 버전은 V81이다. 설치 시 AGENTS.md의 Landing 도착 확인 →
  토크 OFF 절차를 지킨다.
- iOS는 소스만 준비했으며 Windows에서 Xcode 빌드/폰 설치는 미실시.

다음 단계: Windows 화면 확인 후 V82 설치 준비 상태를 확인하고 설치한다.
0mm 기준 보행과 FL/FR +10mm를 같은 입력·촬영 조건에서 비교해 목표·실제 관절각,
몸체 자세와 발의 접촉을 함께 기록한다.
