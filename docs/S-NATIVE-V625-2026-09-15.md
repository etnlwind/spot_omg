# V6.2.5: 빠른 회수와 피드백 회복

사용자는 V6.2.4 정지 후 S 복귀에서 빠른 모터 움직임을 관찰했다.
같은 서보 설정을 사용하는 보행에서 로직이 속도를 억제하는 경로를 조사했다.

## 확인한 병목

V69 실기 초기 기록의 1.0~4.9초 구간을 동일한 C 추종 제어기에 재생했을 때
평균 위상 진행률은 0.3555였다. 분석 구간 내내 0.8 미만이었다.
최대 오차를 가진 관절 표본은 평균 약 135ms 전의 것이었다.
이 재생은 당시 감속을 설명하며 변경 후 실기 속도를 예측한 값은 아니다.

기존 제어기는 오차 14°에서 즉시 진행률 0으로 멈추고, 다시 움직일 때
초당 0.2씩만 회복한다. 0→1 회복에 5초가 걸린다. 관절 12개를 한 개씩
20ms마다 읽어서 같은 관절의 새 표본까지 약 240ms가 걸린다.

## 구현

- V6.2.5를 인덱스 21에 추가했다. 기존 프로필의 인덱스·궤적은 유지한다.
- 회수 중 첫 20% 동안 발을 먼저 들어 올린다. 수평 이동은 20~80%에
  집중한다. 올림·내림은 각각 회수 구간의 30%를 사용한다.
- 기존 오차 6~14° 감속 곡선, 14° 정지, stale/지속 실패 중단은 유지하며
  회복률만 초당 2.0으로 올렸다. 목표 진행률까지 회복하는 지연을 줄인다.
- 새 프로필만 한 프레임에 두 관절을 읽는다. 정상 순환 간격 목표는 120ms다.
- RAM 기록은 256 명령 + 512 피드백으로 확장했다. 12개씩 검증하여
  내려받는 기존 프로토콜을 유지한다. `jointtrace stop`은 다음 Stop에서
  기록을 시작한다. 명령 자체로 로봇을 움직이지 않는다.
- 지원되는 앱에서는 새 모델을 맨 위/기본으로 선택하며 simulator 기본도 갱신했다.
- S 출발, FR·RL 동시 첫걸음, FR의 첫 J1 추가 오므림, 대각선 X/Z 공유,
  “하나, 둘” Stop→S는 유지한다.

## STM32 클럭 점검

V69 실기 `clockdiag`: HCLK 84MHz, APB1 42MHz, APB2 84MHz,
SysTick reload 83999, PLL ready, Flash wait 2.
직전 보행의 1357 프레임 중 late 3회, 계산 구간 최대 11ms, I/O 구간 최대
34ms였다. 프레임 주기는 20ms(50Hz)다. 이 카운터는 구간 경과 시간이며
순수 CPU 명령 실행 시간만 측정한 것은 아니다. 평균적인 36% 위상 진행을
클럭 주파수만으로 설명할 수 없다. V70에서도 84MHz로 비교한다.

하드웨어는 제조사 기준 최대 180MHz를 지원한다.
[ST STM32F446RE 데이터시트](https://www.st.com/resource/en/datasheet/stm32f446re.pdf).
현재 클럭 readback: `artifacts/s-native-v6-2-5/clock-baseline-v69.txt`.

## 검증과 한계

- 새 모델/C-Python 일치/기존 모델/추종/앱 프로토콜 관련 검사 83개 통과.
- C 안전·원점·자세·복구·프로필·기록 회귀 7개 통과.
- iOS simulator 빌드 성공. 768행 paged 다운로드 회귀도 통과.
- 기존 추가 검사 49개 통과, V6.2.1 바닥 동역학 검사 2개 실패.
  설치된 가속도 제한 `[50,254,50] × 4`에서 기울기 중단이 재현되며,
  이전 가정 254로 비교하면 통과한다. 통과시키려고 제한을 되돌리지 않았다.
- 새 모델의 몸체 고정 시뮬레이션은 보호 중단/내부 충돌 없이 Stop→S 완료,
  최종 S 오차 0.219°. 순간 관절 오차는 보행 중 최대 24.0°, 정지 중 32.7°로
  실측 확인이 필요하다. 순차 표본의 14° 기준은 모든 순간 오차가 14° 이하라는
  보증이 아니다.
- 바닥 시뮬레이션은 보행 시작 0.96초 뒤 기울기 중단했다. 바닥 보행 성공을
  주장하지 않는다.

결과는 `artifacts/s-native-v6-2-5/`에 저장한다. firmware revision은
`s-native-v6-2-5-v70`, 크기는 326260 bytes이다.

## V70 실기: 15초 입력 시험

OTA 검증·재부팅 후 몸체 고정/네 발 공중 조건에서 100% 입력으로 시험했다.
입력 시간에는 내부 S 진입이 포함된다. 독립적인 위치 유지 시험이나 바닥
보행 시험으로 해석하지 않는다.

- 정상 정지: `reason=ok elapsed=13082ms`, 피드백 1304개,
  최저 10.7V, lag=46, lag+droop=46, late=1, fall=no,
  derate=recommended. `baldiag` 전체 다운로드는 시간 초과로 미완료다.
- 명령 256개와 피드백 512개를 paged 방식으로 완전히 검증해 내려받았다.
  관절별 중간 조회 간격은 120~121ms로 줄었다.
- 12개 서보 실제 readback: speed=3400, J1/J3 acceleration=50,
  J2 acceleration=254, torque=0. health 오류 0, 10.8~11.0V, 30~35°C.
- 클럭은 여전히 HCLK 84MHz/APB1 42MHz/APB2 84MHz이다.
  계산 구간 최대 11ms, I/O 최대 35ms, tracking fault=0.

### 같은 표본 간격에서의 이동량 비교

V69 V6.2.4 기록과 V70 V6.2.5 기록을 1.0~4.8초 범위의 공통 240ms 격자로
보간했다. 실제 마지막 격자는 4.6초다. 새 기록의 조회 밀도 증가만으로
이동량 증가를 계산하지 않도록 두 기록에 같은 격자를 사용했다.

| 관절군 | V6.2.4 평균 이동량/초 | V6.2.5 평균 이동량/초 | 비율 |
|---|---:|---:|---:|
| J2 네 관절 | 17.85°/s | 25.59°/s | 약 1.43배 |
| J3 네 관절 | 14.36°/s | 20.73°/s | 약 1.44배 |

기록 재생으로 추정한 평균 위상 진행률도 0.3555에서 0.5147로 높아졌다.
최대 오차 표본의 평균 나이는 134.5ms에서 66.4ms로 줄었다. 재생은 기록된
명령과 표본에 기반하며 펌웨어 내부 위상 진행률의 직접 기록은 아니다.

이 수치는 초기 구간의 표본 기반 이동량이며 순간 최고 속도나 몸체 이동
속도가 아니다. 두 시험의 배터리 전압과 시작 위상이 완전히 같지 않다.
속도 향상은 관측됐지만 뒤로 뻗을 때의 바닥 대비 각도와 접지 동기는 이
데이터만으로 검증되지 않았다. raw trace의 J3 RMS 오차는 5.3~6.2°,
최대 표본 오차는 16.6~20.2°로 추종 개선 여지가 남아 있다.

비교 자료: `artifacts/s-native-v6-2-5/pilot-comparison-common-grid.json`,
`pilot-governor-audit.json`, `hardware-pilot-15s/`.

## 사용자 요청으로 30초 재실행

같은 V6.2.5/100% 입력으로 몸체 고정 시험을 반복했다.
정상 정지 `reason=ok elapsed=28448ms`, 피드백 2828개,
최저10.3V, lag=121/lag+droop=121, late=8, limited=0,
derate=recommended, fall=no. 입력 시간에는 내부 S 진입이 포함된다.
Stop 직후 `pose=stand error=8 torque=off safety=ok fault_code=0`을 확인했다.
error=8은 약0.70°이며 별도 토크 유지 시험 결과가 아니다.

첫 기록 다운로드는 BLE 응답 시간 초과로 실패했다. 원본 실패 기록을
보존하고 재연결하여 로봇의 같은 RAM 기록 256명령+512표본을 완전히 검증해
내려받았다. 로봇을 다시 움직이거나 기록을 지우지 않았다.
`hardware-30s/summary.json`의 error는 이 첫 전송 실패를 나타낸다.
복구 결과는 `trace-recovery.txt`, `jointtrace-retry.txt`, 후속 상태는
`post-run-readback.txt`에 별도로 저장했다.

공통 240ms 격자 비교에서 J2 평균17.85→25.58°/s(**1.43배**),
J3 평균14.36→22.37°/s(**1.56배**)로 향상이 반복됐다.
조건과 한계는 위 15초 비교와 같다. 재생 평균 위상 진행률은0.5081이며,
표본의 읽기 실패/하드웨어 오류는0이다. J3 최대 표본 오차는18.5~19.5°다.
후속 상태 조회에서12개 서보 hw=0, 10.8~10.9V, 30~34°C,
torque=off/safety=ok/fault_code=0을 확인했다.
클럭84MHz, 계산 구간 최대14ms/I/O최대36ms였다.

자료: `repeat-comparison-common-grid.json`, `repeat-governor-audit.json`,
`hardware-30s/`. 최저 전압이 내려간 만큼 다음 비교에서는 전원 조건도 맞춰야 한다.
