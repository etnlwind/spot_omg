# V6.2.7 이른 접힘 / v76 실기 반영

> **설치 후 사용자 실기 시험은 첫걸음 전도로 실패했다.** 사용자가 직접 세우고 Stand를 명령했다.
> 마지막 상태와 실패 로그·미완료 분석은 [최신 인수인계](HANDOFF-2026-09-16-V627-FIRST-STEP-FALL.md)를 먼저 읽는다.
> 아래 “실기 보행 미수행”은 설치 작업 종료 시점의 범위이며, 이후 사용자 시험 실패를 대체하지 않는다.

2026-09-16 사용자의 “실기에 적용해봐” 요청에 따른 변경이다.
설치 완료 여부와 최종 기체 상태는 아래 실기 검증 항목 및 원본 로그를 확인한다.

## 채택한 동작

V6.2.6은 이름·형상·프로필 인덱스22를 보존했다. 새 모델은
`s_native_v6_2_7`(인덱스23), 펌웨어 `s-native-v6-2-7-v76`이다.
Windows/iOS 모델 목록 첫 항목과 지원되는 연결의 기본값, 시뮬레이터 기본값을 갱신했다.

- S와 +20/−125mm 추진 스트로크 전체를 유지한다. 추진 종료 이후 회수만 변경한다.
- 회수 X를 Beta(3,5) 누적 곡선으로 앞당겨, J2/J3가 접히는 동안 앞으로 계속 이동한다.
  양 끝 속도·가속도는0이며 교차점 대기나 X 역행을 넣지 않는다.
- 들기16mm, 명목 주기1.8초, 회수 처음/마지막25%에서 부드럽게 들고 내린다.
  실제 주기는 입력 크기와 기존 추종 감독기의 감속에 따라 길어진다.
- 첫 FR/RL 동시 걸음에서 FR J1만 S 대비−18°로 오므린다. 다음 걸음에서
  모두 S 대비−9°가 되며 이후 J1 주기 보정 잔차를 제거했다. 정지는 두 번의 발 옮김으로 S에 복귀한다.
- 서보 방향·영점·가속도 설정, 좌표 변환, 추종 오차/노후/정체 보호는 바꾸지 않았다.

직진 정상 회수의 FR 코드/CAD 각도(대각선 RL과 상대 X/Z 공유):

| 회수 진행 | J2 | J3 |
|---|---:|---:|
| 시작, 밀기 종료 |67.78°|76.16°|
|20%|72.17°|89.46°|
|40%|63.80°|99.99°|
|50%|57.86°|102.18°|
|70%|49.61°|102.52°|

J2 최대72.19°, J3 최대102.68°.
이전 문서의 J2=85°/J3=104°는 수평 몸체의 **정적 기하 예시**이며 그대로 배포하지 않았다.
큰 들기/독립 관절 펄스 후보는 동적 시험에서 보호 중단이나 뒷발 접촉 증가를 보여 제외했다.

## 검증과 한계

- 새 프로필 C/Python 비교10조건, 입출력·기존 프로필·앱 회귀 등을 합쳐 Python123개 통과.
- C 호스트 회귀8개 그룹 통과: 안전, Stow 좌표/동작, 자세 감독, 명령 복구,
  서보 프로필 레지스터, 배터리, 응답 측정 기능.
- 실제 C 커널을 MuJoCo에 연결하고 독립적인 실기 부호/틱 변환으로 재생했다.
  11.1V, 전진 입력100%, 2초 대기+30초 보행+4초 정지 관측:
  최대 기울기6.20°, 보행 중 yaw 변화+0.67°, 전진3.88m,
  최종 S 실측 오차0.99°로 보호 중단 없이 종료했다.
- 같은 형상의 Python30초 시험은 위상 정지0초, 평균 진행률0.831,
  관절 추종 최대오차10.80°, 내부 충돌 프레임0이었다. 보호/충돌을 끄지 않았다.
- 10.9V 전진8초, 우회전 입력8초, 후진60%8초는 보호 중단 없이 S로 복귀했다.
  **회전 기능 합격을 뜻하지 않는다.** 우회전 입력의 순 yaw 변화는+0.93°로
  의도한 회전이 거의 나오지 않았고, 후진 보행 yaw 변화는+7.77°였다. 추가 조정이 필요하다.

**끌림 없는 보행은 아직 아니다.** Python30초에서 회수 중반 하중 접촉 비율은
FL15.6%, FR17.4%, RL17.8%, RR14.9%였다. 하중 접촉만으로 구름/물체 미끄러짐을
구별할 수는 없지만, 발이 완전히 떠 있었다고 주장할 수 없는 결과다.

5mm 최저점 기하 계산은 [계산 문서](S-NATIVE-J2-J3-CLEARANCE-2026-09-16.md)에 있다.
이번 제어는 목표 X/Z 궤적을 J2/J3로 함께 푸는 방식이다. **실제 J3·IMU·몸체 높이를
결합해5mm를 보장하는 피드백 제약을 구현한 것은 아니다.** 목표각보다 실제 J3가
덜 접힌 경우의 끌림 문제는 남아 있다. 실기 가속도/지연을 식별했다는 뜻도 아니다.

## 실기 검증 수준

설치 준비: v75에서 Landing 실제 완료(`complete-residual`, 최대35틱)를 확인하고
Relax 후 주소40을12개 모두 읽어0을 확인했다. 이후에만 OTA를 시작했다.
Landing 중 RR J3 온도79°C 과도 표본1개가 재조회에서 정상으로 확인됐고,
전체 상태 조회는31~36°C, 12개 hw=0이었다. 기존 온도 보고 신뢰성 문제는 미해결이다.

OTA 전송·이미지 검증·STM32 플래시 검증·재부팅을 완료했다.
첫 BLE 재연결은 Windows 알림 구독 오류로 실패했지만 명령은 전송되지 않았다.
다음 연결에서 `rev=s-native-v6-2-7-v76`, `profile=s_native_v6_2_7` 및 새 capability를 확인했다.
설치 후 Landing 전환도 완료(2394ms, 최대35틱), 최종 상태는 **Landing·토크ON·safety OK·fault_code0**이다.
12개 서보 토크 주소40=1, 설정 주소0..39는 설치 준비 직후와 모두 동일했다.
`gaitprofiles`에서 V6.2.6과 V6.2.7이 함께 유지되는 것도 읽어 확인했다.

설치 후 Landing에서도 온도 과도 표본3개가 재확인됐고, 기록된 최대는 ID4 137°C였다.
이후 전체 상태 조회는31~37°C, 11.4~11.6V, 12개 hw=0이었다.
실제137°C 과열로 단정하지 않으며, 온도 보고 신뢰성 문제를 해결한 것도 아니다.
`profile` 조회의 요청값3400/254와 Landing의 현재 레지스터300/30은 구분한다.
이번에 Drive를 실행하지 않았으므로 보행 시작 시 프로필 복구 readback을 새로 실증한 것은 아니다.
**실제 바닥 보행·정상 Stop·독립 위치 유지 시험은 이번 설치 작업에서 수행하지 않았다.**
