# V16 보행 기준 자세 40°/80° — 코드 반영, 미설치

사용자가 40°/80° 보행 후보의 실제 펌웨어 반영을 요청한 뒤, 배터리가 아직 준비되지 않았으므로 코드에만 반영하도록 명시했다. BLE 연결·OTA 설치·로봇 동작은 수행하지 않았다. 실제 설치된 펌웨어는 마지막 확인 기준 V15다.

## 동작

- `stand`: 기존 **J2=45°, J3=90°** 유지.
- 조이스틱 `drive`: Stand를 확인한 뒤 측정된 관절 위치에서 **40°/80° 보행 중립 자세**로 약 1초 동안 smootherstep 보간한다.
- 보행 궤적: V15의 전진 보폭 1.6배와 원래 발 X·발 들기 높이를 유지하고, 정규화 다리 길이에 일정 높이 차이를 더한 뒤 IK를 계산한다. 40°/80°는 중립 기준이며 보행 중 관절은 계속 움직인다.
- 방향 변경 때 높이가 갑자기 바뀌지 않도록 **같은 조이스틱 세션의 회전·후진에도 보행 높이를 유지**한다. 별도 `turn`, `trot4`, `trot5`, landing 등의 명령은 변경하지 않았다.
- 정상 종료·watchdog 감속 종료: 측정 관절 위치에서 Stand 45°/90°로 약 1초 보간해 복귀한다. 이전처럼 정상 종료 시 바로 Stand 한 패킷을 보내지 않는다.
- 시작 직후 기준 자세 송신도 보행 중립을 사용해, 준비한 직후 다시 45°/90°로 내려가는 현상을 방지한다.
- 기존 IMU full/normal 설정, 보행 중 피드백, 기울기 감시, actuator 제한, safety sampler, 800ms 통신 watchdog 유지.
- 전환 구간은 기존 trot5 전환 루틴을 공용화했다. IMU 읽기/기울기 한계/abort/서보 상태 검사를 수행하지만 자세 보정은 적용하지 않는다. 오류 경로의 기존 best-effort Stand 정책은 변경하지 않았다.

## 물리 검증과 한계

`check_walk_stance.py`로 0.5ms 물리 간격, IMU 피드백 OFF 조건에서 준비·전진·좌회전→전진·후진→전진·감속·Stand 복귀를 비교했다. 기준은 V15 궤적과 V16 궤적이며, 두 후보 모두 같은 준비/복귀 보간을 적용해 높이 영향을 비교한다. **V15의 실제 종료 스케줄러까지 그대로 복제한 비교는 아니다.**

기본 / 무겁고 미끄러운 조건 / 무게중심 이동 조건, 각 3개 동작 순서의 총 9조건을 두 궤적으로 비교했다.

- 전진 및 좌회전→전진: 두 궤적 모두 6조건 완료.
- 기본/무게중심 이동 조건의 후진→전진: 두 궤적 모두 완료.
- **무겁고 미끄러운 조건의 후진:** 두 궤적 모두 RR J2/J3 충돌 프록시가 바닥에 닿아 중단. 이때 기울기는 약 7~8°였으므로 '넘어짐 재현'으로 단정하지 않는다. V16이 후진·모든 전환에서 안전하다고 검증된 것은 아니다.
- 준비/복귀 포함 V16 최대 roll/pitch는 완료 사례에서 약 1.65~5.05°.
- 실제 서보 영점·물성·전류·IMU 필터는 미보정이며, 실제 오른쪽 쏠림/전도 해결을 보증하지 않는다. 첫 실기는 평지 전진부터 검증할 필요가 있다.
