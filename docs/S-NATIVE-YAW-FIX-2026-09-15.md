# S-native 회전 방향·직진 보정 수정

조종 프로토콜의 `yaw > 0`은 우회전이다. S-native 발끝 궤적이 같은 입력을
좌회전으로 실행해, 직진 보정이 작은 좌편향을 더 크게 만드는 오류를 수정했다.
실제 앱에서 모델 `s_native_v6_1`, heading ON, 시작 명령 `drive 473 0 3`을 확인했다.

## 반영 범위

- Python `SNativeGait.points`와 STM32 `s_native_step`의 회전 접선 변위 X/Y 부호를 함께 수정했다.
- 수정된 Python 궤적으로 C 지지 보정 표 `s_native_data.h`를 다시 생성했다.
- 기본 직진 보정기의 부호·게인·상한과 IMU 좌표는 유지했다. 앞 J1 CAD→서보 변환과 저장된 서보 영점/방향도 유지했다.
- 기존 S-native 모델들의 공통 회전 입력 해석을 바로잡았다. 모델 이름·목록·프로필 인덱스·직진 보폭·출발/정지 동작 정의를 새 모델로 대체하지 않았다.
- 펌웨어 소스/빌드는 `s-native-v6-1-v61`, 시뮬레이터 상태 버전은 `s-native-v6-1-v61-sim`이다. **보행 모델은 계속 V6.1(`s_native_v6_1`)이다.**

## 검증

관련 pytest 검사74개 통과. 첫 실행의49개가 통과했고, C fixture 출력 상위 폴더 누락으로 실행되지 않은25개는 경로 준비 후 재실행하여 전부 통과했다. 검증 근거는 `artifacts/s-native-v6-1/yaw-fix-v61/`에 보존했다.

- Python/C 목표각 일치, 양·음 회전/직진/후진/혼합 입력, 잘못된 입력 거부와 서보 범위.
- MuJoCo의 **몸체 회전행렬**로 양수 yaw의 우회전·음수 yaw의 좌회전을 Python/C 모두 검증했다. 센서 부호나 목표 궤적끼리만 비교하지 않았다.
- 사용자가 입력한 직진473에서 heading ON의8초 후 방향 변화가2° 미만이며, OFF보다 절반 미만임을 Python/C 모두 확인했다.
- C 최대 직진1000의8초 후 방향 변화2° 미만, 최대 Roll/Pitch5° 미만.
- 각 물리 재생은2초 대기→8초 구동→4초 정지/복귀를 수행하며 기본 기울기 보호와 충돌을 유지한다. 완료 후 S 목표 오차0.01° 미만, 실제 관절 오차1.1° 미만을 확인했다.
- Windows 컨트롤러를 통한 Stop 완료 대기·반복 Stop·실제 가상 관절 S 복귀 검사도 통과했다.

수정 전 독립 재현: 직진1000에서 heading ON 좌31.21°, OFF 좌2.98°;
직진473에서 ON 좌26.80°. 원인 분리 단계의 yaw 반전 시험에서는 각각
좌0.52°/좌1.31°로 줄었다. 이는8초 후 몸체 방향 변화이며 횡이동이나 모든
속도/노면 조건에서의 직선 경로 오차를 보증하는 수치가 아니다.
[진단 원문·시간별 기록](../artifacts/s-native-v6-1/straight-yaw-analysis-2026-09-15/REPORT.md).

재현용 도구: `simulation/mujoco/scripts/validation/validate_s_native_heading.py`.
기본 물성은 추정치이며 실기 보행 검증과 구분한다.

PC 앱과 MuJoCo를 다시 실행해 앱 상태의 `rev=s-native-v6-1-v61-sim`,
`profile=s_native_v6_1`, `heading=on`, 실시간 영상 수신을 확인했다.
`artifacts/s-native-v6-1/yaw-fix-v61/running-app-console.txt`에 실행 버전과
사용자의 후속 조종 기록을 보존했다. 후속 기록의 일부 Stop에는 `^C`가
끼어 있으므로 이번 회전 수정으로 앱의 모든 정지 대기 문제까지 해결했다고
취급하지 않는다. 앞선 정지 후 고정 제한 문제는 별도다.
