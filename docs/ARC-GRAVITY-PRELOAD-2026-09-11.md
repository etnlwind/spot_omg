# 원호 턴 발 끌림 / 하중 보상 검증 — 2026-09-11

## 결론

발을 높이는 것만으로 해결되지 않았다. 고정 CAD 질량에 따른 위치 선행 보상을 공통 C로 구현하면 발 들림과 회전 속도는 개선되지만, 60초에서는 기울기·접촉·추종·접지 이동 기준을 동시에 만족하지 못한다. **실험 후보이며 검증실패다. 기본 보행, 앱 목록, 실제 로봇에는 적용하지 않았다.**

## 구현과 검증 범위

- `arc_turn_targets_configured`로 높이·지지 비율·목표 선행 시간·스윙 아치를 비교한다. 기존 래퍼의 20mm/0.5/40ms/기존 아치를 보존한다. 회전 주기와 원호 크기는 줄이지 않는다.
- `arc_preload.h`: CAD 링크 질량, 질량중심, 발 Jacobian으로 중력 토크와 예정 지지 쌍의 하중을 추정한다. 이를 추정 위치 강성 35Nm/rad로 나눈 위치 보상이다. 토크 제어나 MPC/WBIC가 아니다.
- 쿠션처럼 J3에 고정된 자식 부품도 움직이는 링크 질량으로 합산한다. 전체 추정 질량은 4.418kg이다. 처음 쿠션을 고정 몸체로 잘못 분류한 문제를 수정하고 독립 MuJoCo 중력 계산과 비교했다.
- 보상은 축당 ±4°, 20ms 프레임당 0.25° 이내다. 관절 제한, 안전 정지 기준, 좌표 부호와 누적 서보 원점은 변경하지 않았다. 잘못된 입력이나 범위 초과는 결과/상태를 일부만 변경하지 않고 거부한다.
- 시뮬레이터는 `arc_preload.py`에서 같은 C 함수를 호출한다. 제어 입력은 예정 관절각과 보행 위상이며 정답 접촉력, 실제 발 높이, 물리 엔진의 현재 질량중심을 읽지 않는다. C에 내보낸 고정 추정 모델을 사용한다.
- C 헤더는 STM32에서 사용할 수 있는 구현이지만 **아직 MCU 보행 루프에 연결하지 않았다.** MCU 계산 시간과 실제 서보 강성을 검증하지 않은 상태에서 배포하지 않는다.
- `arc_balance_trial`의 역할별 자세 보정, 스윙 높이/평탄화/지지 시간 증가 후보는 악화되어 채택하지 않았다. 탐색 결과는 `artifacts/audits/arc-clearance/`에 보존한다. 초기 탐색 일부는 Python 참조 구현이며, 최종 아래 검증은 공통 C 구현이다.

## 최종 후보와 60초 결과

후보: 목표 높이21mm, 기존 원호/주기/40ms 선행 유지, 하중 보상 gain0.3, 예정 하중 전환40ms 선행. 실제 시간 5~65초를 평가하고65초에 Stop,69초까지 확인했다. 각 조건은 단일 결정적 실행이며 반복 실험의 통계적 신뢰구간은 아니다.

| 조건 | 회전 속도 기존→후보 (°/s, 절댓값) | 최대 roll 기존→후보 | 후보 발 최대 여유 FL/FR/RL/RR (mm) | 후보 중간 스윙 접촉 FL/FR/RL/RR |
|---|---:|---:|---|---|
| 지연20ms 좌 |17.38→17.95|0.94→3.54°|18.1 /21.4 /19.7 /23.1|19.7 /7.2 /8.3 /12.7%|
| 지연20ms 우 |17.34→17.97|1.39→3.40°|19.9 /17.8 /22.9 /19.9|6.8 /19.6 /13.6 /8.6%|
| 지연80ms 좌 |17.30→17.74|0.98→3.78°|18.9 /21.2 /20.2 /26.4|27.2 /18.1 /19.0 /21.0%|
| 지연80ms 우 |17.38→17.68|1.05→3.69°|21.4 /19.3 /26.2 /19.7|18.2 /27.4 /21.9 /19.1%|

8회 모두 안전 정지 없이 회전하고 Stop을 완료했다. 그러나 후보4회 모두 최종 합격은 아니다. `validated=false`와 개별 실패 항목을 JSON에 기록했다. 최대 여유는 관측된 최고값이며 매 스텝의 최소 들림 보장이 아니다.

정상 좌회전 추종 RMS는1.864→1.948°, 접지 발 중심 이동 속도는9.91→11.03mm/s로 악화됐다. 발 중심 이동에는 쿠션 굴림도 포함되므로 순수 미끄러짐이라고 단정하지 않는다. 지연80ms에서는 악화 폭이 더 컸다. 기울기 RMS·pitch·토크·마찰 진단도 JSON에 남겼다.

해석: 기존 낮은 스윙은 발이 계속 지면에 닿아 추가 지지를 제공하는 양상이 있다. 들림이 개선되면 지지 전환 시 자세 변화가 커진다. 정적 하중 보상만으로 대각선 지지의 동적 균형까지 해결했다고 볼 수 없다. 실물의 옆걸음 원인이 이것이라고 확정한 것은 아니다.

## 남은 검증

- 시각이 서로 다른12축 피드백을 이용한 상태/접촉 추정과 동적 하중 전환은 미구현이다. 진행률 감독기만으로 대신할 수 없다.
- 정상·지연 조건부터 미달하여 무게중심 이동, 모터 열화, 쿠션 물성 변화의 추가 합격 검증은 보류했다.
- 실제 로봇 BLE 조회 시 검색되지 않아 V41 실기 계산 시간·버스 시간·실제 들림/회전 원인 재측정은 못 했다. 설정 readback, 실제 위치 유지 시험, 전체 동작 시험을 완료했다고 표현하지 않는다.

## 코드 검사

- 공통 제어·가상 로봇·Stow·감독기·중력 계산 통합 검사94개 통과. 별도 원호/전환/단위 검사22개 통과(중복 포함).
- STM32 소스 빌드 성공. 실제 설치·설정 readback·위치 유지·전체 실물 동작 시험은 수행하지 않았다. 하중 보상은 호스트 호출 경로의 검증이며 MCU 실행 성능 검증이 아니다.
- 로그와 검증 당시 소스 SHA256을 결과 디렉터리에 보존했다.
