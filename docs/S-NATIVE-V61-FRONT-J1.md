# V6.1 앞 J1 방향 수정 v60 — 2026-09-15

**실제 로봇에 v60 설치·검증·재부팅 및 버전 readback을 완료했다.**
최종 `rev=s-native-v6-1-v60 profile=s_native_v6_1 safety=ok torque=off fault_code=0`.
12개 서보 모두 응답하고 `hw=0x00 moving=0 current=0`이다.
수정 후 실제 위치 유지/보행 시험은 아직 하지 않았다.
모델 ID `s_native_v6_1`과 V6.1 궤적은 유지한다. 새 보행 모델을 덮어쓴 것이
아니라 CAD 관절각을 실제 서보 명령으로 변환하는 오류의 수정이다.

## 확인한 문제와 근거

사용자가 실제 로봇에서 계속 걸을 때 뒷다리는 모이지만 **앞다리 두 J1은
바깥으로 벌어진다**고 확인했다. 출발 첫걸음의 FR 전용 오므림에 국한되지 않는다.
PC 앱 접근성 로그에는 `rev=s-native-v6-1-v59 profile=s_native_v6_1`이 있었고,
FR ID4의 보행 중 목표1884 / 실측1964 및 목표1894 / 실측1992가 기록되어 있다.
이 목표는 FR 영점2089보다 작다. 앱 로그는 최대19999자까지 읽힌 부분 사본이다.

[2026-09-10 실기 기록](FR-J1-TURN-CLEARANCE-2026-09-10.md)에서는 FR ID4의
2093 → 목표2203 / 실측2202 이동을 사용자가 **안쪽 오므림**이라고 확인했다.
CAD에서는 J1 감소가 오므림인데 v59는 이 CAD 각도를 기존 모터 각도로 그대로
전달했다. 앞 J1에 필요한 변환을 빠뜨린 것이다. 앞 좌우 대칭 관계와 이번
양쪽 앞다리/뒷다리 관측을 함께 반영했다. FL에 대한 새 단독 구동 측정은 하지 않았다.

## 수정 범위

- `s_native_servo.h`: S-native CAD → 모터 명령 경계에서만 FL/FR J1 부호를 변환한다.
- V6.1 Stand, 보행, Stop 복귀, idle 유지, 상태 판정에 같은 변환을 적용한다.
- 측정된 `robot_config.c`의 영점/방향, J2/J3, 뒷다리, 기존 모델,
  Stow/Landing 누적 위치 규약, 속도/추종/안전 한계는 변경하지 않는다.
- MuJoCo V6.1도 동일 C 인코더의 실제 전송 틱과 실기 축 방향을 거쳐 CAD에 적용한다.
  기존처럼 잘못된 인코딩/동일한 잘못된 역변환이 서로 상쇄되는 검사로 끝내지 않는다.
- 회귀 검사에는 구현과 독립된 실기 축 방향을 사용하여 이전 인코더의 실패도 재현한다.

정상 오므림 기준 약9°의 정적 기하 비교다. 하중하 실측 이동 거리가 아니다.

다음 걸음 정상 오므림/Stop 시 해제는 보존된다. 위 틱을 사용자 수동 이동 명령으로
실행한 것이 아니며, 현재 실물 자세에서 곧바로 이 목표를 보내서는 안 된다.
