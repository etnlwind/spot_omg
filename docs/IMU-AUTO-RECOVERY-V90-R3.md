# V90-R3 IMU 자동/수동 복구

BNO055 읽기 실패로 명령이 ROBOT_IMU_ERROR를 보고하면, 첫 오류 보고 시각으로부터 3000ms 뒤 메인 루프에서 기존 imurecover를 한 번 실행한다. 반복된 오류가 타이머를 뒤로 미루지 않는다. drive/walkprobe/stow/진단 동작이나 다른 제어 명령이 실행 중이면 정지할 때까지 복구를 보류한다. 3초 대기에 HAL_Delay를 사용하지 않는다.

기존 복구 절차는 STM32 I2C DeInit/Init, 센서 ID/IMUPLUS 모드 검사, body+Euler 정상 표본 3회 검증이다. 센서 전원 재인가나 보정값 초기화가 아니다. 자동 복구는 토크/목표 위치/고장 플래그를 변경하지 않고 이전 보행을 재개하지 않는다. 검증 성공 후 새 명령으로 재시작한다. 실패하면 무한 재시도하지 않으며 수동 복구를 제공한다. 자동 또는 수동 복구 성공이 다음 실패에 대한 타이머를 다시 활성화한다. 초기 부팅에서 감지되지 않은 센서나 BNO086에는 BNO055 복구를 실행하지 않는다.

Apple 앱 V90-R3 빌드62에 'IMU 복구' 섹션과 버튼을 추가했다. 정지·응답 완료 상태에서만 누를 수 있다. 복구 응답을 기다리는 동안 새 스틱 입력을 보류/재생하지 않으며, 명시적 성공 응답을 받은 경우만 성공으로 표시한다. 자동 복구의 IMUAUTO 시작/결과 알림은 진단 채널에서 별도 표시하며 명령 완료로 해석하지 않는다. Windows에도 정지 상태의 IMU 복구 버튼과 R3 버전 인식을 추가했다.

검증: 지연 경계 2999/3000ms, 틱 오버플로, 반복 오류/중복 실행, 실행 중 보류를 포함한 C 스케줄러 및 실제 자동 서비스 함수 시험. 기존 복구 함수 HAL 고장 주입/연속표본 시험, 제어채널 시험과 함께 5개 통과. Apple 공용 88개 통과 후 수동 복구 중 스틱 무시 보완 관련 2개 재검증 통과. Windows UI/프로토콜 142개 통과. 펌웨어 크기 327664바이트로 320KiB 영역 내.

실기 설치 전: R2에서 IMUDIAG hal_error=0x20, SR2=0x3, SCL=0 관측. 수동 복구 첫 시도는 chip 응답 실패, 두 번째는 chip=0xA0/mode=0x08 확인했지만 body_ok=0으로 실패했다. 통신 일부 복구와 자세 표본 검증 성공은 구분한다. 관련 원시 자료는 artifacts/imu-auto-v90-r3/에 보존했다.

## 설치 결과

Landing 완료 후 12개 토크 레지스터 OFF를 확인하고 R3 OTA/이미지 검증/재부팅을 완료했다. 설치 후 Landing, torque=off, safety=ok, rev=attitudepd-v4-v90-r3 및 FL/FR/RL/RR=[20,20,0,0] readback 확인. iPhone/Mac V90-R3 빌드62 설치 확인. Windows는 소스만 반영했다.

설치 후 수동 imurecover 실기 시험: HAL 에러 0, SCL/SDA high, chip=0xA0/mode=0x08은 정상이지만 body_ok=0/samples=0/3으로 실패했다. 따라서 이번 배포는 자동 호출과 수동 버튼을 구현한 것이며, 현재 기체의 모든 IMU 표본 검증 오류를 해결했다고 볼 수 없다. 실기에서 자동 실행 타이밍을 확인하려고 센서 오류를 의도적으로 만들거나 보행하지 않았다. 3초 지연/동작 중 제외/무한 재시도 방지는 호스트 시험 수준의 검증이다.
