# 영상 후보의 실물 이식 — V48

사용자가 고정 카메라 영상 후보를 실물에 넣도록 요청했다. 대상은 `inside_60_4`이며 새 공용 정책 키는 `centerpivot`, 앱 이름은 **몸체 중심 회전 보정 · 실험 (검증실패)**이다. 실험의 보행 품질 미달 판정은 유지한다. 기본 Cruise와 기존 정책은 보존한다.

## 구현

- `center_pivot.h`는 영상의 `measured_swing` 전진 이륙/내딛기 궤적, 안쪽 앞발 CAD 4mm 들림, 60mm 회전 중심 보정, 0.24rad sweep을 그대로 이식한다. 회전 입력 상한은 영상과 같은 0.5다.
- 관절 목표는 공용 CAD 쿠션 좌표/Jacobian에서 계산한다. 원본과 같은 12회 동시 IK, 0.1mm 조기 수렴, 1mm 최종 잔차 제한을 사용한다. 중간 입력에서는 원본처럼 관절 목표를 부드럽게 혼합한다.
- 원본 영상의 Cruise 균형 제어와 같은 기존 제어 경로를 사용한다. 서보 모델별 위치 표현, 목표 부호·회전 기준, 속도·토크 제한과 보호 정지를 바꾸지 않았다.
- 앱 빌드 44는 `centerpivot` capability가 확인될 때만 정책을 선택할 수 있다. 구버전에서는 명령 전송을 차단한다. 속도 표시는 검증실패를 유지한다.
- `centerpivottiming`은 STM32에서 128회 궤적 계산의 실행 시간만 측정한다. 모터 명령을 보내지 않으며 보행 중에는 거부한다.

## 검증

- Python 원본과 C 목표: 전진·후진·좌우·혼합·정지 입력 × 진폭 0/0.2/1 × 101개 위상을 비교했다. 최대 차이 **0.000604°**. 동일 입력의 목표 계산 비교이며 실물 위치 오차가 아니다.
- C O0/O2, 서보 변환, 전환/Stop 및 펌웨어 회귀 포함 48개 테스트 통과.
- Swift 호스트 검사: 구버전 capability 차단, V48 정책 명령, 원격 해제, Landing-before-Relax 처리 통과. XCTest 실기 실행과 구분한다.
- STM32 V48 빌드 성공, 245296 bytes. iPhone Debug 빌드 44 성공.
- 실제 펌웨어와 같은 C 제어 경로로 MuJoCo를 방향별 27초 실행했다. 2초 시작, 25초 Stop. 평가 구간 5~25초.

| 결과 | 좌 | 우 |
|---|---:|---:|
| 회전 속도 | 25.03°/s | 25.31°/s |
| 평가 시작점 기준 최대 중심 이동 | 29.0mm | 40.6mm |
| 명령 전 위치 기준 최대 이동 | 85.8mm | 69.2mm |
| 최대 기울기 | 5.62° | 5.99° |
| 안전 정지 / Stop 응답 | 없음 / 성공 | 없음 / 성공 |

시뮬레이션의 물성/모터 지연에는 추정값이 남는다. 앞발 들림과 시작 자세 이동의 기존 문제는 해결됐다고 주장하지 않는다.

## 설치 상태

빌드 산출물과 해시는 `artifacts/audits/pivot-center-2026-09-12/deployment/`에 보존했다. 실제 전송·재부팅 조회 결과는 아래 설치 기록으로 구분한다. 설정 readback, 실제 위치 유지 시험, 전체 회전 시험은 각각 별도 검증이다.

### 실제 설치·조회 완료

- OTA 전에 실제 Landing 성공(`landing complete=1`). ESP32 staging 및 STM32 flash 검증 후 재부팅 완료.
- 실물 readback: `rev=shared-locomotion-v48`, `caps=centerpivot`, 정책 목록에 `centerpivot` 확인. 새 정책 선택 후 `profile=centerpivot` 재조회 성공.
- STM32 84MHz. `centerpivottiming`: 128회, 최대 7ms, 평균 5421µs, 계산 실패 0, 모터 명령 0. 20ms 제어 주기보다 짧지만 이는 궤적 계산만의 시간이며 전체 I/O 시간은 아니다.
- 최종 직접 조회 상태: Landing, torque off, safety ok. 실제 위치 유지 시험과 실제 좌우 회전 동작 시험은 이번 설치에서 수행하지 않았다.
- iPhone Debug V0.5.0 (44) 설치 완료. 정책은 실물/시뮬레이터 양쪽의 지원 capability에 따라 표시한다.
- 원본 전송/조회 로그: `deployment/ota.log`, `deployment/readback.log`.

아이폰 앱 설치·실행 성공 후 원격 재연결 요청은 응답 시간 초과했다. 이 결과만으로 앱의 BLE 연결 완료를 주장하지 않는다. 로봇 V48/정책 선택은 직접 BLE readback으로 확인했다.

최종 앱 조회는 **ready=true, state=연결됨, target=robot, firmware=shared-locomotion-v48, pose=stand, motion_active=true**로 확인됐다. 재연결 시도는 진행 중 동작 보호로 거부되었으며, 이후에는 읽기 전용 상태만 확인하고 사용자 조작을 중단하지 않았다. 앱 경유 실물 연결까지 확인 완료. 이 상태 응답만으로 실제 좌우 회전 품질을 검증했다고 판단하지 않는다.

### 앱 기본 검증 정책 (빌드 45)

연결 후 지원 capability와 정지 자세를 확인하면 `centerpivot`을 한 번 자동 선택한다. 실제 readback이 올 때까지 화면의 현재 정책을 바꾸지 않는다. 수동 정책 선택은 존중하며 같은 연결에서 다시 덮어쓰지 않는다. 보행·자세 전환·원격 인계·Stow 잠금 중에는 자동 변경을 보류한다. 구버전에는 전송하지 않는다. Swift 호스트에서 1회 선택, 실제 readback 표시, 수동 선택 유지, 자세 전환 중 보류를 확인했다. 실제 설치 결과는 후속 기록과 구분한다.

빌드 45 아이폰 설치 완료. 데스크톱은 Xcode의 My Mac (Designed for iPhone) 대상으로 재빌드·실행했으며 화면의 V0.5.0 (45)와 centerpivot 선택을 확인했다. 데스크톱 실행은 iPhone 실행 파일을 open하는 방식이 아니라 Xcode의 .XCInstall 래퍼를 사용한다.
